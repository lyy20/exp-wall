项目拆解 ​

这一节不是「项目介绍」，是答辩稿。每一页都能单独抽出来回答面试官的一个追问。

两个项目，解决的是两件不同的事 ​

YYHelp v2 · 电商智能客服 Agent科研文献 RAG 问答服务
一句话多轮对话能不能可靠地把事办完检索准不准、答案可不可核对
控制流LangGraph 状态图：分叉 / 汇合 / 循环直线：问题 → 检索 → 生成 → 校验
状态会话持久化 + 中断恢复无状态
副作用查订单、建工单（写操作，幂等键 + 人工确认）只读
检索Milvus 单库双路（dense + sparse）+ RRF + 精排FAISS dense + 自建 BM25 + RRF + 精排
可观测自研 JSONL + Langfuse v4 双后端，显式降级自研 JSONL
评测配对比较 + Holm 校正 + 三态退出码（可进 CI）分层评测集 + 消融实验全表
数据闭环数据飞轮（三入口 → 问题池 → 离线重放）无

为什么这两个项目放在一起讲才有力：它们不是同一个东西做两遍。前作解决「检索准不准」，本项目解决「多轮对话能不能可靠地把事办完」。面试官问「你为什么又做一个 RAG」，答案就是这张表。

顺序页面为什么先读它

三条贯穿两个项目的口径纪律 ​

报数之前先想清楚这三条

  1. 不假装跑过。 未执行的验证就写「未执行验证」，并给一条可执行的验收命令。面试官追问「你怎么验的」时，答得上来比数字大更重要。
  2. 报数必带口径。 recall@5 要说清 macro 还是 micro、k 取几、是否含精排、分母怎么定义、ground truth 从哪来。同一个指标换个口径能差十几个点。
  3. 配置类开关必须配「能失败的断言」。 只验「没报错」等于没验。中文分词器那个坑就是活例子——不报错、只返回空。

与面试准备的关系 ​

  • 完整数字与出处：🔥 面试随身数字卡
  • 追问链预演：项目深挖预演
  • 通用高频题：Agent 与工具调用、RAG、大模型原理
  • 原理图：架构图库 —— YYHelp 组 14 张、RAG 项目组 11 张

两个项目的共同技术底座 ​

bge-m3 Embedding、bge-reranker-v2-m3 精排、RRF 融合、OpenAI 兼容协议调用 LLM、拒答阈值思路——这部分两个项目都用了，面试时只需要讲一次，然后说明「第二次我为什么要换成 Milvus / 换成 LangGraph」。
