L1 · 大模型原理 · 本层导览 ​

本层共 24 个知识点，拆成 12 个页面。面试频率：高 ｜ 建议总学时：113h

这一层在解决什么问题 ​

一句话：这一层回答「大模型内部到底在算什么」。

L1 是整棵知识树里面试考察密度最高的一层。原因是它处在两个夹缝中间：

  • 往上，它是所有应用的归因终点。你解释不了「为什么切块要选 512 / 1024 / 2048」，就只能说「我试过」；你说不出「KV Cache 显存怎么估」，就解释不了「长上下文为什么贵」。
  • 往下，它是一个极少数能靠自学补齐的硬技能。分布式训练、大规模数据工程、集群运维，应届生几乎没有机会真做；但注意力怎么算、位置编码怎么注入、LoRA 为什么省显存、幻觉为什么必然存在 —— 这些可以靠读论文 + 手写代码真正掌握，而且是唯一在面试里无法靠话术蒙过去的部分。

这一层最实际的收益：它把你在项目里做的每一个工程决策，从「我试过有用」升级成「我知道它为什么有用」。面试官追问三层的时候，区别就在这里。

这一层最容易走的弯路：按编号顺序从 L1-01 背到 L1-24。正确做法是先建立一条主链（下面的「必背主链」），再按主链去挂细节 —— 因为面试题几乎都是沿着这条链往下问的。

一条必背主链（面试时的开场句） ​

文本先被 Tokenizer 切成 subword 并映射成向量；向量加上位置信息后进入 层 Transformer，每层做一次注意力（让 token 之间交换信息）和一次 FFN（逐位置加工），两者都包在残差与归一化里；输出端的 logits 经过解码策略选出下一个 token，循环生成。训练分三阶段 —— 预训练让模型学会语言，SFT 让它学会听话，偏好优化让它更符合人类偏好；推理端最大的成本约束来自 KV Cache 的显存。

这六句话就是 L1 的地图。 被问到任何细节，先在心里定位它挂在这条链的哪一段，再回答。

这一层最容易挂在哪 ​

下面 12 条是 L1 的高频失分点，按「说出来就会被追问、追问一层就会崩」的程度排序。每一条都给了「挂法」和「怎么避免」。

一、概念错位类（最致命，一错就到底） ​

① 把 Q 头数当成 KV 头数。挂法：被问 GQA 的显存收益时说「因为头数变少了所以缓存变小」—— 听起来对，但变少的是 KV 头数，Q 头数没变。 怎么避免：记住 GQA 的机制是「每个 KV 头被一组 Q 头共享」，缓存只存 份；计算时才把 K / V repeat 到 。

② 说 QLoRA「把整个模型都变成 4-bit 训练」。挂法：被追问「那 LoRA 适配器呢」就答不上。 怎么避免：准确说法是 —— 量化的是冻结的基座权重（ 字节），可训练的 LoRA 适配器仍以 bf16 计算，前向时反量化。QLoRA 省的是权重存储这一块。

③ 说 SFT「用的是分类损失」。挂法：面试官立刻知道你把 SFT 和奖励模型训练搞混了。 怎么避免：SFT 的目标函数与预训练完全相同（下一 token 预测的交叉熵），差别只在数据形态、损失范围、规模与目的。「SFT 是一次分布切换，不是新算法」这句话必须能脱口而出。

④ 把幻觉说成「模型的 bug」。挂法：被追问「那为什么修不掉」时无话可说。 怎么避免：幻觉是用似然目标优化一个没有真值信号的任务的必然产物。要能说出至少三条机制（没有「我不知道」的训练信号、长尾知识被平坦化、上下文与参数知识冲突时不保证以上下文为准）。

二、公式与计算类（对错分明，最伤分） ​

⑤ 解释不了 的必要性。挂法：「就是为了数值稳定」—— 这个答案太浅，会被追问「稳定什么」。 怎么避免：要给出方差推导：若 各维独立、零均值、方差为 1，则 的方差是 ，维度越大点积的绝对值越大，softmax 会进入饱和区（梯度接近 0），所以要除以 把方差拉回 1。并且要知道为什么不是除以 （那样方差会被压到 ）。

⑥ KV Cache 显存公式漏项。挂法：漏掉前面的 2（K 和 V 各一份）、把 写成 、忘记乘层数、或忘记在并发时乘 batch。 怎么避免：记公式时按「每 token 每层」起步（），再逐级乘层数、长度、batch。这样即使紧张也不会漏项。 并且记住边界：它与序列长度线性相关，不与参数量成正比。

⑦ 把「注意力是平方复杂度」说成生成阶段的问题。挂法：面试官追问「那 KV Cache 是干什么的」时自相矛盾。 怎么避免：分清三件事 —— ① 无缓存时的生成有平方级的重复计算；② 分数矩阵 的平方项出现在训练与预填充（所以要 FlashAttention 这类不物化矩阵的实现）；③ 有缓存时生成阶段的注意力代价是线性的，但显存随序列长度线性增长。

⑧ 多头维度变换顺序写错 / 忘记 contiguous。挂法：写了 [B,S,d] 直接 reshape 成 [B,H,S,d_head]，或者合并时没 contiguous。 怎么避免：背这句 —— 「先 reshape 到带 H 的四维（[B,S,H,d_head]），再 transpose 到 [B,H,S,d_head]；合并回来时先转置回 [B,S,H,d_head]，先 contiguous 再 reshape」。反过来虽然形状碰巧对，但语义已经错了。

三、判断与边界类（区分「用过」和「想过」） ​

⑨ 说「RAG 解决了幻觉」。挂法：被追问「那为什么还答错」时就崩。 怎么避免：RAG 降低幻觉但不消除，而且引入一类新幻觉 —— 忠实性幻觉（给了材料，模型仍按参数记忆回答）。所以需要引用核验（机械比对）与拒答闸门，而不是靠 prompt 里一句「请只根据材料回答」。

⑩ 说「上下文窗口大就不需要 RAG 和切块了」。挂法：这是最容易被追问的过度承诺。 怎么避免：窗口变大不等于模型会用它。四条机制：注意稀释、位置编码分布外、训练长度与宣称窗口不一致、成本非线性上升。并补上反直觉的一条：少而准通常优于多而杂 —— 塞进无关文本会主动降低性能。

⑪ 评测带随机性却做配对检验。挂法：被问「你怎么保证两次跑的结果可比」时答不上。 怎么避免：评测时 temperature = 0（或固定种子），并把生成参数当成评测配置冻结下来写进报告。先控制方差，再做均值比较 —— 否则「分数涨了」可能只是采样噪声，配对检验失去意义。

⑫ 报出记错的模型规格数字（参数量、层数、上下文长度）。挂法：说一个具体数字，被追问「你确定吗」就开始动摇；一旦确认说错，整场技术可信度都会受损。 怎么避免：这类信息迭代很快，不要背数字。正确答法是：「具体规格我会以官方模型卡为准，但我知道它的架构取向与取舍是……」然后讲架构层面的东西（是否 MoE、GQA 配置、注意力设计）。在面试里，承认「这个具体数字我不确定」几乎不扣分；编一个数字被抓到是致命的。

⑬ 把推理模型的思考过程当成可审计的推理记录。挂法：说「看它的 CoT 就知道它是怎么想的」—— 这个假设在研究中被反复质疑。 怎么避免：CoT 可以是提升效果的机制（串行计算量正比于生成 token 数），但不能当作可靠的审计依据（模型可能说一套、答一套）。能被机械校验的才叫审计 —— 所以你的引用核验要在系统层做，不依赖模型的自我说明。

一条跨所有条目的总纪律 ​

凡是数字，先问自己「我是从哪知道的」。

三类数字的处理方式完全不同：

数字类型例子怎么处理
可推导的KV Cache 显存、LoRA 参数量比率、FFN 占注意力的倍数必须能当场推。这是最容易拿分的部分
有量级但非精确的Scaling Law 的 token / 参数比给量级并说明是经验规律，不报小数点
随时会过期的具体模型的参数量、层数、上下文长度、榜单分数说「以官方模型卡为准」，讲架构取向而不是数字

记不住时最安全的句式：「这个具体数值我不确定，但我知道它影响什么、以及怎么估 —— 」然后讲机制与估算路径。面试官通常更在意你能不能推导，而不是你能不能背。
