本页目录

偏好优化：RLHF / PPO / DPO ​

覆盖知识点：L1-16 ｜ 面试频率：高 ｜ 建议学时：5h

一句话说清 ​

SFT 只能告诉模型「这个回答是对的」，教不会「A 比 B 更好」。偏好优化用人类排序数据补上这一课：RLHF 的路线是「先训一个奖励模型当人类偏好的可微代理，再用强化学习（PPO）优化策略」，代价是四套模型同时在显存里、训练不稳、有奖励黑客风险；DPO 的路线是把「KL 约束下的奖励最大化」解析地变形，得到一个直接在偏好对上做分类的损失 —— 不需要显式奖励模型、不需要在线采样、不需要 RL 循环，训练简单稳定。两者的分工不是「谁更好」，而是在线探索 vs 离线简单的取舍。

为什么必须学 ​

这是 L1 里数学密度最高、也最容易被问穿的一块。它和 SFT / LoRA 那页一起构成「后训练」的完整图景，面试中出现的形式通常有三种：

  1. 概念题：「RLHF 的完整流程是什么？」「DPO 和 PPO 有什么区别？」
  2. 推导题：「DPO 的损失是怎么来的？为什么不需要奖励模型？」—— 这是压轴题，能答的人很少。
  3. 判断题：「你的项目为什么不做 RLHF？」—— 这题在你这儿有很好的答案（见「对上号」一节）。

先明确一条纪律：这一页涉及的超参数具体数值、以及某些论文实现细节，我不给固定数字。原因是这类数值高度依赖具体论文与实现版本，记住一个错数字比不记更糟。凡是需要精确数值的地方，正确回答说「要看具体实现与论文设定，并在验证集上扫」。在面试里，承认「这个我不记得具体数值，但我知道它影响什么」是安全的；编一个数字被追问一层就会崩。

核心内容 ​

为什么 SFT 不够 ​

SFT 的目标是最大化「给定指令时，标注回答的似然」—— 它是一对一的模仿学习。它无法表达「在多个都能接受的回答里，哪一个更好」。而人类对回答质量的判断天然是比较式的：

  • 你很难为一个开放问题写出唯一正确的答案；
  • 但你很容易判断「A 比 B 好」。

「更难写绝对答案，但容易做相对比较」这个不对称性就是偏好优化的全部动机。 它决定了数据形态必须是排序而不是标签。

RLHF 的完整流程（三步） ​

第一步：收集偏好数据 ​

给同一个 prompt 让模型（通常是 SFT 后的模型）生成多个候选回答，由人类标注员对它们排序。实践中的取舍是很现实的：

  • 二选一（两两比较） 标注一致性最高、任务最简单、成本最低，也是最常见的形态；
  • 多选排序 信息量更大（一条排序能拆出多个比较对），但标注一致性下降；
  • 标注员的一致性本身是个变量：同一个标注员前后不一致、不同标注员之间的标准差异，都会直接变成奖励模型的噪声。因此实际操作通常是多条标注取多数，并且写清晰的标注指南。

产出形式是「 优于 」（winner / loser）这样的比较对。

第二步：训练奖励模型（Reward Model, RM） ​

训练一个模型 ，输入 prompt + 回答，输出一个标量分数。目标是让被偏好的回答得分更高。常见的损失（Bradley-Terry 风格的成对对数似然）：

这个损失里藏着两个必须能讲的信息：

  1. 右边是分数的「差」，说明奖励模型学的不是绝对分数，而是相对偏好。这也是为什么单独拿 RM 的绝对分数做阈值通常不可靠 —— 它只被训练过排序。
  2. 用 sigmoid 而不是直接回归：因为标注给的是「A 优于 B」这种二元比较，用 logistic 形式与之对应。如果标注给的是带强度或具体分数（例如 1 到 5 分），那才适合回归损失 —— 这也是有的工作直接训一个打分模型的原因，但绝对分数的标注一致性通常更差。

奖励模型的初始化：通常从 SFT 模型（或同规模模型）初始化，把最后的输出头换成输出一个标量的线性层。

奖励模型的质量决定一切：它是整个 RLHF 的上限。RM 一旦有系统偏差（偏好长回答、偏好好的排版、偏好某些措辞），策略就会把这种偏差放大 —— 这叫奖励过优化（reward over-optimization），表现为 RM 打分持续上升但人类评价先升后降。「RM 分数涨而人工评价跌」是一个必须能说出的现象。

第三步：用强化学习优化策略模型 ​

以 SFT 模型为初始策略 、以 RM 为奖励，做强化学习。目标：

两个术语必须能解释：

  • ：奖励项，让策略往 RM 打分高的方向走。
  • 惩罚项：把新策略拴在参考模型 （通常是 SFT 模型、参数冻结）附近。为什么必须有：RM 只是一个学出来的近似，它必然有偏差。无限制地最大化 RM，策略会找到那些「RM 打分高但实际很差」的输出 —— 这就是奖励黑客（reward hacking）。KL 项的作用是限制策略跑出 RM 的置信区间。

注意一个容易讲错的细节：这个 KL 是逐 token 累加在整个回答上的（序列级的 KL 是一串 token 级 KL 之和），不是对整句话算一个 KL。实现上通常在每个生成 token 处计算「策略与参考模型在该 token 上的 log 概率差」，把它作为逐 token 的惩罚加进奖励。这就是为什么 PPO 里的奖励信号是逐 token 的：最后一步（或每个回答结尾）拿到 RM 给的序列级奖励，KL 惩罚按 token 摊开。

PPO 在这条链路里做什么 ​

PPO（Proximal Policy Optimization）是一种策略梯度方法。它在 RLHF 里的角色是「怎么根据奖励信号更新语言模型」，而不是 RLHF 本身。要讲清四个部件：

部件作用是否需要训练
策略模型（actor）生成回答，就是我们要优化的语言模型是
参考模型（reference）提供 KL 惩罚的基准，冻结否
奖励模型（reward）给完整回答打一个标量分否（已训好，冻结）
价值模型（critic）预测「从当前状态往后能拿到多少累计奖励」，用于估计优势是

为什么需要 critic（价值模型）？ 这是 PPO 的核心。策略梯度需要一个「这个动作比平均水平好多少」的信号，也就是优势（advantage）。但奖励只在回答结束时才有，中间的 token 没有奖励。critic 就是用来估计每个中间位置往后能拿到的期望回报的，从而把序列级的奖励摊到每个 token 上，降低梯度方差。GAE（广义优势估计）是这个估计的具体做法。「critic 是为了降低方差、把终局奖励摊到每一步」这一句就够面试用了。

PPO 的「proximal（近端）」体现在哪？ 它的损失里有一个**裁剪（clipping）**机制：比较新旧策略在同一个动作上的概率比，如果这个比值超出了 区间，就把梯度截断。

为什么要裁剪：策略梯度的一大问题是步长不可控 —— 一次更新可能让策略剧变，之后采样出的数据分布完全不同，训练崩掉。裁剪相当于说「这一批数据只允许我在旧策略附近挪一小步」，从而让「用旧策略采样的数据」在更新后仍然大致有效（这是 on-policy 方法能用少量多次更新的前提）。这就是「proximal」的含义。

PPO 在 LLM 场景里的额外工程代价：

  • 四套模型同时在显存里（策略 + 参考 + 奖励 + 价值，后两者在 LLM 规模下也是大模型）；
  • 在线采样：每一步都要用当前策略生成回答，采样成本与生成成本直接叠加到训练成本上；
  • 价值模型也是 LLM 规模，训练它需要额外的 optimizer 状态；
  • 超参敏感：KL 系数 、裁剪范围 、学习率、batch 与 rollout 长度，任何一项不当都会让奖励曲线震荡或崩溃。

实现要点（几乎全是坑） ​

① 参考模型仍然必须在场。 DPO 不是不需要参考模型，它只是不需要奖励模型。参考模型通常是 SFT 模型的冻结副本，所以显存里至少有两份模型（或一份权重 + 一份只查 log 概率的冻结副本）。说 DPO「不需要额外模型」是不准确的。

② log 概率要从 logits 重算，不能直接用现成 API 的输出。 实现上要在同一个前向里同时得到策略与参考模型的每个 token 的 log 概率，再在回答的 token 位置上求和（或求平均）。prompt 位置的 log 概率不能算进去 —— 这和 SFT 只在 assistant 段算损失是同一个纪律。

③ 长度归一化的选择会显著影响结果。 序列级的 log 概率是逐 token 累加的，因此更长的回答天然有更小的（更负的）log 概率，这会引入长度偏差。缓解手段是长度归一化（按回答 token 数平均），有的实现用长度归一化的 DPO 变体。这个坑必须知道 —— 它是 DPO 训练中出现「模型变得极其冗长或极其简短」的常见原因。

④ 偏好数据的质量比数量重要，而且要小心「可察觉的伪特征」。 如果数据里被偏好的回答总是更长的那个，模型学到的是长度而不是质量。这与奖励模型面临的偏差是同一个问题，只是换了个位置暴露。这是「A 比 B 好」标注数据最现实的陷阱。

⑤ DPO 与 SFT 的学习率不同。 DPO 的损失尺度与 SFT 不同，实践中通常需要比 SFT 更小的学习率，虽然具体取值依实现而定。不要背数字，说清「需要单独调、且不能用 SFT 的学习率」就够了。

⑥ 还有一个必须知道的风险：DPO 可能损害推理能力。 因为偏好数据主要是「有用 / 无害 / 风格」，这类数据往往偏好更平铺直叙、更少绕弯的回答，用它做偏好优化有可能削弱模型在多步推理上的表现。这是社区中反复讨论过的现象，也是很多工作要把推理数据混进偏好数据里的原因。

这张表的每一行都能对应一句面试话：

  • DPO 的「离线」是它最大的限制。离线意味着策略永远学不出数据分布之外的东西；PPO 可以在线采样，产生新的回答并用 RM 评价，因此能在数据边界外继续改进。这是 PPO 至今没有被完全替代的根本原因。
  • DPO 的简单也是实打实的优势：它把 RLHF 从「一整套分布式训练工程」降级成「一个和 SFT 差不多复杂的训练脚本」。这让没有大规模 RL 工程能力的小团队也能做偏好优化。
  • 实践中的常见组合：先 SFT，再 DPO（低成本拿到大部分偏好收益）；如果能拿到高质量 RM 且需要进一步压榨，再用 PPO 做在线优化。「DPO 是 RLHF 的平价替代」这个说法在工程上基本成立，但「在线 vs 离线」这条边界不能省。

这一块在你项目的语境下：什么时候根本不该做偏好优化 ​

该拒答时没拒答不该 —— 先做 guard / 阈值校准（这是分类问题，不是偏好问题）
回答能用但语气生硬、表述啰嗦该 —— 这才是偏好优化的主场
两个回答都对，但一个更贴合业务口径该 —— 而且这正好是偏好数据的形态

这张表是这一页最实用的产出。 它把「要不要上 RLHF」变成一个由 badcase 类型决定的判断，而不是由技术时髦度决定。

和你自己的项目对上号 ​

① 你项目的 badcase 类型决定了「不该做偏好优化」。 你项目二的错误分布经过分层评测分析过：主要错误集中在检索没召回正确片段，以及该拒答时没拒答。按这一页的判断表，两者都不属于偏好优化的适用范围 —— 前者是知识注入（靠混合检索 + 重排），后者是分类与阈值校准问题（靠 guard 模块与阈值调参）。这是一个由评测数据支撑的、有说服力的「不做」决策。 它比「我还没学到 RLHF」强得多。

② 但你有一套「准偏好数据」，只是形态不同。 你的评测集是分层标注的，每条样本带着「这个回答是否合格 / 引用是否可核对」的判断。如果你愿意，可以把「同一问题的两个不同版本回答 + 人工判断哪个更好」构造成偏好对 —— 这就是偏好数据的最小形态。

关键是要诚实地说清它的局限：规模小、标注者只有你一个人、并且没有经过一致性检验（无法估计标注噪声）。所以它不足以支撑一次可靠的 DPO 训练，但足以用来验证「偏好数据的构造流程」。把这个边界说清楚，比声称「我做了一个偏好数据集」要可信得多。

③ 你的回归门禁里有一样东西正是 RLHF 缺的：人工评价的兜底。 RLHF 最大的陷阱是「RM 分数涨、人工评价跌」。你的系统用配对检验 + 效应量门槛 + 三态退出码来防止「指标涨了但实际没变好」。这两件事的结构完全一样：都是「用一个自动化指标代替真实偏好，然后用统计纪律防止自欺」。这个类比说出来，能把你已有的工程体系和 L1 的偏好优化议题接上，而不是显得你在硬扯。

④ 你的 guard 模块与 DPO 里的 是同一个东西的不同实例。 DPO 里的 控制「允许多大程度偏离参考模型」；你的拒答阈值控制「允许多少『不确定就硬答』」。两者都是对模型自由度的显式约束，也都要在过度保守（什么都不答）与过度激进（什么都答）之间找到操作点。你的三档切块消融、拒答阈值扫描，本质上就是在扫这个操作点 —— 这是「用评测数据选约束强度」的同一套方法论。

可执行的小实验（低成本验证 DPO 的机制，不训练模型）：

实验 A（半天，纯数值验证）：手算一遍 DPO 损失。 取你项目二的两条真实 badcase：同一个问题的「正确答案」与「模型给出的错误答案」，构造成一个偏好对。用 API 拿这两条回答在你当前模型下的逐 token log 概率（多数 OpenAI 兼容接口能返回 logprobs；如果接口不支持，就换成本地小模型跑一遍）。然后：

  • 手算 ；
  • 如果你有 SFT 阶段前后的两个模型版本，再算上参考模型的项，得到完整的 DPO 损失值；
  • 预期结论：正确答案的 log 概率应该高于错误答案，因此损失较小。如果你测出来反了，那说明你的 prompt 或模型在「更偏好错误回答」—— 这本身就是一个极有价值的发现。

实验 B（1–2 天，验证长度偏差这个坑）： 在你的评测集上，统计「模型生成的正确回答」与「错误回答」的平均长度。如果在你的数据里正确答案系统性地更长，那么任何偏好优化都会学到「更长=更好」这个伪特征 —— 你需要在构造偏好数据时做长度控制，或者用长度归一化的损失。这个检查你的数据就能做，不需要训练任何模型，但它直接预言了一次 DPO 训练会不会跑偏。

面试怎么问 ​

Q1：RLHF 的完整流程是什么？

A（要点）：三步。① 收集偏好排序数据（同一 prompt 的多个回答由人类排序，最常见是二选一）；② 训练奖励模型 —— 损失是 ，右边是分数差，说明它学的是相对偏好而非绝对分数；③ 用强化学习（PPO）优化策略，目标是「奖励最大化 + KL 约束」，参考模型通常是 SFT 模型的冻结副本。

加分句：「奖励模型一定是有偏的近似，所以 KL 惩罚项不是正则化技巧，而是对抗奖励模型偏差的必要装置 —— 没有它，策略会找到『RM 打分高但实际很差』的输出，也就是奖励黑客。」

别说：「RLHF 就是让人给回答打分然后训练。」漏掉了「排序 → 奖励模型 → RL」这三个关键环节。

Q2：RLHF 里 PPO 具体在做什么？为什么需要价值模型？

A（要点）：PPO 负责「怎么根据奖励信号更新语言模型」。奖励只在回答结束时给出，中间 token 没有奖励，所以需要一个价值模型（critic）来估计每个位置往后能拿到的回报，从而算出优势、把终局奖励摊到每个 token 上、降低梯度方差。PPO 的「近端」体现在概率比裁剪上：一次更新只允许策略在旧策略附近挪一小步。

为什么必须裁剪：策略梯度如果步长不可控，一次更新就会让采样分布剧变、训练崩掉。裁剪让「用旧策略采样的数据」在更新后仍然大致有效，这是 on-policy 方法能对同一批数据做多次更新的前提。

加分句：「所以 PPO 在 LLM 场景的代价很具体：四套模型同时在显存里（策略、参考、奖励、价值），价值模型也是 LLM 规模、也要训练，再叠加在线采样的生成成本。」

别说：「PPO 就是一个优化器。」它是策略梯度类的 RL 算法，和 Adam 那类优化器不是一个层级的东西。

Q3：DPO 为什么不需要奖励模型？

A（要点）：从推导上讲，而不是从效果上讲。① 起点是「KL 约束下的奖励最大化」，它与 RLHF 第三步的目标完全一致；② 这个问题有闭式最优解（最优策略 = 参考策略乘以奖励的指数、再归一化）；③ 把它反解，奖励就能表示成「策略与参考模型的 log 概率比」加一个只依赖 prompt 的归一化项 ；④ 代进 Bradley-Terry 偏好损失里，两个 项在相减时消掉了。

所以 DPO 的损失就是一个在偏好对上的二分类损失，它希望「被偏好回答的相对对数概率提升」大于「被拒回答的相对对数概率提升」。参考模型一直在场（就是那个比值），隐含的 KL 约束是结构自带的，不是额外加的项。

加分句：「但要纠正一个常见误解：DPO 不是不需要参考模型，只是不需要奖励模型。 显存里仍然至少有两份模型，而且要在同一个前向里逐 token 重算 log 概率。」

别说：「因为 DPO 直接优化偏好数据。」这只是把问题重述了一遍，没答「为什么可以」。

Q4：DPO 相比 PPO 的缺点是什么？

A（要点）：核心是离线 vs 在线。DPO 用的是固定的偏好数据集，策略无法探索数据之外的空间，只能在已有数据的分布里改进；PPO 可以在线采样、产生新的回答并用奖励模型评价，所以能在数据边界外继续优化。这是 PPO 至今没有被完全替代的根本原因。

另外两个具体风险：① 长度偏差 —— 序列级 log 概率是逐 token 累加的，更长的回答天然 log 概率更低，偏好数据里如果「正确答案总是更长」，模型会学到「长=好」；② 能力退化 —— 偏好数据常偏好平铺直叙、少绕弯的回答，用它做优化可能削弱多步推理表现。

加分句：「所以我的判断是：DPO 是 RLHF 在工程上的平价替代，但『在线 vs 离线』这条边界不能省。如果我能拿到高质量奖励模型并且需要进一步压榨，在线优化仍然是更强的方案。」

别说：「DPO 效果比 PPO 差。」很多场景下 DPO 的效果是持平甚至更好的，笼统说差会被追问场景。

Q5：你的项目为什么不做 RLHF / DPO？

A（要点）：按 badcase 类型判断，而不是按技术时髦度。我的错误分布是分层评测出来的：主要错误是①检索没召回正确片段、②该拒答时没拒答。①是知识注入问题，偏好优化解决不了；②是分类与阈值校准问题，属于 guard 模块与阈值调参。偏好优化的主场是「多个都能接受的回答之间排序不对」，而我现在的 badcase 还没走到那一步。

加分句：「如果我要做，数据条件是明确的短板：我的偏好标注只有我自己一个人，没有一致性检验，规模也小 —— 不足以支撑一次可评估的偏好优化。我宁可先把瓶颈修到『回答质量本身没问题』，再考虑偏好层面的优化。在坏数据上做偏好优化，只会把噪声学成偏好。」

别说：「RLHF 太难了我没做。」难不是理由，判断顺序才是理由。

Q6：奖励模型有什么问题？怎么发现它出问题了？

A（要点）：奖励模型是人类偏好的近似，会有系统偏差：偏好长回答、偏好好的排版、偏好某种措辞、对某些话题过度谨慎。策略会把这些偏差放大。典型症状是奖励持续上升但人工评价先升后降（奖励过优化）。缓解手段：加更强的 KL 约束、早停（在人工评价的拐点停）、用多个奖励模型的集成、以及在偏好数据里显式控制长度等伪特征。

加分句：「我在项目里有一个同源的机制：我的回归门禁用配对检验和效应量门槛来防止『指标涨了但实际没变好』。RLHF 的奖励过优化是同一类问题 —— 用一个自动化指标代替真实偏好，然后用统计纪律防止自欺。所以这个概念我理解得比较具体，不是只背了一个名词。」

别说：「奖励模型就是错的。」它是近似的、有偏的，不是随便乱来的。
