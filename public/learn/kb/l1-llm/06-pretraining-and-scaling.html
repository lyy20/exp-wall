预训练、Scaling Law 与涌现能力 ​

覆盖知识点：L1-12 L1-13 ｜ 面试频率：高 ｜ 建议学时：5h

一句话说清 ​

预训练做的事只有一件：用海量文本做下一 token 预测（）。Scaling Law 发现损失随参数量、数据量、算力呈幂律下降，Chinchilla 的结论是「给定算力预算时，参数量与数据量应当同步放大，而不是一味堆参数」。而涌现能力与上下文学习（ICL）、思维链（CoT）是规模带来的能力层面的跃迁：模型不更新权重，仅凭 prompt 里的示例或推理步骤就能完成新任务。这两件事合起来解释了「为什么今天的大模型可以靠 prompt 而不是靠重训来做新任务」。

为什么必须学 ​

面试里这一页的考法很集中：

  1. 「为什么现在不继续堆参数了？」 —— 考 Scaling Law 与 Chinchilla 的结论。答「因为参数量太大跑不动」是工程视角，答「因为数据量也要同步放大，否则参数会被训不足（undertrained）」才是原理视角。
  2. 「为什么大模型能做没训过的任务？」 —— 考 ICL。这题的正确答案不是「因为参数多」，而是「预训练目标本身逼迫模型学会从上下文里找规律」。
  3. 「CoT 为什么有效？」 —— 高级追问。核心是计算步数：让模型把中间结果写成 token，等于给它在自回归框架里增加了串行的计算步骤。

还有一个非常实用的角度：你项目里所有「换模型」「调 prompt」「加 few-shot 示例」的决策，都属于这一页的范畴。能不能说清「我为什么选这个规模的模型」而不是「因为便宜」，是这一页要补的东西。

核心内容 ​

L1-12 预训练目标：下一 token 预测 ​

给定序列 ，语言模型建模联合概率

自回归分解成逐位置的条件概率，训练目标是交叉熵

其中 ， 是第 个位置最后一层的隐状态， 是映射到词表的输出投影（LM Head）。

几个必须说清的点：

  • 为什么叫「自监督」：监督信号就是文本本身右移一位，不需要任何人工标注。互联网上所有文本都是训练数据，这是大模型能被喂到万亿 token 的根本原因。
  • teacher forcing 与因果掩码：训练时整条序列一次前向，每个位置的标签就是它的下一个 token。这能成立，全靠因果掩码保证位置 看不到 ——否则模型直接抄答案。这就是掩码与目标函数之间的强耦合关系。
  • loss 与困惑度（perplexity）：。PPL 越低表示模型对真实文本的「意外程度」越低。perplexity 是 token 级的指标，跨 tokenizer 不可直接比较——不同 tokenizer 把同一句话切成不同数量的 token，PPL 自然不同。这一点经常被忽略，说出来很加分。
  • 训练数据的关键不是「量」而是「配比与质量」：去重（重复数据会让模型记住而不是泛化）、质量过滤、领域配比（代码/数学/多语言的占比会显著影响能力结构）。数据配比是预训练最重要的旋钮之一，也是各家不公开的核心秘密。

Scaling Law：损失是幂律 ​

核心经验规律的形式：

其中 是参数量、 是训练 token 数（有时把算力 作为变量）， 是不可约损失（数据本身的熵下界）。 这一项很关键：它意味着损失有地板，不能靠堆算力降到 0。

三条可直接说出口的结论：

  1. 幂律不饱和：在很宽的范围内， 或 增大 10 倍，损失按固定指数下降 —— 这意味着「继续变大仍然有收益」，是可预测的。
  2. 参数量与数据量都要涨：只涨一个方向会撞到瓶颈。参数足够大但数据不够，模型处于 undertrained 状态，等效于浪费参数。
  3. 可以外推规划：小规模实验拟合出幂律系数后，可以预测大模型的损失，在真花钱训练之前决定投多少算力。这是 Scaling Law 最实际的商业价值。

Chinchilla 的结论（面试高频）：

给定固定的训练算力预算，最优的参数量与数据量应同步放大。Chinchilla 系列实验给出的经验配比是每个参数配约 20 个训练 token 这个量级。

它的历史意义：在这个结论之前，主流做法是「参数尽量大、数据相对少」，导致很多大模型严重 undertrained。按 Chinchilla 的口径加数据、减参数，同算力预算下可以拿到更低的损失。

必须补上的后续讨论（能说出来就是加分项）： Chinchilla 的优化目标是「训练算力固定时损失最小」。但真实世界里推理成本才是长期成本大头：一个模型训完会被调用无数次，推理成本与参数量成正比、与训练 token 数无关。所以从总拥有成本看，人们反而倾向于「用远多于 20 倍的数据去训一个更小的模型」——这是很多开源模型「参数不大但数据量极大」的策略来源。「训练最优」不等于「部署最优」，这句话是这一节的收束。

Scaling Law 的边界（诚实地说）：它是经验规律，不是理论定理；它在数据质量、架构、训练技巧变化时会失效；它预测的是损失，不是具体任务能力。面试里说清「它是外推规划工具，不是能力保证」，比背公式更能体现理解。

L1-13 涌现能力与上下文学习（ICL） ​

**涌现能力（emergent abilities）**的含义是：某些任务能力在小模型上接近随机水平，规模跨过某个门槛后快速上升，曲线看起来像相变。

一个诚实的补充（能说出这个分歧是加分的）：有研究认为部分「涌现」可能是评测指标选择造成的假象 —— 如果用连续型指标（如 token 级准确率）而不是离散指标（如整题对错），曲线会平滑很多。也就是说「突变」可能部分来自度量方式，而不是模型内部真的发生了相变。面试里把「这是有争议的概念」说出来，比断言「大模型会忽然学会新能力」要专业得多。

上下文学习（In-Context Learning, ICL）：在 prompt 里给若干「输入→输出」示例（few-shot），模型不更新任何权重就能完成新任务。

为什么预训练会产生 ICL？（这是核心问题）

  • 预训练语料里充满了隐含的任务示例：文档、代码、问答、翻译对照、FAQ 列表……要在这些数据上降低下一 token 预测损失，模型必须学会「识别当前上下文隐含的任务，并模仿其模式」。
  • ICL 可以理解为前向传播中的隐式学习：注意力在上下文里定位到相似示例，并提取「输入→输出」的映射规律；这种映射以激活的形式存在，做完这一轮就消失（不写进权重）。
  • 所以 ICL 不是大模型附赠的魔法，而是预训练目标的必然产物。

ICL 的实践要点：

  • 示例的格式一致性比示例的数量更重要：标签空间、分隔符、字段顺序的漂移会显著降低效果。这是所有 prompt 工程的地基。
  • 示例的顺序有影响，这和注意力对位置与相似度的敏感性是一致的。
  • few-shot 与微调的取舍：few-shot 零成本、可即时切换任务，但会占用上下文预算、且对格式敏感；微调效果更稳、不占上下文，但需要数据与训练成本。你项目里两者都没上，用的是 prompt + 检索注入——这个选择要能讲清理由（见下文）。

思维链（Chain-of-Thought, CoT）：让模型先写出中间推理步骤再给答案，在多步推理任务上显著提升正确率。

它为什么有效（面试重点，要给出机制解释）：

  1. 计算步数的观点（最重要）：自回归模型的串行计算量正比于它生成的 token 数。Transformer 每一层的深度是固定的，一次前向只能做固定次数的非线性变换；而把推理过程写成 token，等于让模型多次前向、把中间结果记在上下文里。所以 CoT 是用生成更多 token来换更深的有效计算。
  2. 把隐式计算外显化：中间结果一旦写成文本，就成了后续步骤的上下文的一部分，可以被注意力直接读取，不需要全部塞在固定宽的隐状态里。
  3. 对齐了训练分布：如果预训练语料里存在大量「推理过程 + 结论」的文本（教材、解题、代码注释），那么 CoT 的格式正好落在模型见过的分布里。

CoT 的边界：它不是万能的——如果任务本身不需要多步推理（如简单事实抽取），CoT 只会增加成本与延迟；而且 CoT 的中间步骤可能出错但不被发现（错误会沿着链条传播）；另外把推理过程输出出来对用户不总是必要的（这是后来「推理模型」把思考过程与最终答案分离的动机之一，见本层最后一页）。

与训练三阶段的关系（承上启下） ​

预训练产出的是一个**「文本续写器」**：它见过海量知识，但不会听指令。它会补全你给的文本，而不是回答你的问题。把它变成助手需要后训练（SFT / RLHF），那是接下来几页的事。

一条必须建立的因果链：预训练决定了模型的能力上限（知识与推理基础），后训练决定了模型的行为方式（是否听话、是否安全、输出格式如何）。 后训练不能凭空造出预训练里没有的能力。

和你自己的项目对上号 ​

① 你的「选模型」决策需要 Scaling Law 的语言。 项目一与项目二都用 OpenAI 兼容协议调 deepseek-flash。面试官一定会问「为什么用这个」。不要说「因为它便宜 / 因为它快」就完——那只是结论。要能拆成三层：① 任务性质：你的场景是检索增强 + 指令跟随 + 结构化工具调用，不需要模型自己做多步硬推理，所以不需要把预算花在最大规模的模型上；② 成本结构：推理成本与参数量成正比，而你的系统要处理的是「多个片段 + 多轮历史」的长 prompt，上下文长度本身也会推高成本；③ 可替换性：走 OpenAI 兼容协议意味着模型是可插拔的，先用够用的档位跑通全链路与评测，再用评测数据决定要不要升档。这三层说清楚，就是「我在做工程权衡」而不是「我随手选了一个」。

② 你的成本报告天然是「训练最优 vs 部署最优」的实例。 项目二有成本报告。你关心的全是推理成本（每千次调用的 token 花费、延迟），没有训练成本——这正是 Chinchilla 后续讨论里那个「推理是长期大头」的现实投影。你可以这样讲：「Chinchilla 是在训练算力固定的前提下做的优化；而我的成本报告优化的对象是推理。这两者结论不同不是因为谁错了，而是目标函数不同。」这句话会立刻把你和「背过 Chinchilla」的人区分开。

③ 你的 few-shot 示例设置是 ICL 的直接应用。 YYHelp 的意图分流（9 类意图到 5 个出口）和项目二的答案生成都可能用到 few-shot 示例。ICL 的实践要点直接变成你的工程规范：

  • 格式一致性比数量重要：意图分类的 few-shot 示例必须标签空间固定、字段顺序固定、分隔符固定。任何漂移都会让效果抖动 —— 这也是你回归门禁应该覆盖的一类变化（改 prompt 示例导致的分数波动）。
  • 示例顺序有影响：这意味着你的评测必须是同一套 prompt 固定顺序下对比，否则 A/B 之间的差异可能只是顺序噪声。这一条直接连到你那些配对 t 检验的结论可信度上 —— 如果 prompt 版本之间不仅改了内容还改了示例顺序，你就分不清是哪个因素在起作用。

④ 你的评测门禁与「涌现叙事」的冲突要提前准备。 你项目二的评测集是分层 + 本人标注的，并且有回归门禁。面试官可能会问：「你怎么知道换模型是变好了而不是评测集噪声？」你的答案要落在这页的原理上：Scaling Law 预测的是损失，不是任务分数；任务分数在小样本评测上的方差往往大于模型差异。所以你的做法是配对检验 + 效应量门槛 + 三态退出码 —— 宁可判「不确定」也不报一个假的提升。这是「我懂评测的统计基础」的强证据。

⑤ ICL 与 RAG 的分工（一个很好的对比题）。 面试官常问：「ICL 能在上下文里学新知识，那还需要 RAG 吗？」你的答案：ICL 学的是「任务的映射模式」（格式、标签空间、风格），RAG 提供的是「事实性内容」。 两者不冲突 —— 你用 few-shot 例子固定输出格式，用检索注入提供事实依据。注意 RAG 与 ICL 有一个共同约束：都吃上下文预算（本层第 5 页）。所以「用 few-shot 还是检索」在预算上是有竞争的，这是你 YYHelp 里真实存在的取舍。

可执行的小实验（ICL 的格式敏感性）：用你项目二的分层评测集，构造三组 prompt：

  1. 标准 few-shot（格式严格一致）；
  2. 同样数量的示例，但打乱字段顺序或加一个不相关的示例；
  3. 零样本（只给指令）。

在同一批问题上跑三次，记录准确率并用配对检验比较。判据：如果 1 和 2 的差距超过了你的效应量门槛，你就实测到了「格式一致性比示例数量更重要」这句话；如果差距很小，那说明你的任务对格式不敏感 —— 两种结果都是有效的实验结论，把它写进笔记。这个实验的方法论与你项目二的回归门禁完全一致，可以直接复用脚本骨架。

面试怎么问 ​

Q1：预训练的损失函数是什么？为什么能自监督？

A（要点）：交叉熵 ，自回归分解成逐位置的条件概率。自监督的原因是标签就是文本右移一位，不需要人工标注。整条序列一次前向能并行计算，前提是因果掩码挡住未来位置，否则模型直接抄答案。

加分句：「这个目标还有一个连带好处是评价指标自带：。但要注意 PPL 是 token 级指标，跨 tokenizer 不可直接比较 —— 不同分词器把同一句话切成不同数量的 token。」

别说：「预训练就是用大量文本训练模型。」这没有说出「右移一位」这个关键结构。

Q2：Scaling Law 说了什么？Chinchilla 的结论是什么？

A（要点）：损失对参数量 与数据量 呈幂律下降，形式是 。 是不可约损失，意味着有地板。三条用途：幂律不饱和（继续变大仍有收益）、必须同步放大 与 、可用小实验外推规划大训练。

Chinchilla 在训练算力固定的前提下给出：参数量与数据量应同步放大，经验配比在每参数约 20 个 token 的量级。

加分句：「但要补一句后续讨论：Chinchilla 优化的是训练算力，而推理是长期成本大头，且只与参数量成正比。所以从总拥有成本看，很多人反而选『更小的模型配远多于 20 倍的数据』。训练最优不等于部署最优 —— 我在项目里做的成本报告优化的就是推理这一侧。」

别说：「Chinchilla 说 20 倍最优，所以就该按 20 倍做。」不考虑目标函数就照搬结论是典型的背书式回答。

Q3：大模型为什么能做没有专门训练过的任务？

A（要点）：上下文学习。它是预训练目标的必然产物：预训练语料里到处是隐含的任务示例（翻译对照、问答、代码、文档），要降低下一 token 损失，模型就必须学会识别上下文隐含的任务并模仿其模式。ICL 可以理解为前向传播中的隐式学习——注意力定位相似示例并提取映射，以激活形式存在，不写进权重。

加分句：「所以 ICL 学的是任务的映射模式（格式、标签空间、风格），不是新知识 —— 这就是它和 RAG 的分工：few-shot 管格式，检索管事实。两者都要吃上下文预算，在工程上是竞争关系。」

别说：「因为参数多所以记住了更多东西。」这是把 ICL 和记忆混为一谈。

Q4：CoT 为什么有效？

A（要点）：最核心的机制是计算步数。自回归模型的串行计算量正比于它生成的 token 数，而 Transformer 单次前向的深度固定。把中间步骤写成 token，等于多次前向、逐步推进，把中间结果外化到上下文里供后续读取。次要机制：外化的中间结果可以被注意力直接读，不必全压在固定宽度的隐状态里；且「过程 + 结论」的格式落在预训练分布里。

加分句：「所以 CoT 是用更多 token 换更深的有效计算 —— 这也解释了它的成本：在不需要多步推理的任务上，CoT 只增加延迟不增加准确率，而且中间步骤错了会沿着链条传播。」

别说：「CoT 是因为把问题拆开所以更简单。」这是描述现象，没有机制。

Q5：涌现能力是真的吗？

A（要点）：这是一个有争议的概念。现象是某些能力在小模型上接近随机，规模跨过门槛后快速上升。但有研究认为部分「涌现」可能来自评测指标的选择 —— 用离散指标（整题对错）看曲线像相变，用连续指标（token 级准确率）看则平滑得多。

加分句：「对我的实际意义是：不要指望换一个更大的模型就自动获得某个任务的能力，要用自己的评测集去测。我项目二的评测集就是分层设计的，而且有回归门禁，判断『是否变好』靠的是配对检验加效应量门槛，不是看单次分数。」

别说：「涌现就是大模型忽然学会了新能力。」断言一个学界仍有分歧的结论，不如展示你两边都懂。
