从 NLP 到 Transformer：文本表示演进与三种架构范式 ​

覆盖知识点：L1-01 L1-09 ｜ 面试频率：高 ｜ 建议学时：7h

一句话说清 ​

文本表示经历了四级台阶：one-hot 的稀疏符号、TF-IDF 的统计权重、Word2Vec 的稠密静态向量、再到上下文化的动态表示；Transformer 用自注意力取代循环结构，让任意两个位置之间的信息传递路径长度恒为 且可完全并行。而 Transformer 的三种堆叠范式（Encoder-only / Encoder-Decoder / Decoder-only）不是历史分支，而是决定了今天该用哪个模型做什么事：要表征就去 Encoder-only，要生成就去 Decoder-only，输入输出都是变长序列才用 Encoder-Decoder。

为什么必须学 ​

面试官在「基础」环节几乎必问一句：「BERT 和 GPT 有什么区别，为什么现在都用 GPT 那一套？」 这道题不是考记忆力，是在筛三类人：

  • 答「一个是双向一个是单向」就停 —— 判定为背过八股，没想过为什么。
  • 答「因为 GPT 效果更好」 —— 判定为不知道范式与任务的对应关系，接下来会追问「那你项目里的 Embedding 为什么用双向的」。
  • 能答出「表示任务要双向上下文，生成任务必须因果；而通用能力靠大规模自回归预训练 + 指令微调获得」 —— 才算过关。

这一页同时是整层的动机起点：后面所有页（注意力、位置编码、KV Cache、解码策略）都在回答「Decoder-only 自回归这条路线带来了什么代价」。

核心内容 ​

L1-01 文本表示的四级台阶 ​

第一级：one-hot 与词袋。 词表大小 ，每个词是一个长度 的向量，只有一位是 1。维度随词表线性膨胀（中文词表几十万量级），任意两个不同词的余弦相似度恒为 0 —— 它完全不含语义。词袋模型（bag of words）把句子表示成词频向量，顺带丢掉了词序：「狗咬人」和「人咬狗」得到同一个向量。

第二级：TF-IDF。 给每个词一个统计权重：

是词在文档内的频次， 是包含该词的文档数， 是文档总数。高频但无区分度的词（「的」「the」）被 项压下去。它到今天仍然是 BM25 的近亲、稀疏检索的基线 —— 词序与语义依然没有。

第三级：Word2Vec。 用「一个词的含义由它的上下文决定」这条分布假设，把词映射成低维稠密向量（典型 ）。两个训练目标：

  • Skip-gram：给定中心词 ，预测窗口内的上下文词 ，。
  • CBOW：反过来，用上下文词的平均预测中心词。

目标函数是全词表的 softmax，直接算要 次内积，训练不可行，于是用负采样（negative sampling）把它简化成二分类：正样本是真实共现的 ，负样本从噪声分布（常用词频的 次方）里抽 个，优化

它买到了什么：稠密、低维、有语义结构（king − man + woman ≈ queen）。它的致命伤：每个词只有一个向量，与上下文无关 —— 也就是一词多义（polysemy）问题。「苹果」在「吃苹果」和「苹果发布会」里必须是同一个向量，这是静态词向量的天花板，不可能靠调参解决。

第四级：上下文化表示。 ELMo 用双向 LSTM 拼接两个方向的隐状态，同一个词在不同句子里得到不同向量 —— 方向对了，但 LSTM 有三个问题：串行（无法并行，长序列训练慢）、长依赖衰减（信息在时间步之间反复经过非线性变换后衰减）、以及所谓「双向」只是两层单向拼接，不是真正的全局双向。

Transformer 的解法。 自注意力让每个位置直接看到所有位置：

结构两个位置间的路径长度并行度
RNN / LSTM（随距离线性增长）串行
自注意力（一层内直达） 深度并行

这一栏才是重点：Transformer 对 RNN 的根本优势不只是「能并行」，而是信息传递路径长度与序列长度解耦。代价是每层计算量从 涨到 —— 这也是后面长上下文、KV Cache、FlashAttention 这一整条线的总源头。

L1-09 三种架构范式 ​

三者共享同一套 Block（多头注意力 + 前馈网络 + 残差 + LayerNorm），差别只在注意力掩码与注意力作用的对象。

Encoder-only（BERT 系）。 双向注意力，无因果掩码，每个位置能看到左右两侧全部 token。训练目标是 MLM（masked language modeling）：随机把一定比例的 token 换成 [MASK]，要求还原。它输出的是每个位置的上下文化向量。

Decoder-only（GPT 系）。 因果掩码（下三角矩阵），位置 只能看到 的位置。训练目标是下一 token 预测：。它输出的是下一个 token 的分布。

Encoder-Decoder（T5 / 原始 Transformer 系）。 Encoder 双向编码输入，Decoder 做因果自注意力并额外做 cross-attention 去读 Encoder 的输出。训练目标是序列到序列的还原（T5 用 span corruption：挖掉连续片段让模型补回来）。

选型判据（面试直接考这一段）：

你要做的事选什么原因
句向量 / Embedding / 召回 / 分类 / NLIEncoder-only双向上下文让表征质量最优；输出定长、可离线算、可建索引
问答生成 / 摘要 / 对话 / 工具调用 / 写代码Decoder-only自回归可生成任意长度；大规模预训练 + 指令微调后通用能力最强；生态与权重最多
输入输出都是变长序列（翻译、语音转写、结构化改写）Encoder-Decoder输入可以双向编码不被因果掩码限制，输出仍能自回归

要记住一句能直接说出口的结论：今天主流的通用生成模型基本都是 Decoder-only（GPT 系、LLaMA 系、Qwen 系、DeepSeek 系、GLM 系的对话模型）；Encoder-Decoder 主要活在翻译、语音、部分多模态场景；Encoder-only 则活在检索与判别的底座位置——它不生成文本，但几乎每个 RAG / Agent 系统的召回侧都靠它。

一个常见误区：以为「Decoder-only 是更先进的架构，所以 Encoder-only 过时了」。事实是它们在解不同的数学问题：Encoder-only 优化的是同一序列内的双向交互表征，Decoder-only 优化的是给定前缀的条件概率。拿 Decoder-only 取句向量（取最后一个 token 的隐状态）是可以跑，但那是权衡后的工程妥协，不是「更好的表示」。

和你自己的项目对上号 ​

你的两个项目里，Encoder-only 与 Decoder-only 是同时在跑的。 这不是历史遗留，而是上一节那张选型表在现实里的投影。

① bge-m3 是 Encoder-only —— 而且是双塔用法。 它把一段文本编码成定长稠密向量（具体池化方式与维度以模型卡为准）。关键在于：编码一段文本时不需要看到 query，所以 60+ 篇论文的 chunk 可以提前全部编码、存进 FAISS 索引。检索时只编码 query 一次，然后做 次向量内积。这就是你项目二的 FAISS IndexFlatIP 能成立的前提。

② bge-reranker-v2-m3 是 cross-encoder，属于 Encoder-only 的第二种用法。 它把 query 与 passage 拼成一个序列一起过编码器，输出一个相关性分数。因此：

  • 分数不能预计算（每换一个 query，所有文档的分数都得重算）；
  • 对全库打分意味着 次完整 Transformer 前向 vs 双塔的 次点积 —— 这就是为什么不能让 cross-encoder 直接对全库打分。

你现在有了一条能撑住追问的回答链：双塔负责把 降到 top-k，cross-encoder 只在这个缩小的候选集上做精排。你项目二那 36 个消融脚本里，粗排 top-k 的取值就是这套两阶段结构的直接旋钮。

③ 生成侧走 Decoder-only。 YYHelp 的主力 Agent 与项目二的答案生成都通过 OpenAI 兼容协议调 deepseek-flash，因为需要自回归生成 + 指令跟随 + 工具调用，这三件事只有在因果语言模型上才成立。同一套系统里并存两种范式，正是本页的落点。

④ jieba 与 subword 是两条不同路线。 YYHelp 稀疏路用 jieba（词典 + 统计的传统分词）建 BM25 倒排，稠密路用 bge-m3 自带的 subword tokenizer。二者服务于不同目标：前者要词级频次统计，后者要可组合的子词片段。为什么不能互换，见下一页。

可执行的小实验（30 分钟内能跑完）： 取你项目二里的一句真实 query，分别做两件事：

  1. 用 bge-m3 的编码器对 query 和它的正确 passage 各编码一次，算余弦相似度；
  2. 让 deepseek-flash 对同一对文本输出一个 0–10 的相关性打分，比较两者的排序。

观察点写进你的实验笔记：Encoder-only 的双向表示在「同一句话的两种说法」上是否比生成模型更稳定，以及 cross-encoder 分数与生成模型打分的排序是否一致。这一步的产出是你面试时「我实测比较过两种编码范式」的实物证据 —— 注意只记录你自己的观测，不要引用外部榜单数字。

面试怎么问 ​

Q1：为什么 Transformer 取代了 RNN？

A（要点）：三层。① 路径长度：自注意力里任意两个位置的交互路径是 ，RNN 是 ，长依赖不衰减；② 并行度：训练时整条序列一次前向，不受时间步串行限制，能喂满 GPU；③ 表达能力的取舍：代价是 的注意力矩阵，这个代价在 可控时是划算的。

加分句：「Transformer 真正的胜利是把顺序从计算结构里拿掉了 —— 顺序信息从此变成一个可设计的输入（位置编码），而不是网络拓扑的一部分。RoPE、ALiBi、长上下文外推这一整条线，都是因为顺序被解耦了才可能。」

别说：「因为 Transformer 精度更高/更先进」——这是结论不是原因，会被立刻追问「凭什么」。

Q2：BERT 和 GPT 的本质区别是什么？为什么现在都用 Decoder-only？

A（要点）：① 掩码不同 → 优化目标不同：双向 + MLM 学的是表征，因果 + 下一 token 预测学的是分布；② 任务接口不同：Encoder 输出向量要接一个任务头才可用，Decoder 输出分布天然可生成、可续写；③ 为什么 Decoder-only 成为主流：统一的训练目标和统一的接口。互联网上所有文本都是现成的自回归监督信号（不需要人为造 mask），而生成、对话、工具调用、代码补全在自回归框架下是同一个接口的不同 prompt。

加分句：转成你的项目语言 ——「所以我的检索侧必须用 Encoder-only，因为召回要的是可预计算、可建索引的定长向量；生成侧必须用 Decoder-only，因为我要的是流式吐字和工具调用。」

别说：「BERT 是双向的所以更强」「GPT 参数更大所以更强」。参数规模与范式是两个独立维度。

Q3：Embedding 模型和生成模型能互换吗？拿 GPT 取句向量行不行？

A（要点）：能跑但不该当默认。因果掩码让每个位置只能看到左侧，取最后位置的隐状态相当于只用了单向信息；而检索恰恰是双向对称的相似度判断。加上 Decoder-only 的隐状态是为「预测下一个 token」优化的，不是为「压缩成句向量」优化的。实践里用 Decoder-only 做 Embedding 需要专门训练（后接对比学习目标），并不是免费拿到。

加分句：「我在项目二里对 query 和 passage 都用同一个 bge-m3 双向编码器，就是为了让左右上下文都能进入表示 —— 如果是因果编码器，passage 后半句的信息对前半句的表示没有贡献，会让长 chunk 的表示偏斜。」

别说：「都可以，看哪个效果好」——这是回避问题。

Q4：cross-encoder 更好为什么不用它检索？

A（要点）：复杂度。双塔的相似度是向量点积，可以离线预计算全部文档向量、在线只算一次 query 向量；cross-encoder 的分数依赖 query-passage 配对，不可预计算，对全库打分等于 次完整前向。所以工程上的正解是两阶段：双塔粗排把 压到 top-k，cross-encoder 精排候选集。

加分句：「这个结构还有一个可调参数就是 top-k —— k 太小会漏掉召回阶段排名靠后但真正相关的文档，k 太大精排延迟线性上升。我项目二的消融就是围着这个 k 做的。」

别说：「cross-encoder 更准所以我用它」——不做复杂度分析就选型，是应届生最典型的失分点。
