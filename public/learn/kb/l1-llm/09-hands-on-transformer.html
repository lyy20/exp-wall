动手复现：手写 Tokenizer / TinyTransformer / LLaMA2 ​

覆盖知识点：L1-03 L1-18 L1-19 ｜ 面试频率：中 ｜ 建议学时：22h（这一层最重的动手量）

一句话说清 ​

这一页是 L1 的「动手总装」：用自己写的 BPE Tokenizer 把文本变成 id，用自己写的 TinyTransformer（解码器层堆叠） 做下一 token 预测，最后把它改造成与 LLaMA 架构对齐的版本（Pre-Norm + RMSNorm、RoPE、无 bias、SwiGLU、GQA）。产物不是「一个能用的模型」——教学规模的数据与算力不可能训练出有能力的模型 —— 而是一套你能逐行解释、能通过形状检查与因果性校验、能和 torch.nn 逐张量对齐的实现。它最大的面试价值在于：所有前面几页的公式，你都能指着代码说出它落在哪一行。

为什么必须学 ​

L1 前面几页都是「懂」的层面，这一页是「做过」的层面。面试官的区分度恰恰在这里：

  • 只读过博客的人会说「注意力就是 Q 乘 K 转置」。
  • 真的写过的人会说出那些只有踩过才知道的细节：reshape 与 transpose 的先后顺序、"为什么必须 contiguous()"、"初始化不对时第一轮 loss 是多少"、"因果性检查怎么做"。

这一页覆盖的三个编号（L1-03 手写 Tokenizer、L1-19 手写 Transformer、L1-18 手写 LLaMA2）在面试中的形态通常是：「你说你实现了 Transformer，讲一下实现过程中最难的地方」。这题没有标准答案，考的是你有没有真实的调试经验。答「最难的是理解概念」是零分的；答得出「多头的维度变换顺序和 contiguous 的性能陷阱」才是有效的。

同时要建立的边界感：教学规模复现的正确表述是「我实现了一个与 LLaMA 架构对齐的模型」「我在小规模数据上验证了实现正确性」，绝不能说「我训了一个 LLaMA2」。这条边界要主动说，说了是加分，被追问出来是致命。

核心内容 ​

L1-03 手写一个 BPE Tokenizer ​

接口设计（先定接口，再写实现） ​

一个最小可用的 Tokenizer 需要：

方法职责
train(corpus, vocab_size)从语料统计词频、学出 merge 规则、产出词表
encode(text) -> list[int]文本转 id 序列
decode(ids) -> strid 序列转回文本
save / load持久化词表与 merge 规则（顺序必须保留）
特殊 token 管理注册 bos / eos / pad，并保证原子化（不参与 merge、不被切分）

一个必须做的取舍：字节级 vs 字符级 ​

方案初始符号集中文可逆性
字符级语料中出现过的字符（中文有数千个常用字，集合大）覆盖较全取决于 <unk> 策略：出现词表外字符即不可逆
字节级UTF-8 字节的 256 个取值，天然闭集一个字 = 3 个字节，初始序列更长，但 merge 会把它合起来天然可逆，因为任何文本都能表示为字节

结论：教学实现直接选字节级。 它带来两个决定性好处：① 不需要 <unk>，任何输入都能编码；② decode(encode(text)) == text 是硬保证，可以写成断言。代价是初始序列比字符级长（中文 ×3），训练时 merge 次数要相应多一些。

这个取舍本身就是一道面试题：「你的 Tokenizer 遇到没见过的字怎么办？」字节级的答案是「不存在没见过——字节是闭集」，字符级的答案是「需要 <unk> 或 fallback」。

训练循环（三步，每轮一次合并） ​

  1. 统计相邻符号对的频次：遍历所有词，把当前符号序列里每一对相邻符号记一次数。用 token 对数（pair）字典。
  2. 取最高频的对，合并成新符号，记下这条规则（追加到有序规则列表）。
  3. 重复直到词表达到目标大小。

关键实现细节：

  • 初始符号序列要带词尾标记（例如 </w>）：这样模型能区分「词中间的 est」与「词尾的 est」，否则 lowest 与 lower 的共享部分会被错误地当成同一模式。
  • merge 规则的顺序就是全部信息：编码时按学到的顺序依次尝试应用，不能用「当前文本里频次最高」重新决策。这是新手最常写错的 bug —— 训练和推理用了两套不同的合并逻辑，结果编码结果与训练时不一致。「编码只依赖 merge 的顺序」这句话要能脱口而出。
  • 词级预分词：先在空格/标点处切词，再对每个词内部做 BPE。这一步决定了跨词合并永远不会发生（the cat 不会合成 thecat 的一部分），也让中文需要额外处理（中文没有空格，需要按字符或按字节切）。

验证方式（不靠肉眼看输出） ​

三个可自动断言的性质：

  1. 可逆性：对语料里随机抽的一批样本，断言 decode(encode(t)) == t。这是最容易写、也最容易发现真 bug 的测试。
  2. 压缩率：总字节数 / token 数。字节级 BPE 在中文语料上通常把字面字符数显著压缩；把压缩率与「用现成 tokenizer 得到的 token 数」对比，是很有说服力的实测数据（单位写成「每 token 覆盖多少字符」，并说明语料来源）。
  3. 词表覆盖：断言 len(vocab) == 256 + 特殊 token 数 + merge 次数，能立刻发现词表管理的 off-by-one。

L1-19 手写 TinyTransformer ​

组件拆分与实现顺序 ​

按依赖顺序写，每写完一个立刻做形状测试，不要等全部写完再一次性调试：

顺序组件形状（约定 B batch、S 序列长、d 模型维度、H 头数、V 词表）
1Embedding[B, S] → [B, S, d]
2位置编码（先做可学习或 Sinusoidal，RoPE 留到 LLaMA 版）[B, S, d] → [B, S, d]
3单头注意力[B, S, d] → [B, S, d]
4多头注意力（拆分/拼接）内部经过 [B, H, S, d_head]，其中 d_head = d / H
5FFN[B, S, d] → [B, S, d]（中间升维到 d_ff）
6残差 + Norm形状不变，注意 Pre-LN 的位置
7堆叠成 Block，再堆 N 层形状不变
8末尾的 final norm形状不变。最容易漏，漏了 loss 会明显偏高
9LM Head 投影到词表[B, S, d] → [B, S, V]
10损失[B, S, V] 与 [B, S] 标签算交叉熵（含标签右移）

两个高频坑：

  • 标签右移：输入是 x[t]，预测目标是 x[t+1]。整条序列一次前向即可同时得到所有位置的预测（这就是 teacher forcing 与因果掩码配合的效率来源），但标签必须错开一位。写错会表现为「loss 下降得异常快然后卡在很低的值」——因为模型在学着复制输入。
  • reshape / transpose 的顺序与 contiguous()：从 [B, S, d] 拆多头，正确顺序是先 reshape 成 [B, S, H, d_head]，再 transpose 成 [B, H, S, d_head]；如果先 reshape 成 [B, H, S, d_head] 就直接错了（因为它把「序列位置」当成第二维，切分的是错误的内存顺序）。transpose 后张量不再连续，注意力里做 matmul 通常在框架内部能处理，但如果你要做 view / reshape（比如合并回多头）就必须先 .contiguous()；否则报错或静默得到错误结果。「先 reshape 到带 H 的四维、再 transpose，合并回来时先 contiguous」 —— 这句话是这一页最有区分度的一句。

形状检查表（调试时的第一手段） ​

调试任何形状报错，第一步永远是打印形状。 把下面这张表背下来，报错时能立刻定位到哪一层：

张量形状
输入 id[B, S]
embedding 输出[B, S, d]
Q / K / V（拆头前）各 [B, S, d]
Q / K / V（拆头后）各 [B, H, S, d_head]
注意力分数 [B, H, S, S]
加权后的输出（合头前）[B, H, S, d_head]
合头后[B, S, d]
FFN 中间层[B, S, d_ff]
logits[B, S, V]

注意 [B, H, S, S] 这一项：注意力分数矩阵是 的，它的显存（或峰值显存）随序列长度平方增长 —— 这是长上下文代价的直接来源，也是第 11、12 页要展开的那条线索。（FlashAttention 的做法正是不物化这个矩阵，见注意力那页。）

参数量与显存估算 ​

参数量（单层、忽略 bias）：

组件参数量
注意力四个投影
FFN 两个矩阵（SwiGLU 是三个矩阵、 更小）
两层 Norm各 或 ，可忽略

总参数量 （含 embedding 与输出层；若权重绑定则只算一次）。用这个公式先手算一遍你自己的配置，再打印 sum(p.numel() for p in model.parameters()) 核对 —— 两者对不上说明你漏了某个张量（最常见的是漏了 final norm 或位置编码的参数）。这一步是「参数量估算」这道面试题最硬的答案：你能算，也能验证。

激活显存：与 B × S × d × L 成正比，并且随着 S 平方项出现在注意力分数里。这就是为什么长序列训练必须用梯度检查点（gradient checkpointing，用重算换显存）。

正确性验证四步（按顺序做，每步都有明确的判据） ​

第一步：过拟合单个 batch（在跑大规模训练之前必须通过）。 取一个 batch 反复训练几百步，模型应该能把它几乎完美地背下来 —— loss 降到很低，生成时能复现训练样本。 判据：这一步不过，说明实现有 bug（梯度断了、掩码错了、标签没右移）—— 而不是「数据不够」。这是最有价值的一条调试纪律：先用一个 batch 证明实现正确，再谈训练。

第二步：因果性检查（因果掩码是否真的生效）。 把输入序列的第一个 token 换掉，检查位置 1 及之后的输出 logits 是否完全不变（在数值精度范围内）。 判据：如果变了，说明掩码没盖住或盖错了方向。这是一个能自动化断言的检查，强烈建议写进测试。 注意方向：要保证「位置 只能看到 」，把未来位置盖成极小值（加一个很大的负数再 softmax），而不是把 score 矩阵的上三角置零 —— 置零在 softmax 后并不等于「不参与」，必须是「加负无穷 / 极大负数」这种加法掩码。

第三步：与参考实现逐张量对齐。 把你的单层与 torch.nn.MultiheadAttention 或 torch.nn.TransformerEncoderLayer 做数值对齐：复制同一份权重过去（注意 QKV 的打包方式与维度约定可能不同，需要重排），同样的输入，比较输出张量的最大绝对误差。 判据：误差应该接近浮点精度量级。这一步能一次性排查掉「形状对但语义错」的 bug —— 这类 bug 最阴险，因为程序不报错、loss 也在下降，只是效果永远比预期差。

第四步：让模型生成，看它怎么错。 在小数据（比如只有几十条重复文本）上训练到收敛，然后生成。 判据与解读：

  • 能复现训练数据的结构（重复的短语、正确的标点位置）→ 实现基本正确。
  • 输出全是同一个 token 反复 → 可能训练不足，也可能是采样策略太贪心（greedy 在小模型上极易退化）。
  • 输出完全随机 → 学习率、初始化或标签有严重问题。
  • 输出比训练数据「更整齐」但语义错乱 → 这是教学规模的正常表现，不是 bug。要能区分「实现有 bug」与「规模不够」 —— 这个判断力本身是考点。

L1-18 手写实现 LLaMA2（把 TinyTransformer 改成现代架构） ​

LLaMA 架构相对原始 Transformer 的改动清单（每一条都能对应前面某一页的动机）：

改动对应动机（前面哪页）实现要点
Pre-Norm + RMSNormLayerNorm 那页：Pre-LN 的恒等路径更干净、RMSNorm 省掉均值与偏置每个子层先归一化再进子层；归一化只按均方根缩放，无可学习偏置
RoPE位置编码那页：相对位置 + 外推性只对 Q、K 旋转，V 不动；按相邻维度成对旋转；在每个头的 d_head 内部做（不是在整个 d 上）
去掉所有 bias参数与数值稳定性所有 nn.Linear(bias=False)（通常保留了 norm 的可学习缩放）
SwiGLU FFNFFN 那页：门控带来的表达力三个矩阵（gate / up / down）；d_ff 不再是 ，而是约 再对齐到某个倍数（常见是把隐藏维度取整到 256 的倍数）
GQAKV Cache 那页：KV 头数少于 Q 头数n_kv_heads < n_heads，KV 需**重复（repeat）**到与 Q 头数一致才能算注意力；n_kv_heads == n_heads 时退化为 MHA
权重共享（可选）参数量embedding 与 LM Head 共享权重。注意：LLaMA 系列并不共享，是否共享要以具体模型卡为准

配置驱动 + 权重加载 ​

配置驱动：把所有超参（层数、d、头数、KV 头数、d_ff、词表大小、rope_theta、最大长度）放进一个配置对象或 dataclass，模型只从配置构建。这样同一个实现能按不同规模实例化，也便于和官方配置对齐。

加载官方权重时的两个关键动作：

  1. 键名映射：官方的命名（例如 model.layers.N.self_attn.q_proj.weight）与你的命名大概率不同 —— 写一个显式的映射表，而不是靠字符串替换猜。
  2. 核对缺失与多余键：加载后用不严格模式拿到 missing_keys 与 unexpected_keys，断言两者都为空。这一步是「我确实加载成功了」的唯一证据。 一个具体细节：如果配置里头的划分与权重文件不一致（比如 KV 头数写错），QKV 的形状会对不上，此时 load_state_dict 会直接报形状错误 —— 这反而是好事，它说明架构参数必须与权重严格对应。

一条必须主动说的诚实边界 ​

「我实现了一个与 LLaMA 架构对齐的模型，加载官方权重后能跑通前向并生成合理文本，但训练是教学规模的。」

  • 不能说：「我训了一个 LLaMA2。」你没做过预训练，说这话会在「你用了多少 token、多大规模集群」的追问下立刻崩掉。
  • 可以说：架构对齐、权重加载验证、单 batch 过拟合、因果性检查、与参考实现数值对齐 —— 这些都是可验证的真事实，而且含金量比「我训过」这句话更高。
  • 加分表述：「我的价值不在于训出模型，而在于我能逐层解释它的每个设计选择 —— 比如为什么 RMSNorm 去掉了均值、为什么 GQA 只改 KV 头数、为什么 RoPE 只旋转 Q 和 K。」

和你自己的项目对上号 ​

① 你项目二那句必须拒答的问题，答案就写在这一层的前后两页里。 「Transformer 的 KV Cache 显存怎么估算」—— 一个诚实且有说服力的答法是：

「这个公式不在我的语料库里，所以我的系统应该拒答。但如果让我回答：KV Cache 的显存与层数、KV 头数、每头维度、序列长度、精度成正比，量级上约 —— 前一个 2 是 K 和 V 各一份。它与 batch 也成正比，而不随参数量平方增长。这也是为什么 GQA 用减少 KV 头数来省显存，以及为什么长上下文推理的显存瓶颈往往落在 KV Cache 而不是权重上。」

这段话的妙处在于：它同时展示了「我的拒答是准确的」和「我其实知道」。 完整的公式推导与 MHA / MQA / GQA 的显存对比在下一页。

② 你的手写实现可以直接给项目二做一件真实有用的事：实测 token 效率。 项目二的成本报告是基于 token 计费的。你可以用自己的字节级 BPE 与现成 tokenizer 对比同一批论文摘要的 token 数 —— 这能回答一个很实际的问题：「如果我自建 tokenizer，能不能降低 token 成本？」 实测结论通常是：通用 tokenizer 在专业领域（RL / USV / 控制）的术语上切得更碎，自建词表能压缩，但换 tokenizer 意味着要重训模型，所以这个收益只对「自训小模型」这条路有意义。这个「测得出收益但用不上」的结论本身就是一条合格的工程判断 —— 它能解释你为什么最终没这么做。

③ 因果性检查与你的回归门禁是同一种思维。 你的门禁用配对检验判断「这次改动是不是真的变好了」；这里的因果性检查用「换掉第一个 token，后面的 logits 必须不变」判断「掩码是不是真的生效了」。两者都是把一个模糊的担忧变成一条可自动执行的断言。 面试里可以把这个类比说出来 —— 它证明你的工程纪律是跨任务迁移的，不是针对某个项目临时学的。

④ 形状检查表对应你项目里的「可观测性」意识。 你项目一做了自研 JSONL trace + Langfuse 双后端降级 —— 那是运行时的形状检查（每一步的输入输出结构是否如预期）。训练代码里的形状检查是同一个习惯在另一个域的表现：在出错的地方立刻留下可读的证据，而不是等到最终结果不对再回溯。

可执行的小实验（三个，按投入从低到高，每一个都有实物产出）：

实验 A（1–2 天）：字节级 BPE + 可逆性测试。 只用标准库实现 train / encode / decode，加一个随机样本的可逆性断言。产出：一份可跑的代码 + 在项目二论文语料上的「每 token 覆盖字符数」实测值。

实验 B（3–5 天）：TinyTransformer + 四步验证。 在一个人造小语料上（例如几十条固定格式的多轮对话模板）训练到单 batch 过拟合，写出因果性检查的断言，并与 torch.nn 参考实现做数值对齐。产出：一份能通过全部四步验证的实现 + 一段「形状检查表」笔记。这段笔记在面试里可以直接口述。

实验 C（1–2 周）：改造成 LLaMA 架构并加载官方权重。 实现 RMSNorm / RoPE / SwiGLU / GQA，把官方权重加载进来（断言缺失键与多余键为空），做一次前向并生成一段文本。产出：「架构对齐 + 权重加载成功」这句可验证的表述，以及一份「LLaMA 相对原始 Transformer 的六处改动及其动机」的对照表 —— 这张表就是面试时的答案纸。

面试怎么问 ​

Q1：你实现 Transformer 时最难的地方是什么？

A（要点）：给出具体的工程细节，而不是概念困难。三个最有说服力的答案：① 多头的维度变换顺序 —— 必须先 reshape 成 [B, S, H, d_head] 再 transpose 成 [B, H, S, d_head]，反过来虽然形状碰巧对但语义已错；② transpose 后张量不连续，合并回多头时必须先 .contiguous()，否则报错或静默算错；③ 因果掩码必须用加法（加极大负数）而不是把上三角置零 —— 置零在 softmax 后并不等于不参与。

加分句：「我养成的习惯是先用单个 batch 过拟合验证实现正确，再去跑训练。这一步不过就说明有 bug，而不是数据不够 —— 这能避免我在一个错误实现上浪费几天算力。」

别说：「最难的是理解注意力机制。」这会把问题从「做过」退回到「读过」。

Q2：你怎么知道你的实现是对的？

A（要点）：四步验证。① 单 batch 过拟合 —— 必须能背下来；② 因果性检查 —— 换掉第一个 token，位置 1 及之后的 logits 必须完全不变；③ 与参考实现逐张量对齐 —— 复制同一份权重进 torch.nn 的实现，比较输出的最大绝对误差；④ 看生成的样子 —— 能复现训练数据的结构就基本正确。

加分句：「第②步我写成了自动断言。它的价值在于能把『掩码到底有没有生效』这个模糊的担心变成一条每次改动都会执行的检查 —— 和我在项目里做回归门禁的思路是一样的。」

别说：「loss 下降了就说明对。」loss 下降在掩码错误时也会发生（比如模型在复制输入）。

Q3：你的 Tokenizer 是怎么做的？为什么不用现成的？

A（要点）：自己实现是为了理解 BPE 的训练循环与那个关键性质 —— 编码只依赖 merge 的顺序。我用字节级而不是字符级，因为 UTF-8 字节是天然闭集，不需要 <unk>，并且 decode(encode(t)) == t 是硬保证，可以直接写断言。代价是中文初始序列长 3 倍。

实现上的两个必须讲清的点：① 初始符号带词尾标记，用来区分词中与词尾的同一子串；② 训练与编码必须用同一套按顺序应用的 merge 规则 —— 如果编码时按「当前文本里频次最高」重新决策，训练和推理就用了两套逻辑，这是最容易写出的 bug。

加分句：「我实测了压缩率（每 token 覆盖多少字符），和现成 tokenizer 做了对比。结论是通用 tokenizer 在专业术语上切得更碎，自建词表能压缩，但换 tokenizer 意味着要重训模型，所以这个收益只对自训小模型有意义 —— 这解释了我在项目里为什么没有这么做。」

别说：「现成的不好用。」要给出可实测的判据。

Q4：LLaMA 相对原始 Transformer 有哪些改动？

A（要点）：五到六处。① Pre-Norm + RMSNorm（恒等路径更干净，归一化省掉均值与偏置）；② RoPE（相对位置 + 外推性，只旋转 Q 和 K、在每个头的 d_head 内成对旋转）；③ 去掉 bias；④ SwiGLU FFN（三矩阵门控，隐藏维度从 降到约 ）；⑤ GQA（KV 头数少于 Q 头数，需 repeat 对齐，省 KV Cache 显存）；⑥ 是否共享 embedding 与 LM Head 权重要以具体模型卡为准（LLaMA 系列并不共享）。

加分句：「这六处改动都能对应回原理：Pre-Norm 和 RMSNorm 对应归一化位置的取舍，RoPE 对应位置编码的外推性，GQA 对应 KV Cache 的显存代价。我不是照抄配置，而是知道每一个配置在解决什么问题。」

别说：「LLaMA 就是 Transformer 的改进版。」这种说法等于没答。

Q5：你训过 LLaMA 吗？

A（要点）：必须诚实，而且要主动划边界。「我实现的是与 LLaMA 架构对齐的模型：架构全部自己写，加载官方权重后前向能跑通并生成合理文本，通过了单 batch 过拟合、因果性检查、与参考实现的数值对齐。但训练是教学规模的 —— 我没有做预训练，也没有大规模数据或集群。」

加分句：「我认为这个工作的价值不在于训出模型，而在于能逐层解释每个设计选择，以及能在加载官方权重时通过键名映射与缺失键断言证明架构参数确实对齐了。这两点是可以验证的。」

别说：「我训了一个 LLaMA2 的复现版。」—— 一旦被追问 token 量、集群规模、训练时长就会崩，而且这是编造规模，属于红线。
