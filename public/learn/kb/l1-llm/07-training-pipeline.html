训练三阶段总览：Pre-train / SFT / RLHF ​

覆盖知识点：L1-14 ｜ 面试频率：高 ｜ 建议学时：3h

一句话说清 ​

一个能用的对话助手要经过三段训练：预训练（海量无标注文本 + 下一 token 预测）让模型拥有知识与语言能力，但产物只是一个「文本续写器」；监督微调 SFT（指令-回答配对数据）教它按指令与格式作答；RLHF（人类偏好排序 + 强化学习或直接偏好优化）进一步让输出更符合人类偏好（有用、诚实、无害，以及风格与安全约束）。三阶段的分工是：预训练决定能力上限，SFT 决定会不会听话，RLHF 决定听得多好。 后训练不能凭空造出预训练里没有的能力。

为什么必须学 ​

这是 L1 里少见的「一张图解释一整个行业流水线」的知识点，面试中几乎必被问到，而且是串联型问题：面试官会用这一页当骨架，再往任何一个阶段深挖（SFT 的数据怎么造？RLHF 的奖励模型怎么训？DPO 和 PPO 有什么差别？），挖到哪一层取决于你能不能先把骨架搭对。

三个最常见的失分点：

  1. 把 SFT 说成「教模型知识」 —— 知识主要来自预训练，SFT 教的是行为与格式。
  2. 说不清 RLHF 为什么需要奖励模型 —— 人类偏好是排序不是分数，需要先学一个可微的代理。
  3. 把三阶段的顺序说反或合并 —— 比如以为 RLHF 之前不需要 SFT。

另外，这一页直接连着你项目的现实决策：你两个项目都没有做任何训练，全靠 prompt + 检索。面试官一定会问「你为什么不微调」，答案的框架就在这一页。

核心内容 ​

阶段一：预训练（Pre-training） ​

项内容
数据海量无标注文本（网页、书籍、代码、论文……），万亿 token 量级
目标下一 token 预测
产出基座模型（base model）
成本三阶段中最高的，需要大规模集群与并行训练
决定能力上限：知识广度、语言能力、推理基础

基座模型的行为特征（必须说清，否则后面两阶段没有动机）：

  • 它做的是文本续写，不是回答问题。你输入「中国的首都是哪里？」，它可能补全成「中国的首都是哪里？这是一个常见的地理问题……」—— 因为它见过很多「问题 + 更多问题」的文本，续写这个模式是合理的。
  • 它不区分角色。system / user / assistant 这些边界对它是普通文本。
  • 它的输出格式不可控：你想要的 JSON，它可能给你一段解释再给 JSON，也可能给你 Markdown 代码块。

结论：基座模型不能直接做产品。这不是「效果差一点」的问题，而是接口不匹配。

阶段二：监督微调（SFT） ​

项内容
数据指令 - 回答配对（instruction / response），质量远比数量重要
目标仍是下一 token 预测，但只在回答部分计算损失（prompt 部分通常 mask 掉）
产出指令模型（instruct model），可用且可控
成本远低于预训练，可在单机多卡上完成
决定会不会听话：指令跟随、输出格式、角色边界

为什么 SFT 这么少的数据就有效？ 因为它的作用不是「注入新知识」，而是模型已经具备的能力的激活与格式化。预训练阶段模型已经见过千千万万的问答、指令、对话模式（都在语料里），SFT 只是用一个干净的、格式统一的分布告诉它：「以后遇到这种格式，你要这样回应。」

这一步是「分布对齐」，不是「知识注入」 —— 这句话是这一页最重要的一句，也是判别「懂不懂 SFT」的关键。

SFT 的实践要点（提前建立，第 8 页展开）：

  • 数据质量 > 数据量：少量高质量、格式一致的样本通常优于大量噪声样本。
  • 格式一致性：chat template 的边界 token 必须与训练时一致，否则模型认不出角色边界。
  • 灾难性遗忘：SFT 数据分布太窄会削弱基座模型的其他能力；混入一部分预训练数据或通用指令数据可以缓解。
  • 只对回答算损失：如果对 prompt 也算损失，模型会学着去「生成用户的提问」，这会明显损害对话质量。这是一个很实用的细节。

阶段三：RLHF（基于人类反馈的强化学习） ​

问题：SFT 能教会「按格式回答」，但教不会「哪个回答更好」。因为「更好」是一个比较判断，难以用「标准答案」的形式写出来。你可以轻易判断回答 A 比 B 好，但很难为每个问题写出唯一正确的答案。

做法（三步）：

第一步：收集偏好数据。 让模型对同一个 prompt 生成多个回答，让人类标注员排序（哪个更好）。产出是「A 优于 B」这样的比较数据，不是分数。

第二步：训练奖励模型（Reward Model, RM）。 它要学一个函数 ，给「prompt + 回答」打一个标量分。训练目标是让被偏好的回答得分更高。常用的损失是 Bradley-Terry 风格的对数似然：

为什么必须有 RM？ 因为人类反馈是排序（不可微、离散），而强化学习需要一个逐步可微的奖励信号。RM 就是这个「人类偏好的可微代理」。这是这一节的核心逻辑，答不上来就等于没懂 RLHF。

  • 惩罚项：约束新策略不能偏离参考模型（通常是 SFT 模型）太远。为什么必须加：RM 只是一个学出来的近似，它一定有偏差。如果无限制地优化 RM，策略会找到那些「RM 打分高但其实很差」的输出 —— 这就是奖励黑客（reward hacking）。KL 惩罚把策略拴在参考模型附近，防止它跑出 RM 的置信区间。「RM 有偏差，所以必须加约束」这个因果链是面试得分点。

RLHF 的代价（诚实地说）：

  • 流程复杂：四个模型同时在显存里（策略、参考、奖励、以及 PPO 里的价值模型），工程门槛高。
  • 不稳定：RL 训练本身对超参敏感，奖励曲线容易震荡。
  • 成本高：偏好标注贵，训练也比 SFT 贵。
  • 奖励黑客：即使有 KL 约束，优化久了仍会出现「讨好 RM 而非真正有用」的输出（例如变得过度冗长、过度恭维、过度免责声明）。

这就是 DPO 的动机：能不能跳过显式奖励模型与 RL 循环，直接用偏好数据优化策略？DPO 的答案是「可以」——它把「先学 RM 再用 RL 优化」这一步解析地等价成了一个直接在偏好对上做的分类式损失。它不需要 RM、不需要采样、不需要 PPO 的那套循环。代价是它失去了在线采样与 RM 复用带来的灵活性。（DPO 的完整推导与取舍是第 10 页的内容。）

三阶段的分工与常见误解 ​

预训练SFTRLHF
数据形态无标注文本指令-回答配对人类偏好排序
优化目标下一 token 预测下一 token 预测（只在回答上）奖励最大化 + KL 约束
决定什么能力上限（知识/推理基础）行为方式（听话、格式、角色）偏好匹配（有用/诚实/无害的排序）
相对成本最高中低中高（标注 + 训练复杂度）
能否注入新知识主要靠这里少量（且容易过拟合）不能

六个高频误解（每一个都值得单独记）：

  1. 「SFT 是给模型灌知识」 —— 错。知识主体在预训练，SFT 是把已有能力对齐到指令格式。
  2. 「RLHF 可以纠正事实错误」 —— 错。RLHF 优化的是偏好，不是事实性；它甚至可能鼓励更「自信」的表述。事实性主要靠 RAG、工具调用、以及预训练数据质量。
  3. 「三阶段可以跳过中间直接 RLHF」 —— 通常不行。RLHF 的参考模型与初始策略都来自 SFT 模型，没有 SFT 阶段策略的初始分布太差，RL 很难收敛。
  4. 「SFT 数据越多越好」 —— 不一定。数据质量与格式一致性往往比数量更关键，低质数据会教坏格式。
  5. 「RLHF 之后模型更聪明了」 —— 不准确。它更多是同一能力的更好表达；能力上限在前一阶段已定。
  6. 「预训练不需要，直接 SFT 就行」 —— 完全错。没有预训练的基座，SFT 只有几十万条数据，不可能获得通用能力。

这条流水线在你项目的语境下意味着什么 ​

你没有做过任何训练阶段 —— 两个项目都是「调用已经完成三阶段训练的开源 / API 模型」。这不需要辩解，但必须说清楚你的位置：

  • 你是消费侧：在模型已完成三阶段训练的基础上，用 prompt、检索、编排、工具调用来解决业务问题。
  • 你也有一部分的「后训练替代品」：few-shot 示例在做上下文内的分布对齐（本质上是 SFT 的作用，只是发生在上下文里而不是权重里）；你的回归门禁在做的，是把「改 prompt」当成一次「微型的后训练迭代」来管理。
  • 当有人问「你为什么不微调」，你的答案有三个层次：① 你的任务瓶颈在检索质量与编排逻辑，不在模型的行为方式（用评测数据支撑这一步）；② 微调需要数据，而你项目一的语料是合成的、项目二的评测集是本人标注的小规模集，都不足以支撑一次可靠的 SFT；③ 微调会牺牲可替换性 —— 走 OpenAI 兼容协议意味着模型可插拔，一旦微调就被绑定到某个权重版本上。

和你自己的项目对上号 ​

① 你的「不微调」是决策，不是能力不足。 面试官看到一份应届生简历上全是 API 调用 + 检索 + 编排，会问「你懂训练吗」。你的答法不是辩解，而是说清这个决策的依据：

  • 瓶颈定位：你项目二的评测是分层的。如果 badcase 分析显示错误集中在「检索没召回正确片段」，那么微调生成模型对这个错误无效 —— 因为信息根本没进上下文。这是「先定位瓶颈再选手段」的工程素养，也是你 36 个消融脚本真正在证明的事。
  • 数据条件：项目一是合成语料、项目二是本人标注的小规模评测集。SFT 需要的「指令-回答配对」数据质量要求极高，用合成数据做 SFT 很容易学到噪声，反而损害效果。
  • 可替换性：你走 OpenAI 兼容协议，模型是可插拔的。微调会把这个可替换性换成一个绑定到某个权重版本的资产。

这三条按顺序说，是一个完整的工程论证。 注意第一条是核心 —— 前两条只是补充条件。

② 你的回归门禁本质上是「微型的后训练迭代流程」。 SFT 的迭代是「改数据 → 重训 → 评测 → 决定是否上线」；你的迭代是「改 prompt / 改切块 / 改检索参数 → 重跑 → 配对检验 → 三态退出码」。结构完全对应，只是你改的是上下文而不是权重。这个类比说出来，能让人看到你理解后训练的流程本质（而不是只会背三个名词）。

③ SFT 的「只在回答上算损失」对应你的 prompt 设计。 SFT 不对 prompt 算损失，是为了避免模型学会「生成用户的提问」。你的 prompt 模板设计里有同样的原则：system 指令与 few-shot 示例是「条件」，不是「要模型生成的内容」。所以你在做输出解析（JSON 解析、工具调用解析）时，稳定的做法是让模型只输出结构化的结果，把角色边界交给特殊 token 和模板管理。

④ 上下文预算在三阶段视角下是一个固定约束。 你的 few-shot 示例、检索片段、会话历史都在抢同一份 token 预算。few-shot 示例是「上下文内的 SFT」，检索片段是「上下文内的知识注入」—— 在预算有限时，你需要按任务决定把预算分给哪一侧。这正是「少样本 vs 微调」这个经典取舍在你项目里的具体形态，且你的取舍落点在「检索优先」（因为关键错误是没召回）。

可执行的小实验（量化 few-shot 的『伪 SFT』效果）：在你项目二的答案生成环节，对同一批问题做四组配置：

  1. 零样本 + 检索（当前基线）；
  2. few-shot 2 个示例 + 检索；
  3. few-shot 2 个示例，但示例格式不一致（字段顺序或分隔符漂移）；
  4. 不检索 + few-shot（看缺知识时 few-shot 能不能救）。

用你的分层评测集分别跑，记录答案准确率与引用正确率两个指标，做配对比较。判据 —— 如果 2 优于 1：说明「上下文内的 SFT」对格式与风格有实际收益；如果 3 显著差于 2：说明格式一致性比示例数量重要；如果 4 明显差于 1：说明few-shot 替代不了检索，它管的是行为不是知识。最后一组的结果尤其有价值，它是你「不微调、先保证检索」这个决策的直接证据。

面试怎么问 ​

Q1：说一下大模型训练的完整流程。

A（要点）：三阶段。预训练 → 基座模型（文本续写器，有知识但不听指令）；SFT → 指令模型（学会按指令与格式回答）；偏好优化（RLHF 或 DPO）→ 对话助手（输出更符合人类偏好）。贯穿的一句话分工：预训练决定能力上限，SFT 决定会不会听话，偏好优化决定听得多好。

加分句：「后训练不能凭空造出预训练里没有的能力 —— 所以任何指望用 SFT『教模型一个新知识』的做法，本质上都是低效的，知识应该靠检索注入或回到预训练数据配比里解决。」

别说：「先预训练，然后强化学习，最后微调。」顺序说错是最直接的扣分。

Q2：SFT 和预训练的目标函数一样吗？

A（要点）：形式上相同，都是下一 token 预测的交叉熵。区别在数据形态（无标注文本 vs 指令-回答配对）、损失计算范围（全序列 vs 通常只在回答部分）、数据规模（万亿 token vs 万到十万量级）、以及目的（获取能力 vs 对齐格式与行为）。

加分句：「目标函数相同这一点很重要，它说明 SFT 不是一种新算法，而是一次分布切换。模型的能力没有新增，只是被引导到『按指令作答』这个分布上。这也是为什么少量高质量数据就能显著改变行为。」

别说：「SFT 用的是分类损失。」那是把 SFT 和奖励模型的训练搞混了。

Q3：RLHF 为什么需要一个奖励模型？

A（要点）：两个原因。① 人类反馈是离散排序，不可微（「A 优于 B」没有梯度），而强化学习需要一个可微的标量奖励信号 —— 奖励模型就是这个代理；② 训练奖励模型时可以直接在比较对上做，损失是「偏好回答与被拒回答的分数差」的对数 sigmoid，不需要标注绝对分数。

加分句：「奖励模型一定是有偏的近似，所以必须在目标里加 KL 惩罚项，把策略拴在参考模型附近 —— 否则策略会找到『奖励模型打分高但实际很差』的输出，也就是奖励黑客。这个 KL 项不是正则化技巧，而是对抗奖励模型偏差的必要装置。」

别说：「因为人类不能给每个回答打分所以训一个模型。」要说出「不可微 → 需要代理」和「排序 vs 分数」这两个具体点。

Q4：RLHF 有什么问题？DPO 为什么出现？

A（要点）：RLHF 的问题是工程复杂度高（策略、参考、奖励、价值四套模型同时在显存里）、训练不稳定（RL 对超参敏感）、偏好标注成本高、以及仍有奖励黑客风险（讨好奖励模型的表现如过度冗长或过度免责）。DPO 的动机是跳过显式奖励模型与 RL 循环，把「先学 RM 再 RL 优化」解析地等价成直接在偏好对上的分类式损失，训练更简单稳定；代价是失去在线采样与奖励模型复用带来的灵活性。

加分句：「这是一个典型的『把两步数学等价合并，换掉一整条工程链路』的优化 —— 我在项目里做 RRF 融合与显式降级也是同样的思路：能用更少的活动部件达到目标，就少一个会坏的地方。」

别说：「DPO 就是更好的 RLHF。」两者有不同的适用面，说成「更好」会被追问「那在什么情况下不好」。

Q5：为什么增量知识不靠微调，而靠 RAG？

A（要点）：微调（尤其是 SFT 或 LoRA）改变的是行为方式与格式，把新事实稳定写进权重需要足够的重复与合适的数据构造，而且容易遗忘、难以更新、难以审计。RAG 把知识放在外部可更新的索引里，改一条文档立即生效，并且能给出引用溯源。两者的分工是：行为靠训练，事实靠检索。

加分句：「我在项目二里还多做了一层：拒答机制。因为 RAG 的失败模式不只是『答错』，还有『检索不到却硬答』。事实性保障不能只靠注入，还要有『没找到就不答』的闸门 —— 这在三阶段训练的视角里属于训练解决不了的问题，必须在系统层做。」

别说：「因为微调太贵了。」成本是次要的，根本原因是分工不同（可更新性、可审计性、以及微调不擅长注入事实）。
