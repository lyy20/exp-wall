自注意力机制：QKV、缩放与多头注意力 ​

覆盖知识点：L1-04 L1-05 L1-06 ｜ 面试频率：高 ｜ 建议学时：12h

一句话说清 ​

注意力是「用查询去匹配一组键，再按匹配度加权求和对应的值」：。除以 是为了在维度升高时把点积的方差拉回常数，避免 softmax 进入饱和区导致梯度消失。自注意力让 Q/K/V 都来自同一个序列，cross-attention 让 Q 来自解码端、K/V 来自编码端。多头把 切成 份并行做注意力再拼回，让模型在不同子空间里同时关注不同的关系——代价是 份形状变换，收益是表达能力的显著提升，参数量不变。

为什么必须学 ​

这一页是整个 L1 层的几何中心。面试官在这里的问法有一个固定套路，叫「三层追问」：

  1. 第一层：公式是什么？ —— 90% 的人能背出来。
  2. 第二层：为什么要除以 ？ —— 能答「防止 softmax 梯度消失」的人不少，但能说出方差为什么是 的人不到一半。
  3. 第三层：那为什么不用 或 ？多头里的 变了，缩放因子跟着变吗？ —— 到这里能答的人很少。

这一页必须把三层都写清。另外，手写 Transformer 的第一道坎就是这里的形状变换：[B, S, d_model] → [B, H, S, d_head] 那三行 view / transpose 写错一个维度，代码能跑通但结果全错，而且不报错。写完形状检查表，面试时能当场画出来。

核心内容 ​

L1-04 注意力的动机：从「固定压缩」到「按需取用」 ​

在注意力出现之前，序列到序列的模型是「编码器把整句压成一个定长向量，解码器从这个向量里恢复全部信息」。这是一个信息瓶颈：句子越长，压进定长向量时丢的东西越多，解码端的表现随长度急剧下降。

注意力的思路变化是：不要压缩，保持全部位置的原样表示，让解码端在每一步自己决定该看哪里。

它由三个角色构成，都是同一个序列（或两个序列）的线性投影：

角色语义类比
Query（）我现在想找什么搜索引擎里的查询词
Key（）我能提供什么（被检索的索引）文档的标题/关键词
Value（）我实际提供的内容文档正文

为什么 Key 和 Value 要分开？ 因为「被匹配的依据」和「被取走的内容」是两个不同的功能。如果 ，那么一个位置的「可匹配性」与「它的内容向量」被强制绑定，模型无法表达「我的内容很有用，但我不是一个好的匹配目标」这类区分。分开之后， 和 各自学习。

因果掩码用加一个极大的负数实现，而不是直接乘 0。原因是：如果乘 0，softmax 之后那些位置的概率是 0，看似也对；但如果在 fp16 下用加法掩码， 量级的数经 softmax 后是精确的 0。用加法掩码是标准做法，因为 softmax 的输入本来就是「任意实数打分」，加法不会破坏它的数值结构，而乘法会引入「必须恰好为 0」的额外假设。实践中会用该 dtype 下足够小的有限值（如 fp16 的 -65504 或一个大的负数常量），而不是真的 -inf，避免 -inf - (-inf) = nan。

第四步：归一化

沿最后一维（键的方向）做 softmax，使每一行（每个查询对所有键的关注度）和为 1。

第五步：加权求和

为什么解码器的 cross-attention 不加因果掩码？ 因为它要看到完整的源序列——翻译时译第 3 个词需要看完整句英文，这才叫「对齐」。因果性只约束解码端自己不能偷看未来的输出词。

L1-06 多头注意力：split / reshape / transpose ​

动机：一次注意力计算只能产出一个「关注分布」。但一句里可能同时存在多种关系需要追踪（主谓一致、指代、位置邻接、句法依存）。单头必须把这些关系挤进同一个 softmax 分布里，互相竞争归一化的权重。

多头的做法：不增加总维度，而是把 切分成 份，每份独立做一次注意力，最后拼回去再做一次输出投影。

完整形状变化链（这一段必须能默画）：

text
输入 X                       : [B, S, d_model]
  ↓ 三个线性投影（各自 d_model -> d_model）
Q, K, V                      : [B, S, d_model]
  ↓ view 成多头（d_model = H * d_head）
                             : [B, S, H, d_head]
  ↓ transpose 把 H 提到序列前面
                             : [B, H, S, d_head]
  ↓ 打分 Q @ K.transpose(-2, -1)

  ↓ 除以 sqrt(d_head) 并加因果掩码，再 softmax
注意力权重                    : [B, H, S, S]
  ↓ 加权求和 @ V
单头输出                      : [B, H, S, d_head]
  ↓ transpose 回来
                             : [B, S, H, d_head]
  ↓ contiguous + view 合并
拼接后的多头输出              : [B, S, d_model]
  ↓ 输出投影 W_O（d_model -> d_model）

为什么必须 transpose？ 因为矩阵乘法作用在最后两维（PyTorch 的 @ 按 batch 广播，对最后两维做矩阵乘）。要批量并行计算 个头的 注意力，头这一维必须排在序列维之前，即 [B, H, S, d_head]。如果停留在 [B, S, H, d_head]，算出来的是「每个位置内部把头与头做匹配」，完全错误。

为什么 view 前有时要 contiguous()？ transpose 返回的是视图（view），底层内存布局没有变，只是步长（stride）变了。而 view 要求内存连续，所以 transpose 之后直接 view 会报错，必须先 contiguous() 把内存真正重排。这是手写实现里最常见的报错。

参数量：三个投影 各是 ，输出投影 也是 ，合计

这个数字与 无关 —— 多头切分只是重新组织了计算，没有增加参数。「多头提升了表达能力却不增加参数」是这一节的总结句：它把「一个大注意力」换成「 个小注意力并行」，每个头的 更小，但不同头能学到不同的子空间模式。

常见误区：

  • 误区一：「头数越多越好」。 越大， 越小，单头的表达能力下降； 过大（例如 只有几维）会让每个头的注意力变得退化。头数是与 绑定的设计选择。
  • 误区二：「多头是串行加深」。是并行，各头之间在计算时没有交互，只在最后的 投影里融合。
  • 误区三：「 只是把维度拼回来」。 是可学习的融合矩阵，它同时承担「跨头信息混合」和「投影回残差流维度」两个职责。删掉它，各头的输出只是简单拼接，跨头交互就没了。
  • 误区四：把 [B, H, S, d_head] 说成 [B, S, H, d_head]。这个混淆在实际写代码时会直接导致注意力算错而不报错。

与 KV Cache 的接缝：多头注意力里 和 要缓存起来供后续步复用。 个头的 K 和 V 都要缓存，所以 KV Cache 的大小与头数（准确说是 KV 头数 ）成正比。这就是为什么后来出现了 MQA / GQA——减少 KV 头数可以在几乎不损失质量的前提下把 KV Cache 压到几分之一。细节见 KV Cache 那一页。

和你自己的项目对上号 ​

① 你的检索排序里藏着一个注意力式的打分。bge-reranker-v2-m3 是 cross-encoder：query 与 passage 拼成一个序列过编码器，让 query 的每个 token 去「注意」passage 的每个 token，最后聚合成一个相关性分数。这就是 cross-attention 的形态（Q 来自 query 侧，K/V 来自 passage 侧），只是它被封装在了模型内部。你能说出「cross-encoder 的内部就是 query 对 passage 的交叉注意力，所以它才能捕捉词级的对齐关系，而双塔只能比较两个已经压缩好的向量」——这句话能直接把「我调了个 reranker」升级成「我知道它为什么比双塔准」。

② 为什么双塔做不到词级对齐？ 双塔（bge-m3）把 query 和 passage 分别编码成定长向量，两侧在编码时完全没有交互，信息在各自的最后一层被池化压成一个点。cross-encoder 保留了 的完整交互矩阵。这就是「准但不快」的全部原因，也是你项目二两阶段检索的第一性原理：交互越充分越准，代价是不可预计算。

③ 因果掩码解释了你为什么能流式。 YYHelp 用 SSE 流式返回 Agent 的输出。流式之所以可能，正是因为 Decoder 用了因果掩码——第 步的输出只依赖前 步，所以生成完一个 token 就能立刻吐出去，不需要等整句生成完。如果是双向注意力，任何位置的输出都依赖整句，流式在数学上就不成立。这是一个很好的「原理 → 工程能力」映射。

④ 你的成本/延迟报告里最该关心的是那个 。 项目二有压测与延迟基准。注意力的 意味着：检索片段从 3 段加到 6 段，注意力成本大约翻 4 倍（如果拼接总长度翻倍）。你的切块档位消融（512 / 1024 / 2048）同时也是这个平方项的消融——把切块变大，单块信息更完整，但注入到 prompt 的总长度变长，注意力与 KV Cache 成本上升。这条权衡要能在面试里明确说出来，它证明你理解自己的消融在测什么。

⑤ 一个能立刻做的小实验（验证 的必要性）。 取一个开源的 Encoder 模型（如 bge-m3），在 forward hook 里抓一层的 attention 分数矩阵：

  1. 打印原始 的标准差与 （键长度）的关系；
  2. 对同一个分数矩阵分别用「除以 」「不除」「除以 」做 softmax，打印每行概率的最大值与熵。

判据很明确：不除时最大值趋近 1、熵趋近 0（饱和）；除以 时熵处于中间区间；除以 时分布过于平坦（趋近均匀）。这份实验记录是你回答「为什么是 」时唯一需要的实物证据，而且它是你自己跑出来的。

面试怎么问 ​

Q1：注意力公式是什么？为什么要除以 ？

A（要点）：完整链条是 加掩码 softmax 乘 。缩放的原因是方差控制：假设 各分量独立、均值 0 方差 1，则点积 的方差是 ，标准差是 。维度升高时分数的量级被放大，softmax 进入饱和区、梯度趋近 0，而且这个饱和在初始化时就发生（ 是随机的，与是否训练无关）。除以 后方差变为 1，尺度与维度解耦。

加分句：「这不是一个可调超参，而是从方差推导出的唯一能让尺度与 无关的常数。乘 0.1 之类的做法在高维下会失效，因为它没消掉维度依赖。」

别说：「为了防止数值太大溢出/为了数值稳定。」这是把方差问题说成了精度问题——数值溢出用 fp32 或减最大值就能解决，这里解决的是梯度问题。

Q2：多头的 变小了，缩放因子用哪个？

A（要点）：用 ，不是 。因为一次注意力计算发生在单个头内部， 与 的维度就是 ，方差是 。

加分句：「这也说明多头的切分是有副作用的： 变小意味着单头的分数尺度更容易控制，但单头可用的维度也更少。头数与 是绑定的设计选择，不能独立调。」

别说：「用 。」这暴露了只是背了公式没想过它在哪一维上做。

Q3：多头注意力的维度是怎么变的？为什么要 transpose？

A（要点）：[B, S, d_model] → view → [B, S, H, d_head] → transpose → [B, H, S, d_head] → 算出 [B, H, S, S] → 乘 V 得 [B, H, S, d_head] → transpose 回 [B, S, H, d_head] → contiguous + view → [B, S, d_model] → 。

transpose 的原因是矩阵乘法作用在最后两维，要把 个头的注意力并行算，头维必须排在序列维之前。

加分句：「这里有两个真实的坑：一是 transpose 后直接 view 会报错，因为内存不连续，必须 contiguous()；二是 head 维留在序列维后面不会报错，但算出来的是错的，这类 bug 最危险——它不崩溃。」

别说：「就是 reshape 一下。」说不清为什么要 transpose 就是没真写过。

Q4：多头到底提升了什么？参数量不是没变吗？

A（要点）：单头必须把所有需要追踪的关系挤进一个 softmax 分布，各类关系在归一化时互相竞争权重。多头把 切给 个独立子空间，每个头可以专注于不同的关系模式（邻接、指代、句法等），互不挤占。参数量恒为 与 无关——多头是计算结构的重组，不是参数扩容。

加分句：「严格说，多头不是数学上更强的函数类（多头在表达能力上与单头同阶），它的优势来自优化动力学：独立子空间的注意力和独立的 融合，让梯度下降更容易找到分工解。」

别说：「多头就是多个视角看问题，效果更好。」这是同义反复。

Q5：Self-Attention 和 Cross-Attention 的区别？

A（要点）：Q 与 K/V 是否同源。Self 的 Q/K/V 都来自同一序列，注意力矩阵是 方阵，解码端使用时加因果掩码；Cross 的 Q 来自解码端、K/V 来自编码端，矩阵是 矩形，不加因果掩码（必须看完整源序列才能对齐）。工程上 Cross 的 K/V 解码全程不变，可一次算好复用。

加分句：「我在项目二里用 cross-encoder 做精排，内部就是 query 对 passage 的交叉注意力，所以它能捕捉词级对齐，比双塔准；代价是完全不可预计算，只能用在 top-k 候选集上。」

别说：「cross-attention 就是两个不同序列的 attention。」把「哪些来自哪一侧」以及「掩码为什么不同」说清才算过关。

Q6：注意力为什么是 ？FlashAttention 解决了什么？

A（要点）： 会产生一个 的矩阵， 时元素数是 。计算量与显存都是这个量级。FlashAttention 的核心是用分块（tiling）与在线 softmax 把注意力计算融合进一个 kernel，不把 矩阵写回显存——它优化的是显存访问（IO），不是降低计算量。所以它的收益主要来自减少 HBM 读写，而不是减少了 FLOPs。

加分句：「这也说明它和长上下文的注意力稀疏化是两条不同路：FlashAttention 让稠密注意力更快更省内存，稀疏化/线性注意力改变的是复杂度本身。」

别说：「FlashAttention 让注意力复杂度从平方降到线性。」这是错的，它会立刻被抓。
