本页目录

位置编码：Sinusoidal / 可学习 / RoPE / ALiBi ​

覆盖知识点：L1-08 ｜ 面试频率：高 ｜ 建议学时：4h

一句话说清 ​

自注意力本身是置换等变的——把输入序列打乱，输出只是跟着打乱，模型对顺序毫无感知。位置编码就是补上「顺序」这条信息。四代方案的演进主线是从绝对位置到相对位置：Sinusoidal 用固定的三角函数加到输入上，可学习编码给每个位置一个可训向量，ALiBi 直接在注意力分数上按距离衰减，而 RoPE 走的是最巧妙的一条路——对 Q 和 K 做位置相关旋转，让点积结果自然只依赖相对位置差。RoPE 因为「相对性 + 实现简单 + 无额外参数 + 可以通过改基底做长度外推」成为今天几乎所有主流开源大模型的选择。

为什么必须学 ​

这一页是「长上下文」这条热门线的地基，面试里三种问法：

  1. 「为什么需要位置编码？」 —— 考你能不能说出置换等变性。答不出这一点，后面的 RoPE 推导全是背的。
  2. 「RoPE 为什么比可学习位置编码好？」 —— 核心是它把相对位置编码进了注意力打分里，而可学习编码是绝对位置、且训练长度之外的位置没有对应的向量，天然无法外推。
  3. 「RoPE 怎么扩展上下文长度？」 —— 这是高级追问，答案涉及「改基底 / 插值」，也是你项目里长文档处理绕不开的话题。

还有一层现实价值：项目二有 60+ 篇长论文，你的切块与「一次塞几段」直接受模型上下文限制。能不能把长上下文这个限制讲清楚来源，是「会用模型」和「懂模型」的分界。

核心内容 ​

为什么自注意力必须补位置信息 ​

自注意力的计算是 ，其中 都是 的线性投影。如果给 的序列维做一次置换 ，那么 都变成 的投影，输出变成 。

也就是说：输出只是跟着输入一起被置换，内容完全不变。 这叫置换等变（permutation equivariant）。模型的每个位置看到的是「一组无序的向量」，它无法知道谁在前谁在后。

一句「我咬狗」和「狗咬我」，token 集合相同、注意力能拿到的信息相同，模型无法区分。所以必须显式注入位置。

一个常被忽略的细节：位置编码的作用是打破置换对称性。理论上只要注入的信息随位置变化即可（不一定是「位置编号」这种语义化的量），但实践中编码方式的选择会显著影响长度外推能力——这才是四代方案的分水岭。

它声称的好处：相对位置可由绝对位置线性表示 —— 因为 可以用 与 的线性组合写出来。这意味着「模型理论上能学到相对位置」。

它实际的问题：

  • 这个「线性关系」需要模型自己学会去用，而不是结构上保证的；
  • 训练长度之外的位置虽然有编码（sin/cos 可以算任意 ），但没有见过这些组合，外推能力实测很弱；
  • 加在输入端意味着位置信息只在第一层进入，后面 层全靠残差流携带，长距离的精细位置关系在传播中容易被冲淡。

方案二：可学习绝对位置编码（BERT / GPT-2 系） ​

给每个位置 一个可训练的向量 ，加到 token embedding 上。BERT 用 ，GPT-2 用 1024 之类。

优点：实现最简单，位置表示完全由数据驱动。

致命缺点：

  • 超过 就直接不可用——没有第 513 个位置的向量。所谓「外推」只能靠插值或改模型。
  • 每个位置一个向量，参数量随最大长度线性增长（，相对总量不大但纯属浪费）。
  • 学不到相对性：位置 5 和位置 6 的向量在训练中是两个独立参数，模型要自己发现它们该「相邻」。

对长上下文的直接后果：想扩到更长序列，就必须用插值或微调重新学习新位置的向量，而且训练时没见过的新位置向量学得很差。这是 2023 年前后 RoPE 成为主流的最直接原因。

为什么它胜出（四条，每条都要能说清）：

优点说明
天然相对位置点积里只出现 ，结构保证而非学习得到
无额外参数不引入任何可训练向量，只做旋转；参数量与位置无关
作用在每个注意力层不像 Sinusoidal 只在输入端注入一次，它每层都对 Q/K 做旋转，位置信息不会在残差流里被冲淡
可外推 / 可扩展因为形式上是「角度」，可以通过改基底 或做位置插值把有效窗口拉长，不需要重新定义「第 1025 个位置的向量」

长上下文扩展怎么做（高级追问）：

  • 改基底（base scaling）：把 从 10000 调大，让旋转变慢，同样长度下覆盖的角度范围更「密」，从而在推理时容纳更长的序列。这是不少开源模型给出的官方做法之一。
  • 位置插值（position interpolation）：把超出训练长度的位置压缩映射回训练区间（例如 8192 的窗口，把位置 16384 按 缩放）。代价是分辨率下降。
  • 注意：具体数值、各模型推荐配置与是否需要继续微调，以官方模型卡与文档为准，不要在面试里报自己记不准的数字。

实现上的两个坑：

  1. 旋转要成对应用：必须把最后一维按 配对，不能随便切。实现里通常是把最后一维 view 成 [..., d/2, 2] 或等价地拆成前后两半再拼接。
  2. Q 和 K 都要旋转，V 不旋转。因为只有 Q 与 K 之间要做点积，V 是被加权的内容，不需要带相对位置信息。

方案四：ALiBi —— 直接在分数上按距离惩罚 ​

做法：完全不加位置编码。改为在注意力分数上加一个与距离成正比的偏置：

其中 是查询与键的距离，每个头有一个自己的斜率 （ 是头下标；不同头用一组固定的几何级数斜率，让有的头关注近处、有的头关注远处）。

含义：离得越远，注意力分数被扣得越多 —— 一个「近处优先」的先验。这不是学习出来的，是硬编码的归纳偏置。

优点：

  • 极简：没有位置向量、没有旋转，只在分数上加一项；
  • 外推好：因为偏置是距离的线性函数，训练长度之外的距离照样能算出偏置，不需要「第 个位置的向量」；
  • 多斜率设计让不同头天然分工。 缺点：
  • 丢掉了绝对位置信息 —— 对某些任务（如需要精确位置的任务）可能有害；
  • 是惩罚式的：它只告诉模型「远的少看点」，而不是「位置 相对于 是什么」；对需要精确相对距离的任务，表达力不如 RoPE；
  • 主流开源模型选 RoPE 的更多，ALiBi 更多出现在强调外推的 Encoder 或早期长上下文模型里。

面试里最好用的一句总结：「位置编码的四代演进，本质是从『给模型一个位置的标签』走向『让模型直接感知位置差』。RoPE 赢在它用旋转把相对位置做进了注意力的代数结构里，所以它既不需要额外参数，又能通过调基底获得外推能力。」

和你自己的项目对上号 ​

① 上下文长度限制解释了你为什么要做 512 / 1024 / 2048 三档切块消融。 你项目二的语料是长论文。把一整篇论文塞进 prompt 是不现实的：模型的训练上下文有上限，而超长序列带来的注意力 成本与 KV Cache 增长会让延迟与显存同步上升。所以正解是切块 + 只注入 top-k 相关片段。你的三档消融本质上在测：块越大（单块上下文越完整）vs 块越小（检索更精准、注入总长度更短） 之间的取舍。这条权衡的物理来源就是本页与前一页讲的东西。

② 为什么你的检索系统要「分块」而不是「整篇」——还有一个 RoPE 视角的解释。 即使模型的标称上下文窗口足够大，有效上下文往往小于标称值：训练时的序列长度分布决定了模型在长距离上真正学好了多少相对位置关系。把不相关的长文档整篇塞进去，不但成本高，还可能因为有效注意力被稀释而降低质量。「检索做得好，是为了让注入的上下文里有效信息密度高」——这句话是你项目二把 recall 与最终答案质量分开评测的动机。

③ 位置编码与「引用溯源」的关系。 项目二要求答案带引用（哪个 chunk 的哪段）。引用能成立的前提是 chunk 之间有明确的位置标识与边界，而不是把全文拼成一坨。你在 prompt 里给每个片段编号（[1] [2] ...）并让模型在输出里引用，本质上是在给注入的上下文重建位置信息——因为拼成一长串之后，模型看到的是一段连续文本，片段的来源边界会消失。这是一个很好的、把位置编码的直觉迁移到工程设计的例子。

④ YYHelp 的多轮会话与位置预算。 多轮对话的历史同样是「位置预算」的消耗者。你的会话状态持久化 + 中断恢复机制决定了历史怎么裁剪。注意：裁剪历史要按 token 数裁（见 Tokenizer 那页），并且要从中间裁而不是从开头裁（保留 system 指令与最近若干轮）。这是一个能立刻写进 FastAPI 层的预检逻辑。

可执行的小实验（验证 RoPE 的相对性）：取一个开源模型的注意力实现（或用自己手写的 RoPE 层），构造两个实验：

  1. 固定 与 的向量内容不变，只改变它们的绝对位置 ，但保持 不变，观察旋转后的点积是否完全一致（应当一致，误差在浮点范围内）；
  2. 保持位置不变，把 从 1 变到 100，观察点积随距离的变化趋势。

判据：实验 1 的差异应该只来自浮点误差（用 torch.allclose 验证）；实验 2 的点积会随距离振荡而非单调衰减（因为是多频率旋转的叠加）——这一点常被误解成「RoPE 会让远处的注意力自动变小」，实际上它不保证衰减，衰减要靠 ALiBi 那种偏置或训练学出来。把这两个观察写进笔记，你在面试里就有一句别人说不出来的话。

面试怎么问 ​

Q1：为什么需要位置编码？

A（要点）：自注意力是置换等变的：对输入序列做置换 ，输出只是跟着被置换（），内容量不变。所以模型对 token 的先后顺序一无所知，必须显式注入位置信息来打破这个对称性。

加分句：「这也说明位置信息在 Transformer 里不是『网络拓扑的一部分』（RNN 里顺序是结构决定的），而是一个可以独立设计的输入。正因为解耦了，才有 Sinusoidal / 可学习 / RoPE / ALiBi 这一整条演进线。」

别说：「因为 Transformer 没有循环结构所以不知道顺序」就完 —— 要说出「置换等变」这个机制。

Q2：RoPE 为什么能编码相对位置？

A（要点）：把每两个维度配成一对做二维旋转，旋转角度与位置成正比。旋转矩阵是正交的，于是 —— 点积里只出现 。相对性是旋转的代数性质，不是学出来的。

加分句：「所以 RoPE 不需要额外参数，也不需要在输入端加任何东西；它是每层对 Q 和 K 做旋转，位置信息不会随层数在残差流里被冲淡。V 不旋转，因为 V 是被加权的内容，不参与位置匹配。」

别说：「RoPE 就是把位置编码乘到 Q 和 K 上。」是旋转不是乘法——乘一个标量改变不了方向，旋转才能让点积产生相对位置依赖。

Q3：可学习位置编码有什么问题？

A（要点）：三个。① 不能外推：超过 就没有对应的向量，第 513 个位置的参数根本不存在；② 参数量随长度增长（），纯浪费；③ 学不到相对性：位置 5 和位置 6 是两个独立参数，模型需要自己发现它们相邻，没有结构上的保证。

加分句：「这也是长上下文需求一上来，可学习编码就迅速被 RoPE 取代的直接原因 —— RoPE 的位置是角度，不是查表，所以『更长的位置』天然有定义。」

别说：「可学习编码不灵活。」要给出「不可外推」这个硬机制。

Q4：RoPE 平时怎么把上下文窗口扩到更长？

A（要点）：两条主要路子。① 改基底：把 rope base 调大，旋转变慢，同样长度下覆盖的角度范围变化，从而容纳更长序列；② 位置插值：把超出训练区间的位置压缩映射回训练区间，代价是位置分辨率下降。两条路都可能需要继续训练来恢复质量。

加分句：「还有一条不依赖模型的路是我在项目里用的：不改模型，改应用层 —— 切块 + 只注入 top-k 相关片段 + token 预算预检。这样长文档处理不依赖模型的窗口能开多大，而且成本和延迟都可控。」

别说：报一个具体的 base 数值或「某某模型用的是多少」。记不准的数字不要报，说「具体推荐值以官方模型卡为准」是安全且专业的回答。

Q5：ALiBi 和 RoPE 的区别？

A（要点）：ALiBi 不加位置编码，直接在注意力分数上按距离减一个偏置（每头一个固定斜率），是「近处优先」的硬编码先验；RoPE 通过旋转把相对位置做进 Q·K 的代数结构里。ALiBi 更简单、天然可外推，但丢掉绝对位置、只是惩罚式表达力受限；RoPE 表达力更强且成了开源主流。

加分句：「两者都瞄准『外推』这个目标，但手段不同：ALiBi 是改打分（加归纳偏置），RoPE 是改表示（旋转 Q 与 K）。RoPE 赢在它不损失原有表达能力。」

别说：「ALiBi 就是另一种位置编码。」它恰恰是「不要位置编码」的方案。

Q6：长上下文模型标称 128k，实际能处理 128k 吗？

A（要点）：要区分标称窗口与有效窗口。标称值来自训练配置与位置编码的扩展方式；而实际能力取决于训练时序列长度的分布（模型在长距离上学到了多少真实的位置关系）、以及注意力在长上下文里的稀释效应。加上 的注意力与线性增长的 KV Cache，长上下文的延迟与显存代价都很高。

加分句：「所以工程上的做法不是『把窗口开到最大』，而是让注入的上下文信息密度高 —— 这正是我项目二做混合检索 + 重排 + 只注入 top-k 的动机：与其塞 60 篇论文，不如精准地塞 5 个最相关的片段。」

别说：「128k 就能处理 128k。」把标称当实际是典型的应届生陷阱。
