L7 导览 · 进阶方向 ​

本层知识点导览 ｜ 10 个知识点 / 6 页正文 + 1 页导览 / 50 学时 ｜ 面试频率：高 2 页、中 4 页

这一层在知识体系里的位置 ​

前六层解决的是「把模型用起来」：L0 打底、L1 讲原理、L2 会写提示词、L3 会接检索、L4 会编 Agent、L5 会上线、L6 会评测。L7 解决的是「当推理侧的招都用完了，还能动什么」——动权重（微调 / 偏好优化 / 后训练）、动成本（蒸馏 / 量化 / 调度）、动输入形态（多模态）。

一句话主干：L7 不是在讲"怎么训模型"，而是在讲"什么时候值得训、要付什么代价、以及为什么大多数时候不该训"。

这一层有一个和别层不同的性质，必须提前说清：

面试权重结构是分叉的。 对于大模型开发工程师岗，L7-03（LoRA/QLoRA 实操）、L7-04（分布式全参）、L7-06（RL 后训练 / GRPO）、L7-08（推理优化）属于会被直接考到实操细节的内容；对于 AI Agent 开发 / AI 应用开发岗，这一层的定位是「能接住追问，但不用背到能实操」——面试官会问你「为什么不微调」「你没做后训练怎么保证效果」，而不是让你现写一段训练脚本。

所以本层的读法是：判据背熟、机制说清、参数不背。凡是具体参数名、默认值、模型规格（参数量 / 层数 / 上下文长度）——一律不背，一律答"以官方文档为准"。

这一层最容易挂在哪 ​

按「被问到的概率 × 答不出来的代价」排序：

1）报出框架的参数名、默认值或模型规格（全层，尤其 ③④）。 这是本层最快也最致命的失分方式。r / alpha / target_modules 没有普适最优值（必须在自己验证集上扫），QLoRA 的量化配置项、DeepSpeed 各 ZeRO stage 的开关名、DPO/ORPO/SimPO 的超参、GRPO 的实现细节、各家模型的参数量与上下文长度——都在持续变动，且各框架命名不同。正确答法是只讲机制与取舍方向，加上一句「具体参数名与默认值以官方文档为准」。答"我记得是……"比答"我不背这个，我查文档"危险得多——后者是工程习惯，前者是风险敞口。

2）把 LoRA 的 r 当成"越大越好"的旋钮（③ L7-03）。 r 决定低秩增量的容量：越大越能表达、也越容易过拟合且显存与训练时间上升；alpha 是缩放系数，通常和 r 一起被讨论；target_modules 决定注入到哪些层——这三个是三个不同的问题，混在一起谈就说明没实际跑过。安全答法：给「常见区间」+ 一句「无普适最优，要在验证集上扫」+ 说明你会用哪个指标判断。

3）「SFT 效果不好 → 加数据、加 epoch」（② L7-02）。 微调的上限由数据决定，不由超参决定：格式不一致、长度分布失控（静默截断）、训练集与评测集泄漏这三类问题，加再多轮数也修不回来，只会把错误记得更牢。必须能说出「先看哪几个指标判断是数据问题还是超参问题」。

4）把"训得更多"当默认方向（④ L7-06 / ⑤ L7-07）。 两个高频错误：一是没有可靠的评测就去做后训练——偏好优化需要一个能判"哪个回答更好"的信号，没有可信的评测，奖励信号就是噪声，训练只会把噪声固化进权重；二是以为"蒸馏就是让学生超过老师"——学生通常只是在特定任务与成本约束下更有性价比，能超过老师的只有三种例外情况（教师通用而学生专用 / 教师受约束没发挥 / 学生用了教师之外的信息）。

5）用推理侧的思路解决训练侧的问题，或者反过来（① L7-01 / ⑤ L7-08）。 两条典型错法：「知识不够 → 去微调」（时效性知识应该走 RAG，微调更适合改输出格式与行为风格）；「延迟高 → 换个更快的模型」（先拆时间构成——常见的真实情况是瓶颈根本不在模型生成，而在检索或前置计算上）。判据：先定位瓶颈在哪一环，再谈手段。

本层必须记住的项目口径 ​

这一层的每一页都有一节「和你自己的项目对上号」，共同前提只有一条，必须先说清楚：

两个项目都没有做过任何训练。 全程只用了推理侧的现成模型——Embedding 用 bge-m3、Reranker 用 bge-reranker-v2-m3、生成走 OpenAI 兼容协议的 deepseek-flash / deepseek-v4-pro。没有训过生成模型、没有训过 Embedding / Reranker、没有做过偏好优化、没有做过量化或推理优化、没有用过多模态模型。

两条未验证事项（必须如实说） ​

  1. 本层全部 6 页都不含训练或推理优化的实测。 页内出现的所有机制说明、决策树、参数取舍方向都是依据公开资料与原理推导，没有在本机跑过任何一次微调、偏好优化、蒸馏、量化或视觉模型调用。因此本层不提供任何"调完之后的数字"——凡是要报效果的地方，验收方式都写在对应页末尾的「未执行验证」注释里（统一形状是：先用评测集定义成功判据，再谈训练）。

  2. 各框架的具体参数名、默认值与模型规格一律未在本地快照中确证。 LLaMA-Factory / ms-swift / PEFT / TRL / DeepSpeed / vLLM 的字段名、各模型的参数量与层数、视觉 token 的换算方式、Chinchilla 系数——页内凡涉及这些的地方都标注了「以官方文档为准」。这不是偷懒：这一层的知识时效性在所有层里最高，把会变的东西背下来，是最快失效的投入。
