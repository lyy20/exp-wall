本页目录

稀疏检索与混合融合 ​

覆盖知识点：L3-16 L3-17 ｜ 面试频率：高 ｜ 建议学时：7h

一句话说清 ​

稀疏检索（BM25）强在字面精确匹配、弱在同义表达与跨语种；混合检索不是「两路加起来一定更好」，它是一条有前提的结论——前提是两种检索器的失效场景互补。

为什么必须学 ​

这一层有一个几乎每个 RAG 面试都会问的题：「混合检索是不是一定比纯向量好？」 教科书答案说「是」，而 2026 年的合格答案说「不一定，要看两路是否互补」。能主动说出后者的人，会被直接归到「做过真实项目」那一档。

另外两个高频点：

  • RRF 的公式与 k 的含义：很多人只会调库，说不清 1/(k+rank) 里那个 k 在做什么。
  • BM25 的能力边界：能不能回答「中文查询检索英文语料为什么失效」，是判断你有没有踩过坑的分水岭。

核心内容 ​

L3-16 BM25 与稀疏检索 ​

定义：稀疏检索是基于词项精确匹配的检索方法，代表算法是 BM25。它的分数来自「这个词在文档里出现多少次（TF）」×「这个词在全库有多稀有（IDF）」，再按文档长度归一化：

其中 是词频、 是文档长度、avgdl 是平均长度。 控制「词频饱和」（出现 10 次不该比出现 1 次重要 10 倍）， 控制长度归一化强度（默认常取 、，具体默认值以你所用的实现文档为准）。

机制：建索引时要先分词（tokenize）——英文按词、中文通常按字或二元组（bigram），再对每个词项建倒排表（inverted index）。检索时对 query 分词、逐词查倒排表、算分、排序。

为什么这样设计：BM25 擅长的是稠密检索原理上做不到的事——精确字面匹配：产品型号、专有名词、编号、缩写、错误码。一个词只差两个字母就是另一个东西时，字面匹配才是对的判据。

数量级与形状：倒排表的规模与「词项数 × 平均文档频率」成正比，通常比向量索引小得多（不存浮点向量）。中文用二元组时词典规模会显著膨胀（「安全距离」→ 安全 / 全距 / 距离），这是中文稀疏检索的固有成本。

常见误区：

  • 「BM25 是过时技术」——在专有名词、编号、缩写检索上它仍然显著优于稠密检索，而且零训练成本。
  • 「分词用 jieba 就能解决中文问题」——解决的是「中文查询检索中文语料」；中文查询检索英文语料时，任何分词器都救不了，因为英文文档里根本没有这些中文词——这是原理性边界，不是分词质量问题。
  • 「分数全 0 会报错」——很多实现会静默返回空结果。空结果混在正常结果里，会让你的「混合检索」组指标悄悄退化成纯向量，而报告看起来一切正常。

L3-17 混合检索与融合（RRF / 加权） ​

定义：把稠密路与稀疏路的候选合并成一个排序。主流融合方式有两种：加权求和（把两路分数归一化后加权）与RRF（Reciprocal Rank Fusion，只使用名次、不使用分数）。

机制：RRF 的公式极简——

其中 是文档 在第 路里的名次（业界实现通常从 1 开始）， 是平滑常数。为什么这样设计：因为两路的分数量纲根本不可比——余弦相似度在 0–1 之间、BM25 是无上界的实数。直接加权必须先做归一化，而归一化会引入新的假设（分数分布是什么形状、要不要按分位数归一）。RRF 绕开了这个问题：只信名次，不信分数。

k 的作用（高频追问）：它压低「头部名次」的相对优势。

  • 越大， 随 rank 变化越平缓——k 很大时，第 1 名和第 2 名的分数几乎相同，融合更「民主」，更看重两路是否都出现过；
  • 越小，头部名次的话语权越大——k 很小时，单路第 1 名就能压过另一路的多个中位命中。

k 的常用取值在几十这个量级（比如 k = 60，具体取值以你所用的实现/论文推荐为准），但没有普适最优值——它取决于你希望融合多「保守」，要在自己的候选分布上做消融。

加权 vs RRF 的取舍：

维度加权求和RRF
需要什么两路分数可比（要归一化）只要名次
可解释性权重直接表达偏好名次贡献固定，调的是 k
适合两路分数都稳定且量纲已知量纲差异大、或一路分数不稳定
风险归一化假设错了会系统性偏置丢弃了分数里的「置信度」信息——一路全体低分时，它仍会被当成有效证据

为什么必须有「自检」机制：融合的前提是两路失效场景互补。当这个前提不成立（比如一路在本次语料上系统性失效），融合会主动伤害结果——它把一路的噪声当成有效证据投票，把另一路的好结果挤下去。所以成熟实现会给融合加一道可观测的准入判断，而不是永远开或永远关。

数量级与形状：融合后的候选数量取两路的并集，通常按融合分截断到与单路相当的规模（几十条），再进精排。注意 RRF 分数的量纲：单条 RRF 分是 量级，多路累加后最大也就几十分之一——它和余弦/精排分完全不是一个量级，绝不能共用阈值。

常见误区：

  • 「混合检索 = 效果一定更好」——错。要问的是「这两路在我的语料上互补吗」，而且必须有实测支撑。
  • 「RRF 的 k 是 top-k 的意思」——不是。 是平滑常数，和「取几条」无关。
  • 「两路各取 top-k 再融合，就一定能提升召回」——只有当至少一路能命中时才有意义；如果两路都漏，融合只是把两个空集合并。
  • 「一路返回空结果不影响结论」——会淹没结论。消融报告里如果大多数题上稀疏路都是空的，那这一组的指标实际上反映的是纯向量，必须在报告里说清。

和你自己的项目对上号 ​

这一页是你整个项目最有分量的内容——因为你亲手做了一次「推翻教科书」的实验，而且原因、机制、修法、代价四件都齐。

1）你自己实现的稀疏路：rank-bm25 的 BM25Okapi，索引在 ingest.py 建、查询在 retrieve.py:184 用；分词真源是 config.tokenize()——英文按词、数字原样、中文二元组（不足两字退单字）。中文二元组的例子：「安全距离」→ 安全 / 全距 / 距离。两个必须讲清的行为：① 全 0 分等于空结果（if scores[i] <= 0: continue，retrieve.py:188）——这是静默降级；② 空结果用 _SPARSE_EMPTY 计数器（retrieve.py:127）+ 首次出现时的一次警告（:200-209）来记录，因为消融结论要靠它：如果某组里大部分题上 BM25 都是空的，那这组指标其实反映的是纯向量，报告必须交代（源码注释 retrieve.py:123-126）。

2）融合确实可能有害（核心结论）：扩库前后的对照（config.py:173-176 注释 + exp34_fusion_diagnosis.py，docs/projects/rag/04-retrieval.md:118-129）：

语料① 纯向量 R@5② 混合（无精排）R@5③ 混合 + 精排 R@5
5 篇（523 块，全英文）62.3%64.5%（融合有帮助）74.6%
56 篇（5470 块，含 2 篇中文）49.3%29.2%（比纯向量还差）59.7%

根因：中文查询的 BM25 top-20 全部来自那两篇中文文献——不是因为主题相关，而是因为语言相同；在失败查询上两路 top-20 的交集是 0，于是 RRF 把 dense 的好结果挤掉了。一句话总结：「同语言 ≠ 同主题」。

3）修法是一条配置项：SPARSE_MODE=overlap（config.py:180-182，实现在 retrieve.py:294-316）——always | overlap | never 三态；默认 overlap 的语义是「两路各取 top-20，交集 ≥ 2 才融合，否则丢掉稀疏路、退回纯稠密」。设计思想是：「两路交集低于 2」是「这两路在这个查询上互不认可」的可观测信号——与其让人去猜什么时候该关稀疏路，不如把这个判断写成配置项，让系统自己判断该不该生效。指标回到 47.9%（旧题集口径）。

4）跨语种的真实数字（exp35_crosslingual.py 五路对照，R@5）：原始 BM25 8.3% → 加领域术语表（当前线上策略）29.2% → LLM 查询翻译 70.8%。结论一句话：不要用 BM25 做跨语种召回；跨语种需要语义桥。 而术语表是领域补丁——glossary.py 的 TERM_MAP 是 57 条中文→英文映射，要人工维护，换语料就失效；它的增益是 ② 组 R@5 62.3% → 64.5%、R@10 66.7% → 73.2%，③ 组 R@5 73.2% → 74.6%（全量消融、23 题人工核对版 gt），而且不增加延迟（只作用于 BM25 路，不增加精排候选）。

5）RRF 的一个「抄来的因果句」被自己推翻：代码注释原来写着「rank 从 0 开始会让排序错乱」。exp24_rrf_check.py 验证的结果是这句话是错的：，0 起点下第 1 名分数更高；两种起点都是单调递减函数，在 3 个真实查询上给出完全相同的排序。要求 rank 从 1 起的真正理由只是「对齐公式定义与业界实现」。真正会出问题的是两路用不同起点：这会给其中一路带来系统性偏置 （），而 时第 1 名与第 2 名的分数差只有 0.000264——偏置比一个名次格子的宽度还大，在近似并列时会翻转名次，而且不报错。教学价值就是项目里的一句原话：「注释里的因果句也要有证据，不能继承一句就一直抄。」

6）参数真源：RRF_K = 60（config.py:165）、每路深度 20/20、融合后 FUSED_TOP_K = 20（:163-166）——注意 k 与 top-k 是两个完全不同的东西，这一页必须能一口分清。

面试怎么问 ​

Q1：混合检索一定比纯向量好吗？

A（要点）：不一定，这是有前提的结论——前提是两种检索器的失效场景互补。我有实测：5 篇全英文语料上融合让 R@5 从 62.3% 涨到 64.5%；扩到 56 篇（含 2 篇中文）后，同样的混合检索 R@5 从 64.5% 崩到 29.2%，比纯向量的 49.3% 还差。加分句：根因是同语言 ≠ 同主题——中文查询的 BM25 top-20 全部来自那两篇中文文献，不是因为主题相关，而是因为语言相同；两路交集是 0，RRF 就把 dense 的好结果挤掉了。别说：「混合检索是标配，肯定更好」——这句话会被一句「那你测过吗」直接问倒。

  • 追问 1：那你怎么办？永远关掉稀疏路吗？→ 不是。我把它做成了配置项 SPARSE_MODE，三态：always（总是融合）/ overlap（默认：两路 top-20 交集 ≥ 2 才融合）/ never（等价纯向量）。思想是：与其让人去猜什么时候该关，不如把判断写成可观测信号，让系统自己决定该不该生效。
  • 追问 2：交集 ≥ 2 这个数是怎么定的？→ 它是一个启发式阈值，不是推导出来的。我承认这一点：它买到的是「明显失效时自动降级」，代价是可能误判——两路本来弱互补但只有 1 条交集时会被丢掉。要更严谨就得把「交集数」当成一个可扫的参数，在标注集上看「降级判定」与最终指标的联合影响。这是我知道但还没做完的部分。

Q2：RRF 公式里的 k 是什么？取多少？

A（要点）： 是平滑常数，不是 top-k。它压低头部名次的相对优势： 大 → 名次差异被压平、融合更保守（更看重「两路都出现过」）； 小 → 头部名次的话语权更大。加分句：我取 60，但没有普适最优值——它取决于你希望融合多保守，要在自己的候选分布上做消融。别说：「k 就是 top-k 的 k」——这一句会立刻暴露你没读过公式。

  • 追问 1：rank 从 0 还是 1 开始？→ 我用 1。但我要主动更正一个常见说法：我代码注释里原来写着「rank 从 0 开始会让排序错乱」，这句是错的——我实测过，两种起点都是单调递减，在真实查询上给出完全相同的排序；真正的风险是两路用了不同起点，那会给其中一路带来系统性偏置，偏置量比一个名次格子的宽度还大，在近似并列时会翻转名次且不报错。
  • 追问 2：为什么不直接用加权求和？→ 因为两路分数量纲不可比（余弦 0–1，BM25 无上界），加权前要先归一化，而归一化会引入「分数分布是什么形状」这类新假设。RRF 只信名次，绕开了这个问题。它的代价是丢掉了分数里的置信度信息——某一路整体低分时仍被当成有效证据，所以我给融合加了准入自检。

Q3：BM25 有什么局限？中文场景要注意什么？

A（要点）：两条——① 不认识同义表达（用户说「安全距离」，论文写 a safe distance ranging from 15m to 30m）；② 跨语种完全失效，而且是原理性的：中文 token 在英文语料里 df=0，换任何分词器都救不了，因为英文文档里根本没有这些词。加分句：我实测过严重程度——13/13 纯中文查询的 BM25 返回空，也就是说「混合检索」在我这个语料上会静默退化成纯向量，而且不报错；跨语种五路对照里原始 BM25 的 R@5 只有 8.3%，加术语表到 29.2%，而先把查询翻成英文再检索能到 70.8%。别说：「中文就用 jieba 分词」——这只回答了中文查中文的情况。

  • 追问 1：BM25 返回空结果你怎么发现？→ 我加了一个可读的计数器（_SPARSE_EMPTY，配 sparse_empty_count() 与 reset_sparse_empty()），首次出现时打印一次警告。一条只打一次的日志不足以支撑报告结论——因为消融报告要判断「这一组里稀疏路到底有没有在起作用」，那需要能事后统计的数。
  • 追问 2：那你线上的方案是什么？→ 线上是「术语表 + SPARSE_MODE=overlap」的组合：术语表把中文查询里的领域词映射成英文词，让稀疏路至少能命中一部分；overlap 兜住它仍然失效的场景。我把它明确写成领域补丁——换语料就失效、术语表要人工维护、映射错了会引入噪声。更通用的做法是「先把查询翻译成英文再检索」（实测 R@5 70.8%）或训一个跨语言稀疏模型。
