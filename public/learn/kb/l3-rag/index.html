L3 · RAG 检索增强 ​

本层知识点导览 ｜ 28 个知识点 / 10 页 / 101 学时 ｜ 面试频率：高 9 页、中 1 页

这一层是什么 ​

RAG（Retrieval-Augmented Generation，检索增强生成） 是把外部知识检索出来拼进上下文，再让模型基于这些材料回答。它是企业 AI 应用的第一个落点，也是 AI 岗位面试里考察最密集的领域——因为它是少数能同时考到「算法原理」（Embedding、ANN 索引、Cross-Encoder）与「工程落地」（解析、权限、护栏、延迟）的题目。

本层按一条完整链路的数据流组织：解析 → 切块 → 向量化 → 建索引 → 检索（稠密 + 稀疏）→ 融合 → 精排 → 改写/多跳 → 生成约束 → 引用与权限。它不是十个孤立专题，而是一条链上的十个环节——所以前一环的输出质量问题，后一环永远修不回来。

三句话概括这层的核心判断：

  1. 上游决定上限：解析与切块错了，向量化与精排再强也救不回来。
  2. 召回与排序是两件事：混合检索修召回，Rerank 修排序，不能相互替代。
  3. 没有普适最优参数：chunk size、top_k、HNSW 的 M/efConstruction、RRF 的 k 都必须在自己的语料与题集上做消融——这一层给的是判据，不是数字。

这一层最容易挂在哪 ​

按面试被问到的概率 × 答错的代价排序，五条：

1）把 RRF 的 k 当成"相似度阈值"或"权重"（⑥ L3-17）。 k 是排名偏移量，取最小排名加上一个平滑常数，作用是压掉头部名次的过大优势、让后面的名次也有机会贡献——它不是分数，也不是"调大了就更严格"。连带的高频错误是把 RRF 融合分（本项目实测区间约 0.016–0.033）当成精排分去比 0.30 阈值，结果每一道题都被拒答。判据：先问这个分数的性质，再谈阈值。

2）把 Recall@10 == Recall@5 当成"检索已经到顶"（⑤ L3-15）。 这个相等是标注窗口造成的构造性结果——机器 gt 的候选只取 retrieve()[:5]，人只看前 5 个，所以 R@10 在定义上就追平了 R@5。修正后暴露的真实情况是：不做精排时 R@10 比 R@5 高 11–14 个百分点。这题考的是"你会不会怀疑自己的指标口径"，答"说明前 5 条已经够了"就是踩进去了。

3）认为"同语言 = 同主题"，用 BM25 兜跨语种（⑥ L3-16）。 扩库后中文查询的 BM25 top-20 全部来自那两篇中文文献（两路零重叠），混合检索 R@5 从 64.5% 崩到 29.2%。根因是中文分词产出的词元在语料里 df=0，被 BM25 当成"极高区分度词"。修法是加准入自检（两路交集过小就丢弃稀疏路，SPARSE_MODE=overlap）——但这只是止血，跨语种真正要做的是语义桥（查询翻译），实测 R@5 从 8.3% → 29.2%（术语表）→ 70.8%（查询翻译）。

4）给 chunk size、top_k、M/efConstruction 报"最佳值"（③④⑤）。 这一层的正确答案永远是判据 + 消融方法：chunk size 看语义完整性、检索单元粒度、上下文预算三条；M/efConstruction、nprobe/ef 看召回-延迟曲线的拐点；top_k 要分三处（召回 / 融合 / 进上下文）分别定。报一个具体数字并说"业界最佳"，是这一层最快的失分方式。

5）把"我没做过的"说成"我做过"（全层，尤其 ⑧ 与 ⑩）。 本项目没有实现 Text2SQL、GraphRAG、多模态检索、查询改写（含 HyDE）、多查询、路由、多跳检索、Agentic RAG、多租户隔离。这些题的正确答法是：说清它解决什么问题、代价是什么、我为什么现在不做、要做的话第一步是什么——比如"先补评测题类（多跳题 / 免检索题 / 全局性问题 / 图文题现在都是空的），否则做完无法判断有没有变好"。"我知道瓶颈在哪、该往哪修，但我没修"比编一个优化后的数字安全得多。

补充两条"隐形的坑"，不一定被直接问到，但会决定你答得深不深：① 误拒率是一个统计量而不是一组固定坏样本（23 道可回答题每轮固定 3 道被误拒，但中招的题每轮不同）——盯单题找根因找不到；② 精排 8.5 s（CPU）与 LLM 生成 1.26 s 的对比告诉你瓶颈在哪：端到端 P50 15.66 s 里检索占约 92%，所以"优化 LLM"是错误方向，而"先返回来源列表再流式出答案"这类把等待变可见的产品层改动，收益比模型层大。

本层与项目的对应：这一层讲的几乎每个环节，都能在你的科研文献 RAG 项目里找到真实痕迹——语料 55 篇 / 5325 块，切块三档（"512" 档实际 max_chars 1024 字符 / overlap_chars 153，"1024" 档 2048 / 307），检索三档实测 ① 纯向量 R@5 64.4% ｜ ② 混合无精排 59.1% ｜ ③ 混合+精排 71.8%，双层拒答（程序层阈值 0.30 + 模型层自述），RRF_K = 60、RERANK_TOP_N = 5、三个 TOP_K 均为 20、LLM_TEMPERATURE = 0.1。逐条出处见各页末尾的 <!-- 事实来源 --> 注释。
