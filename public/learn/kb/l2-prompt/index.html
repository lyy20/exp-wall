L2 导览 · 提示工程与结构化输出 ​

本层共 22 个知识点 / 8 页 / 合计 57 学时。这是全套知识体系里最能直接转成简历条目和面试问答的一层：它不讲模型内部怎么算，讲的是你怎么把一个概率模型用成一个可靠的系统。

这一层在解决什么问题 ​

L0 解决「代码写不写得对」，L1 解决「模型的脾气你懂不懂」，L2 解决的是「你写的这段东西，模型到底听不听得懂、守不守规矩」。它的所有内容都在回答同一类问题：

  • 我该怎么组织这次请求？（消息角色、系统提示、模板化）
  • 我该怎么让模型按我想要的方式思考？（示例、CoT、分解、ReAct、Reflection）
  • 我该怎么让模型的输出被别人写的程序消费？（JSON Mode、JSON Schema、Function Calling、校验重试）
  • 我该怎么证明我的改动确实变好了？（版本化、评测闭环）
  • 我该怎么让它在长时间、多轮、有外部输入的情况下不崩、不被骗、还付得起？（上下文工程、注入防护、缓存）

一句话：L2 是「把 LLM 从 Demo 做到生产」的那一层。面试官在 AI 岗位面试里问的技术细节，超过一半落在这一层。

这一层最容易挂在哪 ​

按「挂掉的概率 × 挂掉的代价」排序。前四条是高危，最后三条是加分项没拿到。

  1. 分不清「哪些保证来自协议、哪些只是请求模型配合」。把 JSON Mode 当 Schema 用是典型死法：它只保证输出是合法 JSON，字段名、类型、必填项一概不管。更隐蔽的是把「严格模式」当成内容正确的保证——它保证结构有效，不保证事实正确。一句话答不上来就会被判定为没做过生产系统。
  2. 结构化输出只测了规范路径，并且校验函数是「空输入恒真」的。check([]) 返回 True 这种函数会把「引用全丢光」报告成「校验通过」——静默假通过比崩溃危险得多，因为你的验收报告是绿的。正确姿势：归一化必须上报被丢弃项，丢弃项非空即判失败；用测试替身往生产校验层喂脏输出。
  3. 说不清 Function Calling 到底谁在执行工具。模型只输出意图（调用哪个工具、什么参数），执行、鉴权、幂等、审计全在你的代码里。这个隔离是你安全性的来源，答成「模型会调用工具」就没了。
  4. 缓存的作用域讲反了。前缀缓存要求逐 token 匹配前缀，所以任何变的东西都必须靠后：时间戳、随机 ID、未固定顺序的工具列表、每轮不同的检索结果——它们放在前缀里会让缓存永不命中；而用户可控的内容更是绝对不能进前缀（缓存污染）。把「稳定在前、动态在后」讲成「重要的放前面」是没抓住机制。
  5. A/B 一次改多个变量、分流不粘性、样本不够就说提升。三条里中任意一条，实验结论就不可信。能主动说出「这轮样本不足，结论不可比」，比报一个漂亮的提升数字更能证明你懂实验。
  6. Reflection 被当成免费的提升手段。没有外部信号（测试结果、工具返回、schema 报错、明确评分标准）时，让模型检查自己只会得到另一段看起来合理的文本——加了成本，还可能引入自我偏袒。正确说法是「Reflection 是校验失败时的重试机制，它的价值取决于回灌进去的那条具体报错」。
  7. 术语只有中文没有英文原词。面试官和技术面试官的检索词是 ReAct、Function Calling、JSON Schema、CoT、Self-Consistency、Context Engineering、Prompt Caching、Prompt Injection。说中文没问题，但要能接住英文提问——这一条不影响深度，但影响你能不能听懂问题。
