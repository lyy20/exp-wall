多轮、轨迹与 Agent 评测 ​

覆盖知识点：L6-09 L6-10 ｜ 面试频率：高 ｜ 建议学时：4h

一句话说清 ​

单轮问答的评测是「答案对不对」，多轮与 Agent 的评测要额外回答「过程合不合理」——工具选对没有、参数填对没有、步数是否超出必要、失败之后有没有自我恢复。这两件事必须分开测，因为同一条轨迹可以用完全错误的路径得到正确答案（把工具删掉、硬编一个答案），也可能走了完全正确的路径却没得到答案（最后一步汇总出错）。评测指标因此分成结果指标与过程指标两层；而在做「A 方案 vs B 方案」的比较时，还有第三层问题：你测出来的差异是真的，还是样本量不够导致的噪声。这一页把三层串起来——轨迹分解 → 配对实验 → 三态结论（有提升 / 有回归 / 测不出来）→ 与公开基准的关系。

为什么必须学（面试官视角） ​

你的简历里两个项目都写了评测与 CI 门禁，所以面试官在项目环节一定会问**「你怎么知道你的改动是变好了」**。这是这一整层里最容易被问穿的一题，因为它的答案牵涉统计，而绝大多数应届生答不上来。

答「跑了一遍，指标涨了」会被追问到崩：涨了多少？多少题上测的？换个随机种子还涨吗？——你没法证明那不是噪声。

而这一页最值钱的不是「你会做 A/B」，是**「你知道自己的实验在哪里失效」。真实素材里有一条极硬的证据：40 题配对盲测，两臂在 39/40 的题上同对同错，于是有效样本量 。也就是说，这 40 题在这套比较上只提供了 1 个独立的信息单位**。能主动说出这句话的候选人，面试官会立刻把你从「背过指标名」归到「知道自己在干什么」那一档——因为承认自己的结论测不出来，比报一个好看的数字难得多。

核心内容 ​

L6-09 多轮对话与 Agent 轨迹评测 ​

  • 定义：把一次 Agent 运行展开成一条轨迹（trajectory）——用户轮次、模型的思考与工具调用请求、工具返回结果、状态变更、最终输出——然后对这条轨迹的结构与产物分别打分。

  • 机制——两层指标，职责完全不同：

    层看什么典型判据失败时说明什么
    结果指标最终答案 / 任务是否完成完成率、最终答案正确性、结构化字段是否合法系统没解决问题
    过程指标中间步骤是否合理工具选择是否正确、参数是否完整、步数与调用次数、是否重复调用、失败后是否恢复、单任务成本系统碰巧解决了问题，或用了不可接受的方式解决

    两层必须同时报。只报结果指标，你会漏掉「删掉工具也能过」这类退化；只报过程指标，你会漏掉「每一步都对但最后汇总错了」。

  • 为什么这样设计：因为多轮场景里没有唯一正确轨迹。同一件事可以一次检索搞定，也可以查三次再合并；两条轨迹都不是错。所以过程指标不能写成「与参考轨迹逐字匹配」，只能写成约束（必须调用过某工具 / 步数不超过 N / 不出现重复的相同调用）或评分量表（由裁判或人工按维度打分）。这是 Agent 评测与单轮评测最根本的区别。

  • 多轮特有的三个麻烦：

    1. 信用分配（credit assignment）：多轮里最终答错，错在哪一轮？可能第 1 轮没问清意图，也可能第 3 轮工具返回被截断。逐轮打分 + 整体打分同时记录，才能定位。
    2. 状态污染：把整段历史塞给模型，早期错误会被反复放大（错误传播）；评测时如果每轮都重放全历史，延迟与 token 都会超线性增长。
    3. 人的因素：多轮评测里的「用户」是谁？真实用户不可复现，所以常用模拟用户（按剧本扮演）——但要让模拟用户也有确定性（同剧本同回复），否则比较的两臂其实跑在不同的对话上。

  • 数量级 / 形状：过程指标的方差通常远大于结果指标。因为轨迹长度本身就是变量——一个 3 步的轨迹和一个 11 步的轨迹，可观测的行为数差了近 4 倍。这意味着：轨迹指标需要比结果指标更多的样本，或者必须用配对设计把任务难度差异消掉。

  • 常见误区：

    1. 用「最终答案对了」代替「Agent 做对了」。这是 Agent 评测最常见的一个自欺。
    2. 把工具调用次数当质量指标。步数少不一定是高效，可能是漏做了检查。
    3. 不做配对设计。两组跑不同的题，题目难度差会盖过方案差异。
    4. 不记录失败样本的原始轨迹。失败样本是回填评测集的唯一来源，只存一个错误码等于把最有价值的数据扔了。

L6-10 Agent 评测基准与横向比较 ​

  • 定义：公开基准（如 GAIA 这类通用助手任务集、AgentBench 这类多环境任务集、以及偏交互式的工具使用基准）提供统一任务 + 统一判分，让不同 Agent 可比。

  • 机制与取舍方向（具体基准的官方版本、题量、判分脚本以各基准官方仓库文档为准，不要凭记忆引用数字）：

    你的需求该用什么代价
    对外横向比较、简历里的一个数字公开基准任务分布与你的业务不重合；跑一次成本高
    定位自己系统的失败模式自建评测集（≥几十题，按失败类型分层）标注成本；覆盖面受限于你想到的失败类型
    证明某个改动的因果效果配对对照实验 + 统计检验样本量与统计门槛

  • 为什么这样设计（什么时候不该用公开基准）：公开基准的设计目标是排名，不是诊断。它给你一个标量，但不告诉你哪一层坏了。更现实的三条约束：

    1. 环境漂移：涉及网页、真实工具、外部 API 的基准会随时间失效（网站改版、API 下线）。一个「上个月 30% 这周 22%」的基准数字，可能什么都没变，只是环境变了。
    2. 不贴合：你的项目是电商客服多轮 Agent，通用助手基准里的任务（订机票、查天气）测不到你的核心能力（多轮意图澄清、幻觉拒答）。
    3. 成本随步数放大：Agent 任务的 token 消耗是单轮的几十倍，跑全量基准要按预算规划。

    所以正确姿势是：公开基准用来「有一个可对外说的参照点」，自建评测集用来「指导你下一步改什么」。二者不可互相替代。

  • 常见误区：

    1. 在简历上写基准分数却说不出口径（版本、任务子集、运行日期、是否用了工具）。这类数字在面试里活不过一次追问。
    2. 把基准成绩当业务效果。基准排名高 ≠ 你的客服 Agent 更准。
    3. 忽略成本维度。同一个任务 A 用 3 步、B 用 9 步，成功一样时 B 没有任何优势——这恰好是本页实验数据的结论。

实证：一次真实的两臂配对盲测（把它当成模板记住） ​

实验设计：YYHelp 侧，40 题 × 2 臂，配对盲测——同一批题在两条臂上各跑一次，配对比较。题类分布：

题类数量
single_hop12
synonym8
unanswerable8
multi_hop6
exact_term6
合计40（answerable 32 / 不可回答 8）

三条指标的完整结果（每一步都要带口径：样本量、检验方法、效应量、校正方式）：

指标两臂数值差异与区间检验结果结论
完成率multi 40/40 vs single 39/40均值差 +0.025，CI [−0.024, +0.074]配对 t p = 0.323；Wilcoxon p = 1.0NSC（测不出差异）
每问 tokens5,783.7 vs 6,243.3—t p = 0.409；Wilcoxon p = 0.017两法结论不一致 → 按校正后判 NSC
每问墙钟20.9s vs 9.9s差 −10.95s，CI [−14.79, −7.12]，2.11×t p = 1.9e-6；Wilcoxon 8.7e-7；效应量 dz = −0.89；Holm 校正后拒绝原假设REGRESSION（明确回归）

这组数据里有五个可以直接拿去面试的要点：

  1. 「没有显著差异」是一种结论，而且是主要的结论。 三个指标里两个是 NSC。报告 NSC 需要勇气，但它是诚实的唯一形式。
  2. 墙钟的 2.11× 是真回归。 它同时在一个区间（CI 不含 0）、两个检验（参数与非参数都拒绝）、一个效应量阈值（ 很大）上过关，并且经过了多重比较校正。
  3. tokens 指标的「两法打架」本身就是发现。 配对 t 不显著而 Wilcoxon 显著，说明差值分布重尾（少数题上 tokens 差异极大，把均值拉偏了）。这种时候不该选一个「更好看的」结果上报，而应判 NSC——因为检验方法的选择不能由结论决定。
  4. 多重比较必须校正。 一次评测比了 3 个指标，等于做了 3 次检验，误差率会累积；这里用 Holm 控制。不校正的多指标评测，本质上是在"跑到显著为止"。
  5. 最硬的一条：。 两臂在 39/40 的题上同对同错。用配对设计里的「不一致对数」去算，有效样本量只有 1。这解释了为什么完成率测不出差异——不是差异不存在，是这 40 题没有能力测出它。

功效分析（用来说明"要多少题才够"）：以 、 为参数计算——

想检测的提升需要题数
+5 个百分点76 题
+10 个百分点17 题

最后一行是这一节最值钱的一句反直觉结论：有些提升不是"样本不够"，而是在给定题集上根本不可能观测到。给出「+20pp 无解」比给一个笼统的「样本量再大点」专业得多。

统计实现的可信度也要能讲：配对 t 检验的实现以教科书 T 分布临界值表逐点核对，配对 t 的部分用不完全 Beta 函数的连续分数展开计算。也就是说，这套统计不是「调库拿到一个 p 值就上报」——能说出自己核对过临界值表的候选人，几乎不存在竞争者。

和你自己的项目对上号 ​

YYHelp 侧是你全部素材里最接近「一次完整实验」的东西，而且它的价值恰好在于结论是否定的：

  • 你做了配对盲测、算了区间与效应量、做了多重比较校正、给了功效分析——这是「实验设计」四件套。
  • 你发现 ，也就是自己否定了自己的实验有效性。这条在任何面试里都比「提升了 12%」更有说服力，因为它证明你验证过结论的边界。
  • 你用三态退出码把「测不出来」和「回归」在工程上分开了（详情见 CI 门禁与三态退出码），这直接从实验结论落地成了流水线行为。
  • 必须如实说的边界：知识库是合成语料、没有真实用户、评测集由本人标注。所以这 40 题上的结论不能外推到真实线上效果——只说明「在我的合成语料和我的标注口径下，多跳路线在墙钟上有 2.11× 的代价，且完成率上没有证据支持它更好」。

RAG 侧：多跳检索的严格准确率只有 27.8%——这个数字只能当线索，不能当结论（题量与判据口径见该报告）。它和 YYHelp 侧的 multi_hop 题类（6 题）是同一个现象在两个项目里的体现：多跳是当前系统的薄弱环节。两处放一起讲，比分开讲更有力量。

缺口：两个项目都没有做过轨迹级的过程指标（工具选择正确率、步数约束、失败恢复率）。要补的话最小可执行版本：在 YYHelp 侧已有的 JSONL trace 上，写一个 50 行以内的脚本，统计每题的工具调用序列与调用次数分布，报告「重复调用率」与「平均步数」，再把它写进报告顶部作为口径的一部分。

面试怎么问（≥3 组） ​

Q1：你怎么证明你的改动让 Agent 变好了？

A（要点）：不报「涨了百分之几」，报实验设计：同一批题、两条臂、配对盲测，先做功效分析确定题数够不够，再报告「差异 + 置信区间 + 检验方法 + 效应量 + 多重比较校正」，最后给三态结论。

追问一：你的结论是什么？

三个指标里两个是 NSC（完成率、tokens），一个是明确回归（墙钟 2.11×，CI [−14.79, −7.12]，Holm 校正后拒绝）。所以我的结论是「多跳路线在我的评测集上没有证据更好，而且在延迟上有确定代价」。

再追问：那你还留着这条路线吗？ 留着，但不默认开。它唯一可能的收益在 multi_hop 那 6 题上，而 6 题远远不足以支撑结论（+10pp 需要 17 题，+5pp 需要 76 题）。要留就是留成配置项，并且先把 multi_hop 题类扩到能测的规模再决定。

Q2：40 题够吗？

A（要点）：不够，而且我知道为什么不够。两臂在 39/40 的题上同对同错，配对设计里有效样本量算下来是 。这 40 题在这套比较上只提供了 1 个独立信息单位。

追问一：那要多少题？

功效分析给的答案：检测 +5pp 需要 76 题，检测 +10pp 需要 17 题，而 +20pp 在本题集上是数学无解。

再追问：「数学无解」是什么意思？ 意思是按当前题类的难度分布，两臂在同一条题上的表现几乎不可能产生足够多的不一致对——你加再多同分布的题，不一致对数也涨不上去。要观测到 +20pp，必须先改题集构成（往更难、更有区分度的题类倾斜），而不是改样本量。

Q3：如果 tokens 指标上参数检验说不显著、非参数检验说显著，你报哪个？

A（要点）：报 NSC，并且把「两法不一致」本身写进报告。检验方法的选择不能在看到结果之后再做，否则就是 p-hacking。

追问一：那不一致说明什么？

说明配对差值的分布是重尾的：少数题上 tokens 差异很大，把均值拉走了，所以 t 检验被拖累；Wilcoxon 看秩，受这些极端值影响小。tokens 这类长尾计数型指标出现这种情况是常态。

再追问：下次你会怎么设计？ 两个改动：预先注册检验方法（在跑之前就写死用哪个、多重比较怎么校正），以及对长尾指标用对数变换或直接用分位数（如 p50/p95），而不是只报均值。

Q4：为什么不直接跑一个公开 Agent 基准？

A（要点）：公开基准给的是可对外的参照点，不是诊断工具。它跑在我的业务上没有区分度，而且有三条现实约束：环境漂移（外部依赖变化会让历史分数不可比）、任务分布不贴合（我的核心是多轮意图澄清与拒答幻觉，通用任务测不到）、成本随步数放大。

追问一：那你简历里为什么不写基准分数？

因为我没在一个固定版本上跑过完整基准，写一个说不出口径的数字，等于给自己埋一个必然被追问的坑。我写的是自建评测集的规模与口径，那是我能负责到底的数字。

再追问：如果面试官就是要一个横向可比的结果呢？ 我会说清取舍：要么花预算在某个固定版本的基准上跑一次，产出一个带完整口径（版本、子集、日期、是否用工具）的数字；要么用「受控的自建评测集 + 对照实验」证明改动效果。两者回答的是不同问题——前者回答「我大概在什么水平」，后者回答「我的改动有没有用」。
