L6 · 评测与可观测 ​

本层知识点导览 ｜ 14 个知识点 / 6 页 / 28 学时 ｜ 面试频率：高 9 项、中 5 项

这一层在解决什么问题 ​

L1 讲模型怎么算，L2 讲怎么把话说清楚，L3 讲怎么把材料找对，L4 讲怎么让 Agent 动起来，L5 讲怎么把它跑在生产上。L6 回答的是唯一一个贯穿前面五层的问题：你怎么知道它变好了？

这不是一个「加个分数」的问题，而是一个测量学问题。LLM 应用是概率系统：同一个 prompt 跑两遍能得到两个答案，所以「变好」在这类系统里没有默认含义——它必须先被定义成一组 (题集版本, gt 版本, 指标口径, 比较对象) 四元组齐全、可复算的数字。没有这四元组，所有关于效果的讨论都是手感。

这一层的独特之处在于：它是对前面五层的元层，也是最容易被跳过的一层。

  • 它与上游的关系：L3 的检索指标、L5 的可观测三支柱，本质都是本层的实例。本层不去重讲它们怎么实现，而是讲它们的数字在什么条件下才可信。
  • 它与下游的关系：没有评测，L7 的微调决策只能靠感觉；没有回归门禁，L5 的每一次迭代都在赌。

三句话概括这层的核心判断：

  1. 尺子先于系统。 先定义怎么量，再动手改；反过来做，改动的方向由手感决定。
  2. 分母决定含义。 同一个数字，换分母就是另一件事。报数必带口径是这一层唯一的硬纪律。
  3. 被测系统不能参与出题。 拿检索结果当 gt、拿模型当裁判又不校准，指标就变成自证。

这一层最容易挂在哪 ​

  1. 报一个没有分母的百分比。 100.0% 分母只有 6 道题时几乎不含信息；71.8% 不带「124 题 / gt 206 块 / 密度 1.66 / 含精排」就是不可复算的。这一条是初筛与一面共同的高频死亡点——因为面试官只要追问一句样本量，答不出来整份简历的数字全部失效。

  2. 把 Recall@10 == Recall@5 读成「排序完美」。 真相是标注窗口造成的构造结果：gt 候选只取 retrieve()[:5]，人也只看前 5 个，所以 R@10 在数学上不可能高于 R@5。要先排除构造性解释，再怀疑模型——这个顺序反了，排序问题会从待办清单里消失（实测名次分布 1–5 位 21 道、6–10 位 0 道）。

  3. 拿被测系统的输出当 ground truth。 机器 gt 的候选由检索结果生成，再拿同一个检索器去评它就是自证——某组 R@5 = 100.0% 就是这么来的。正确处置不是删报告，而是让报告自己声明无效（那份报告顶部写着「🚫 不可作为结论」）。指标的可信度取决于流程是否独立于被测系统，不取决于数字多高。

  4. 跨报告沿列连读。 16 份历史报告跨越 ≥4 把尺子（gt 版本 / gt 块数 / 题数不同），同一列上下两行的分母不是同一个东西。换尺子会让分数掉——独立盲标后 Recall 从 87.0% → 71.0%，掉下来的 16 个点是原来的虚高部分，不是系统退步。

  5. 裁判没校准就当结论用。 答案准确率 65.2% / 91.3% 是旧 30 题口径、且 LLM 裁判未人工校准，与当前 130 题报告不是同一批次。严格与宽松差 26.1pp 这个分差本身就是诊断信号——它说明评分规则没定死，而不是「模型时好时坏」。

  6. 只验「脚本没报错」。 配置类与流程类假设必须配能失败的断言：gt 若全部落在 top-5 内就该抛异常；被标为「不可回答」却已填 gt 块的题就该抛异常。一个恒等关系成立时，脚本是跑得好好的——只验「没报错」等于没验。
