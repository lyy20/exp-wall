L0 · 编程与工程基础 ​

本层知识点导览 ｜ 30 个知识点，13 个页面，约 132 小时

这一层在解决什么问题 ​

L0 是整座知识体系的底座层：它不讲模型、不讲微调、不讲 Agent 原理，只解决一件事——你能不能把想法变成一个别人也能跑起来的东西。

这一层的内容全部来自同一个判据：面试官问「然后呢」的时候，你有没有东西可答。 你在简历上写了「基于 Milvus 做了混合检索 Agent」，面试官会接着问：服务怎么起的（L0-08 L0-07）、接口怎么设计的（L0-09 L0-10）、怎么做到逐字输出（L0-11）、数据存哪（L0-12 L0-13）、线上答错了怎么查（L0-17）、换一家模型要改多少代码（L0-16 L0-23）、模型服务挂了会怎样（L0-24）、这一天要花多少钱（L0-25）。这些问题不需要你会训模型，但答不上来，前一句话就白说了。

学这一层的正确姿势不是「看完」，而是跟着做：每一页的「和你自己的项目对上号」都把知识点钉在两个真实项目（YYHelp v2 与科研文献 RAG）的具体实现上——那些文件里写着的设计理由，就是这一层最好的教材。能把这些理由用自己的话讲一遍，这一项就算过了。

这一层最容易挂在哪 ​

以下是面试反馈里反复出现的失分模式，按出现频率排序：

  1. 「用了 X」但说不出为什么用它。 简历写 Milvus、LangGraph、SSE，被问「为什么不用别的」就沉默。修法：每个技术选择都要能说出一条被排除的替代方案，以及排除它的具体理由（规模、变量可控性、成本、团队熟悉度都算理由）。
  2. 只讲「成功路径」，不讲「失败路径」。 答不出「模型超时怎么办」「检索返回空怎么办」「用户重复提交怎么办」。修法：给每条链路补充一张降级表（11）。
  3. 量化全是形容词。 「大幅提升了准确性」「响应很快」——面试官无法验证，也无法记住。修法：换成可验证的量：recall@5、P95 延迟、token 用量、拒答率；没有测过就明说没测，这比编一个数字安全得多。
  4. 工程细节一问就空。 「别人 clone 下来能跑吗」「一天花多少钱」「线上答错了怎么查」——这三问几乎是固定搭配，考察的是你有没有把项目当成一个会被别人使用的系统。修法：把 04、07、08 三页的自检清单过一遍。
  5. 代码阅读能力被低估。 面试官问「你读过什么框架源码」时，答「没读过，都是照着教程写」会立刻降低技术可信度；而能说清「我读了状态图那个模块，它把每个字段的 reducer 写成一张表，还用一条『故意配错』的测试证明断言能红」的人，展示的是可迁移的工程判断力。修法：从自己项目里真正用到的那几个库入手，带着一个具体问题去读（11）。
