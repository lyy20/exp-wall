L4 导览 · Agent 与工具生态 ​

本层规模：33 个知识点 ｜ 15 页正文 + 1 页导览 ｜ 累计 116 学时 ｜ 面试权重：最高（与 L3 并列）

这一层在知识体系里的位置 ​

前三层是「模型本身能做什么」——L0 打工程基础，L1 讲模型原理与推理，L2 讲怎么把话说清楚（提示、结构化输出、上下文工程），L3 讲怎么把外部知识接进来（RAG 与检索）。L4 开始发生变化：模型不再只是「回答问题」，而是「决定下一步做什么」。

这个变化带来的全部复杂度可以压缩成一句话：从「一次生成」变成「一个循环」。 一旦有了循环，你就必须回答四个问题——循环怎么转（ReAct 循环与状态）、循环的手是什么（工具定义、生命周期、选择与并行）、循环记得住什么（短期与长期记忆）、循环什么时候停（终止条件、预算、幂等）。这四个问题就是 L4 的主干。

L4 之后的两层是它的外延：L5 工程化（服务化、可观测、成本），L6 评测与可观测（怎么证明你的 Agent 真的更好）。L4 是「能不能做出来」，L5/L6 是「能不能上线说清楚」。

这一层最容易挂在哪 ​

按「被问到的概率 × 答不出来的代价」排序。前五条是必须立刻补的。

1. ⚠️ 把 Agent 说得太玄（L4-01 / L4-03） ​

症状：一开口就是「自主」「智能体涌现」「它会自己思考」，但说不出 Agent 与 Workflow 的边界判据，也说不出四要素是什么。

为什么会挂：面试官立刻判定你没实现过，只是读过文章。凡是不能落到「哪一步由模型决定、哪一步由代码决定」的描述，都是玄学。

补法：用一条判据回答——控制流的决定权在谁手里？事先写死的分支是 Workflow，由模型在运行时决定下一步的是 Agent。然后立刻补一句成本：Agent 的代价是延迟、成本与不确定性，所以能从 Workflow 解决的不要用 Agent。

2. ⚠️ 说「工具是模型执行的」（L4-06） ​

症状：答「模型调用工具拿到结果，再继续推理」——把执行方说成了模型。

为什么会挂：这是机制性的错误，不是表述问题。它会让面试官立刻推断你不知道安全控制该放在哪。

补法：背六段生命周期，并指出只有第二段在模型侧；紧接一句「所以所有安全控制只能落在第三段：白名单、参数校验、权限、幂等键、人工确认」。再补两个边界：tool_calls 字段会骗人（模型可能在 content 里说「我要调用」而结构化字段是空的；反过来字段有调用而 content 为空是正常的）、arguments 通常是 JSON 字符串且可能解析失败。

3. ⚠️ 多智能体只会说「更强」（L4-17） ​

症状：「我做了多智能体，效果更好」，追问「提升多少、怎么测的」就卡住；或者直接说「多智能体没用」。

为什么会挂：这是实验素养的分水岭。答不出「没测出差异」与「证明没有差异」的区别，就说明你的结论来自观感而不是数据。

补法：准备一组完整的数字——40 题 × 2 臂、配对盲测；完成率 p=0.323、tokens p=0.409（两处 NSC）、墙钟 2.11× p=1.9e-6（REGRESSION）；两臂同对同错 39/40 ⇒ n_eff = 1；功效阈值 +5pp 需 76 题 / +10pp 需 17 题 / +20pp 数学无解。最后一句要落在「结构收益不需要统计显著性，质量收益未证，延迟代价已证」。

4. ⚠️ 装配错误只靠单测（L4-15 / L4-16 的应用面） ​

症状：说「我写了单测所以图编排是对的」。

为什么会挂：add_conditional_edges(source, path_fn, path_map) 的第三参是「path_fn 返回值 → 目标节点」的映射表；第一版让 route_by_exit 返回节点名却传了另一张表 → KeyError: 'agent_memory'，报错形态是 During task with name 'triage' and id 'a06e0b0c-...'。它能 import、能编译、纯函数单测全绿，一跑就崩。

补法：把结论说成方法论——装配错误必须靠运行图来验。给两条可执行的验收：图结构断言（决策表 vs 实际注册键做集合比对，差集非空即失败）+ 端到端冒烟（真跑一条非默认分支）。配套纪律：每一个回环边都要有自己的闸；只在一侧检查，另一侧就是一个能绕过去的循环入口。

5. ⚠️ 记忆只讲「我用了向量库」（L4-13 / L4-14） ​

症状：说不出写入门槛、衰减函数、召回打分的权重，也答不出「有多少记忆是垃圾」。

为什么会挂：「用了向量库」是零分答案；有门槛、有半衰期、有打分权重才说明设计过。

补法：背一组真实参数——写入门槛 preference 0.60 / fact 0.75 / solution 0.80 / correction 0.85（未知种类兜底 0.85，对未知从严）；半衰期 preference 90 天 / solution 180 天 / fact 与 correction 不衰减（偏好会变，事实不会）；召回打分 0.55 相似度 + 0.25 关键词重合 + 0.20 时间衰减 = 1，衰减下限 0.30、取值范围 [0.30, 1.0]，衰减在召回时计算（能算出来的东西不要存）。最后主动说那条反直觉设计：召回结果进 state 但不拼 prompt（可观测 / 可回滚 / 可对比），代价是模型看不到记忆，「用上了记忆」这件事本身还需要单独验证。

6. 其余高频失分点（一句话清单） ​

  • 工具描述写「什么时候用它」却不写「什么时候不要用它」 —— 相似工具之间的错选就靠这一句挡（L4-05）。
  • 把可选参数写进 required —— 模型会编一个值给必填字段（L4-05）。
  • 治理工具结果时只截断不标注 —— 静默丢弃会让模型在缺信息时自信地编（L4-09）。
  • 收窄工具可见性却说不出「越权副作用」这条理由 —— 那样它就只是性能优化，而不是权限边界（L4-08）。
  • 让代码执行直接做写操作 —— 绕过幂等键与人工确认，等于把安全控制整段拆掉（L4-10）。
  • 浏览器 Agent 把坐标当首选定位方式 —— 页面改版即失效；正确姿势是无障碍树优先、坐标兜底（L4-11）。
  • 反思没有上限，或上限写在提示词里 —— 模型的服从性不是闸，程序里的计数器才是闸；REFLECT_MAX_RETRIES = 1（L4-16）。
  • 给浅任务套 Planner —— 项目实测分派轮次均值 1.075，规划在浅任务上是纯开销（L4-15）。
  • 参数化测试当覆盖证明 —— 参数化测试是从清单读条目的，删掉清单里的一项只会「少跑一个用例」而不会变红；关键入口要写点名断言。
  • 报数不带口径 —— 任何一个百分比都要能说出分母是什么、样本多少、和谁比。

7. 「写下 ≠ 执行」：本层最该内化的工程纪律 ​

项目里做过一次清算：v1 有 11 个 selftest 从未被 pytest 执行；v2 建了自检总闸，把 v1 14 条 + v2 16 条 = 30 条入口用 subprocess 真跑起来，超时从 180 秒收紧到 60 秒（依据：实测最慢的自检约 2.6–2.8 秒，60 秒约为其 21 倍）。

原文值得逐字背：

代码的防护力 = 「被执行的断言数」，不是「写下的断言数」。一个从不执行的断言，防护力与「没有断言」完全相同 —— 但它会让你以为有防护。这比没有更危险。

这条纪律在 L4 全层的适用面：工具参数校验（L4-05）、并集覆盖断言（L4-08）、沙箱策略（L4-10）、幂等键（L4-32）、图的装配（L4-27）。遇到「你怎么证明这个防护是生效的」这类问题时，先问自己「有没有一个用例能让它失败」。构造不出失败用例的防护，不算防护。

两条未验证事项（必须如实说） ​

面试里被问到相关问题时，主动说出下面两条边界，比含糊地夸效果可信得多：

  1. 专家菜单选择准确率尚未实测。目前只验证到「结构上每个专家只看得见 1–3 个工具」（隔离报告这一层）。要做的是用真模型跑那 9 条可见性探针加跨域样例，判据是两条同时成立：选对率 ≥ 阈值 且 越界调用 = 0。
  2. 「用上了记忆」尚未验证。因为 RECALL_POLICY = "state_only"——召回结果进 state 但不进 prompt，模型其实看不到记忆。要验证必须单独做一次 hint 开 / 关的对照，判据是偏好引导的遵守率。
