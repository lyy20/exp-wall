面试准备总览 ​

这一节不是「知识」，是武器。八页里越靠前的，越能在 48 小时内见效。

如果你明天就有面试 ​

按这个顺序读，别从头翻知识体系：

顺序读什么花多久读到什么程度
1项目深挖预演40 min两个项目的「口径卡」能背下来，数字的口径说得清
2RAG 高频题30 min能画端到端图 + 说清它为什么会失败
3Agent 与工具调用高频题30 minReAct 循环能默写，工具调用生命周期能讲
4大模型原理高频题20 min注意力、KV Cache、位置编码三件套
5对应项目的拆解页60 min讲到第三层追问不卡

不要在面试前夜去啃没读过的知识点。面试考的是你能不能把会的东西讲清楚，不是你会多少。

面试官到底在问什么 ​

同一个问题，面试官脑子里在同时跑五层判断。大部分人只回答了第一层。

对应到你的答案，就是四条硬要求：

  1. 具体 —— 说文件名、说行数、说函数名（「在 graph/supervisor.py 的 run_react 里」），不要说「在编排层里」。
  2. 有取舍 —— 每个技术选择都要能说出被放弃的那个方案和放弃的理由。
  3. 有排查过程 —— 讲故障时讲「我怎么定位的」，不只讲「我改了什么」。
  4. 不越界 —— 没做过的就说没做。面试官见过太多编的数字，一旦被戳穿，前面全白讲。

你的两个项目在这四条上都有存货：源码已被逐行读过，缺陷、失败、文档与代码不一致的地方全都在事实清单里记着。这些「不完美」是你最值钱的素材——它们证明你真跑过。

口径卡（先背这两张） ​

YYHelp · 电商客服多轮对话 Agent ​

一句话：用 LangGraph 状态图把 9 类意图分流到 5 个出口，各子流程汇合到主力 Agent 的 ReAct 循环——解决的不是「检索准不准」，是多轮对话能不能可靠地把事办完。

三个必须带口径的数字：

说法口径（必须一起说）
多智能体 vs 单智能体：完成率 −14.2pp + 墙钟 1.43×，双 REGRESSION120 题×2 臂配对；完成率 63.3% vs 77.5%（p=0.00053）、墙钟 24.7s vs 17.3s（p≈0）显著更差；只有 tokens 省 12.5%（IMPROVEMENT）。结论：不切换多智能体。⚠️ 首轮 40 题的数字（100%/97.5%、2.11×）已被证伪，四轮链条见 ⭐ 架构对比实验
11 个 selftest 从未被执行这是 v1 的 grep 结果；说明「代码写下了」和「CI 真的跑了」是两件事
文档与代码不一致 9 处例：README 写「9 个新字段」实为 14；longterm.py docstring 写 7 组 selftest 实为 10 组

三个能撑住追问链的缺陷：run_react 缺 state 形参 → 异常被吞成 model_error；getattr(llm, "model") 同一个错逐字复发在两处；bottleneck 块构造持有 GIL，把并行收益从 1.02× 掩盖到 6.41×。

科研文献 RAG 问答 ​

一句话：面向 AI 领域科研文献的「混合检索 + 重排序 + 引用溯源 + 拒答」问答服务，外加一套分层评测集。

三个必须带口径的数字：

说法口径（必须一起说）
双层拒答，两层误拒率 1.6% vs 6.5%程序层 = rerank top1 < 0.30 零成本拒答；模型层 = 自报 insufficient 兜底。可回答题 top1 中位 0.9617 vs 不可回答 0.0127
Recall@10 == Recall@5 不是排序完美那是我自己标注窗口造成的构造结果——机器 gt 的候选只取了前 5 个。修正后立刻暴露「不做精排时 R@10 比 R@5 高 11–14pp」
首字延迟 14.9 s，瓶颈不是 LLM实测 14.90 / 10.00 / 14.86 s；其中 CPU 精排 20 对约 8.5 s，LLM 生成 P50 只有 1.26 s。优化方向一开始搞错了

两个能撑住追问链的发现：SPARSE_MODE=overlap 的自检失效机制（扩库后混合检索 R@5 从 64.5% 崩到 29.2%，根因是中文查询的 BM25 top-20 全来自那两篇中文文献——「同语言 ≠ 同主题」）；预热做了但没生效（/health 秒回 200 ⇒ 编排在模型加载前就把流量导进来，第一个请求照样等 48 秒）。

三条纪律 ​

报数必带口径

「recall@5 是 64.5%」这句话本身没有信息量。必须说：macro 还是 micro、k 是多少、有没有过精排、分母怎么定义、ground truth 谁标的。面试官只要追问一句「这个数怎么算的」，口径不全的人就露馅了。

不假装跑过

没测的就写「未验证」，并给出你会怎么验证。你两个项目的事实清单里都专门有一节叫「未实测 / 未验证清单」——带着这个去面试，比编三个漂亮数字安全一百倍。

配置类开关必须配「能失败的断言」

只验「没报错」等于没验。中文 BM25 静默返回空就是活例子：不报错、不抛异常、只给你一个空列表。任何一个开关，你都要能说出「我怎么知道它真的生效了」。
