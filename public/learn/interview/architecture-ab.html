架构对比实验：从假数据到显著结论 ​

一句话：这是整个项目里最能体现工程判断力的一段——我用四轮实验把"多智能体到底值不值"从一个漂亮的假数字，查成了一条统计显著的结论，中间修了三层根因。

与 ⑱ 面试深挖的分工

⑱ 面试深挖与口径 是整个项目的口径表与追问链。 这一页只讲架构对比实验这一条线：数字链、根因、方法论、以及怎么讲。

一、结论先行（先说结果，再讲过程） ​

指标multisingle判定（Holm 校正后）
完成率63.3%77.5%−14.2pp，p=0.00053 → REGRESSION（显著）
tokens/问4,7085,379multi 省 12.5%，p=0.00034 → IMPROVEMENT
墙钟/问24.7s17.3s慢 1.43×，p≈0 → REGRESSION

口径：120 题 × 2 臂 = 240 条，v4-pro 主模型、语义检索、盲测裁判（含锚定校准）；题集为 40 道原始题 × 3 个变体问法。

一句话判读：用 12.5% 的 token 省量，换来 14.2pp 的完成率损失 + 43% 的延迟增加——对在线客服场景是明确的亏。

二、四轮数字链（这一段本身就是面试素材） ​

轮次完成了什么完成率 multi / single当时的判定
Gate-1 / ab2首轮 40 题配对盲测100% / 97.5%假数据（见第三节）
ab3修三层根因后重跑60% / 75%边缘不显著（p=0.057）
ab4 / ab4-r2修生成层缺陷 + 评测精度修正72.5% / 77.5% → 70% / 77.5%打平（p=0.26~0.42）
ab5修工具数据源 + 性能优化70% / 70%（δ=0.000）完全打平
ab6扩样到 120 题（40 题 × 3 变体）63.3% / 77.5%显著 REGRESSION

为什么 40 题打平、120 题显著？两个原因：

  1. 功效：n=40 时置信区间是 [−14pp, +14pp]，真实的 −14.2pp 恰好落在可检出边界外；n=120 把边界压到 ±11pp。
  2. 变体暴露了脆弱性（见第五节）：换问法后 multi 掉 6.7pp，single 稳定——这才是差异的真正来源。

三、三层根因（第一轮的数字为什么是假的） ​

首轮我把"40/40 vs 39/40，不显著"写成结论。后来做人工锚定抽样（15 题逐条核对答案与标准答案），发现三层问题叠加：

根因 1：检索后端从未接入（接线缺口） ​

.env 里 YYHELP_KB_RETRIEVE 没设 → 默认 stub → 整场 A/B 跑的是"关键词替身"（对一份硬编码政策列表做子串+单字重叠打分），Day1 建好的 163 切片语义检索根本没接上。

怎么发现的：诊断脚本直连检索器，发现"改约收费""丢件赔付"这类题两臂齐声说'知识库没有'，而 KB 里明明有对应 chunk——两臂同时失败 = 共同前置坏了。

修法：.env 显式 semantic；并加前置闸：A/B 跑题前检查检索后端，不是 semantic 就直接退出。

根因 2：向量路静默降级（配置漂移） ​

即使切到 semantic，YYHELP_HF_HOME 指向一个空目录 → embedding 模型每次加载都去联网重试下载（超时）→ 向量路失效，检索静默退化成只有 BM25。

怎么发现的：独立 benchmark 测 encode 耗时，发现单条 query 稳态只要 0.03 秒而首次要 12 秒——12 秒是模型加载，而当时的"慢"其实是联网重试。

修法：修正缓存路径 + 补齐模型权重（镜像 8 段并行下载，字节数精确校验）；加第二道前置闸：embedder 维度必须等于集合维度，不等就退出。

根因 3：裁判在放水（评测层） ​

原来的裁判 rubric 写着"诚实说明无法回答并给出可行下一步 = 满分"——于是检索失败 + 礼貌拒答被判成完成任务。更难查的是：裁判会用自己的先验当事实（把"退款 3-7 个工作日"这种幻觉判成正确，因为它的先验里这句话"听起来合理"）。

修法两条：

  • rubric 分层：有确定答案的题，只有给出正确事实才得分；拒答/查不到一律 0 分。超范围题反之。
  • 锚定题 + 参考事实：裁判队列尾部混入 5 条已知标签的锚定题，锚定不全对就整批标签作废（退出码 2）；同时把标准答案 chunk 作为"参考知识"喂给裁判，让它从"判断"变成"核对"。

⚠️ 一个副作用：修完 rubric 后完成率从 97.5% 掉到 60-75%——这不是模型变差了，是数字终于真的了。这一条要主动讲。

四、方法论（可以迁移到任何 A/B 项目） ​

方法具体做法为什么必须
配对检验 + 多重比较校正同题两臂配对（t + Wilcoxon），多指标用 Holm 校正单方法显著不敢下结论；多指标不校正会把噪声当发现
功效分析用不一致对占比 ψ 反推"要多少题才能测出 X pp"没有它，"不显著"到底是"没差异"还是"样本不够"永远说不清
锚定校准已知标签题混入评测队列，全对才采信裁判本身是模型，会漂移、会被自己的先验带偏
参考事实注入给裁判标准答案文本，而非让它凭常识判断LLM 裁判不核实事实，rubric 再严也拦不住"合理幻觉"
前置闸门跑题前检查：检索后端 / 模型维度 / 端到端 smoke配置漂移是静默的，事后靠人工抽样发现代价太大
共同前置优先两臂同时失败的题，先查它们共用的那一层本项目的教训：检索和裁判坏了，测什么架构都是白测

功效数字（务必带口径）：ψ=0.208 时，测 +5pp 需 652 题、+10pp 需 161 题、+20pp 需 39 题——所以 −14.2pp 在 120 题下可检出，而小幅差异仍不可判。

五、新发现：multi 的脆弱点在分派鲁棒性 ​

同一批题的两种问法multi 完成率single 完成率
原题（40 题）70.0%70.0%
变体问法（120 题）63.3%（−6.7pp）77.5%（+7.5pp）

解释：multi 的收益依赖分派正确（意图分类 → 计划 → 专家），而分派对口语变体不鲁棒——问法一变就可能派错专家，而派错的专家工具集不匹配，答不出。single 用一个全工具专家，对问法天然更稳。

这条比"完成率更低"更有解释力：multi 的成本不只是 token 和延迟，还有路由脆弱性。改进方向也由此而来：不是"多加专家"，而是让分派对问法不敏感（规则兜底 + 口语归一化）。

六、面试怎么讲（三档 + 两条追问链） ​

30 秒版 ​

我给这个项目做了架构对比实验：让多智能体和单智能体共享同一套骨架，只把"谁决定下一个专家"这一个变量分开，跑 120 题 × 2 臂的配对盲测。结论是多智能体完成率显著低 14.2 个百分点、延迟高 43%，只在 token 上省 12.5%——所以我保持单智能体为主。

更有价值的是过程：这个结论我是修掉三层根因之后才拿到的，第一版数字是假的。

2 分钟版（加根因） ​

第一版我拿到的是"完成率 100% vs 97.5%、不显著"。后来做人工锚定抽样发现三层问题：检索后端从来没接上（跑的是关键词替身）、向量路因为一个环境变量指向空目录而静默降级、裁判把"礼貌拒答"判成完成任务。

修完之后完成率掉到 60-75%——这才是真实水平。第二版结论是"打平"，我又扩样到三个问法变体，差异才达到统计显著。

整个过程我沉淀了两条纪律：共同前置坏了就别谈架构对比；裁判本身也要被校准。

两条追问链 ​

追问链 A：「你是不是为了得出想要的结论才改评测？」

「反过来说更准确——我是先发现问题才改的。三个改动都不是我主动想改：检索后端没接上是我读代码发现的；环境变量指向空目录是 benchmark 测出来的；裁判放水是人工核对答案时发现的。 而且我保留了反向证据：修 rubric 让完成率从 97.5% 掉到 60-75%，如果我想美化数据，最该删的就是这个改动。 另外每轮的数字都写在台账里，包括中间那两轮"打平"的——没有一轮是我事后挑出来的。」

追问链 B：「40 题说打平，120 题说显著，哪个可信？」

「120 题更可信，但不是我挑样本挑出来的，是功效算出来的。n=40 的时候置信区间是 ±14pp，真实的 −14.2pp 刚好在边界外——测不出不等于没差异，这句话在我 40 题那版结论里就写着了。 扩样用的是同 40 题的三个问法变体（语义一致、gt 复用），不是为了凑数。 而且扩样暴露了我原本没意识到的机制：multi 在变体问法上掉 6.7pp 而 single 稳定——差异来自分派鲁棒性，不是模型能力。」

七、红线（这一段绝对不能说过头） ​

不能说该怎么说
"多智能体没用 / 是伪需求"「在这批任务、这个实现质量下，多智能体没有完成率收益且延迟显著更高；它的脆弱点在分派鲁棒性」
"我证明了架构选型"「这是单场景、离线题集、合成语料上的结论；触发条件（问题跨域占比、延迟预算、分派鲁棒性）满足时需要重测」
"AI 客服就该用单智能体"「决定性变量是问题分布与延迟预算，不是行业名——跨域占比高的场景结论可能相反」
"我早就发现问题了"「第一版数字是假的，是锚定抽样把它揭穿的——这一点我写在复盘的第一段」
