手撕与算法 ​

这一页的定位：能在白板或编辑器里 15 分钟内写出来。 和 L0 算法与复杂度 的分工是：知识页讲题目分类与判定路径，这一页只给能跑的代码 + 关键点 + 面试官会追问什么 + 常见写法错误。 每段代码都可以直接复制进 Python 文件运行；开头标了「完整可运行」的，连测试入口都写好了。

手撕题的评分方式（先明白判分点） ​

面试官看你写代码，心里在同时打四个分。大多数人只在意第一个：

维度他在看什么怎么拿分
正确性边界条件写没写空输入、单元素、越界、mask 全屏蔽
形状张量维度对不对每一步都写出形状注释（这是最容易被忽略的加分项）
说法你有没有边写边说「这里先 reshape 再 transpose，因为语义不同」
容错出错了怎么办「这个 API 我记不精确，我会查一下签名再写」——这句话几乎不扣分，编一个错签名会扣很多

一个白板技巧：写下第一行之前先说三句话——「输入是什么形状」「输出是什么形状」「复杂度目标是什么」。这三句话能给你争取 30 秒思考时间，还能让面试官知道你是有结构的。

一、手写 Scaled Dot-Product Attention ​

题目：用 numpy 实现 scaled dot-product attention，支持 padding mask，softmax 数值稳定。

python
"""完整可运行：scaled dot-product attention（含 mask 与数值稳定 softmax）。"""
import numpy as np


def softmax(x: np.ndarray, axis: int = -1) -> np.ndarray:
    """数值稳定的 softmax：先减去最大值。

    减最大值在数学上等价（softmax 对输入整体平移不变），
    但避免了 e^x 上溢成 inf。
    """
    x = x - np.max(x, axis=axis, keepdims=True)
    e = np.exp(x)
    return e / np.sum(e, axis=axis, keepdims=True)


def scaled_dot_product_attention(Q, K, V, mask=None):
    """Q, K, V: [..., S_q, d_k] / [..., S_k, d_k] / [..., S_k, d_v]
    mask: bool 数组，形状可广播到 [...], True 表示**保留**，False 表示屏蔽。

    返回: [..., S_q, d_v]
    """
    d_k = Q.shape[-1]
    scores = Q @ np.swapaxes(K, -1, -2) / np.sqrt(d_k)     # [..., S_q, S_k]

    if mask is not None:
        # 关键：用 -inf 赋值，而不是 softmax 之后乘 0。
        # 乘 0 之后那一行不再和为 1，权重语义就错了。
        scores = np.where(mask, scores, -np.inf)

    weights = softmax(scores, axis=-1)
    return weights @ V


if __name__ == "__main__":
    rng = np.random.default_rng(0)
    B, S, d_k, d_v = 2, 4, 8, 8
    Q, K, V = (rng.standard_normal((B, S, d)) for d in (d_k, d_k, d_v))

    # 因果 mask：位置 i 只能看到 <= i
    causal = np.tril(np.ones((S, S), dtype=bool))          # [S, S]
    out = scaled_dot_product_attention(Q, K, V, mask=causal)
    print("输出形状:", out.shape)                            # (2, 4, 8)

    # 数值稳定性：喂一个极大的分数，不应该出 nan
    huge = np.array([[[[1000.0, -1000.0]]]])
    print("极端输入:", softmax(huge)[0, 0, 0])               # [1. 0.]

关键点讲解：

  1. 缩放因子是除以 ，不是除以 。理由：若 各维独立同分布、方差为 1，则点积的方差是 ，除以 把方差拉回 1。除以 会压得太平，softmax 失去区分度。
  2. mask 用 -inf 而不是乘 0：乘 0 之后那一行权重和不为 1，等于偷偷改变了归一化。
  3. swapaxes(-1, -2) 而不是 K.T：K.T 在高维下会反转所有轴，只有二维时才等价。这是最常见的错。
  4. 复杂度：算力 ，分数矩阵显存 。

面试官会追问：

Q：如果整行都被 mask 掉会怎样？

A：-inf 那一行 softmax 之后是全 nan（，分母 0）。实践中必须避免出现「没有任何可见位置」的行——要么保证每行至少一个可见位，要么对分母加一个极小值。

Q：/ np.sqrt(d_k) 放在 mask 之前还是之后有区别吗？

A：没有区别，因为是逐元素缩放，和 mask 的赋值操作可交换。但顺序上有讲究的是缩放必须在 softmax 之前。

Q：如果 很大而你忘记缩放，输出会长什么样？

A：softmax 输入绝对值很大 → 输出接近 one-hot → 加权求和退化成一个位置的值。而且反向传播时梯度会接近 0，训练会停滞。这就是「除以 」被写进论文的原因。

常见错误答法：

错误后果
用 K.T 做转置高维下形状错，但二维测试能过——典型的「测了但没测到」
mask 之后再 softmax 乘权重权重和不为 1，结果偏小
不写形状注释面试官无法确认你懂维度，扣「形状」分
softmax 不减去最大值数值溢出，测试数据一大就 nan

二、手写 Multi-Head Attention 的维度变换 ​

题目：写出多头注意力的维度变换链，并说明 contiguous() 放在哪。

python
"""完整可运行：多头注意力的维度变换（纯 numpy，便于白板推导）。

变换链：
  [B, S, d_model]
    → Linear 投影后 split → [B, S, H, d_head]
    → transpose          → [B, H, S, d_head]      ← 注意力在这里算
    → 注意力输出          → [B, H, S, d_head]
    → transpose 回来      → [B, S, H, d_head]
    → contiguous + reshape→ [B, S, d_model]
"""
import numpy as np


def split_heads(x: np.ndarray, H: int) -> np.ndarray:
    """[B, S, d_model] -> [B, H, S, d_head]

    注意顺序：先 reshape 成带 H 的四维（H 与 d_head 在最后两轴），
    再 transpose 把 H 提到前面。
    直接 reshape 成 [B, H, S, d_head] 会**把相邻 token 的维度混进同一个头**，
    形状碰巧对，语义已经错了。
    """
    B, S, d_model = x.shape
    d_head = d_model // H
    x = x.reshape(B, S, H, d_head)      # [B, S, H, d_head]
    return x.transpose(0, 2, 1, 3)      # [B, H, S, d_head]


def merge_heads(x: np.ndarray) -> np.ndarray:
    """[B, H, S, d_head] -> [B, S, d_model]"""
    B, H, S, d_head = x.shape
    x = x.transpose(0, 2, 1, 3)         # [B, S, H, d_head]
    # numpy 的 transpose 返回视图（非连续内存），reshape 前要保证连续。
    # PyTorch 里对应 .contiguous()：不调用可能报错，或拿到错误的内存布局。
    x = np.ascontiguousarray(x)
    return x.reshape(B, S, H * d_head)  # [B, S, d_model]


if __name__ == "__main__":
    rng = np.random.default_rng(0)
    B, S, H, d_head = 2, 5, 4, 8
    d_model = H * d_head

    x = rng.standard_normal((B, S, d_model)).astype(np.float32)
    heads = split_heads(x, H)
    print("split :", x.shape, "->", heads.shape)      # (2,5,32) -> (2,4,5,8)

    back = merge_heads(heads)
    print("merge :", heads.shape, "->", back.shape)   # (2,4,5,8) -> (2,5,32)
    print("往返一致:", np.allclose(x, back))

关键点讲解：

  • 「先 reshape 到 [B,S,H,d_head] 再 transpose」是唯一正确的顺序。因为 reshape 是按内存顺序切分的：[B,S,d_model] 里最后一维的前 d_head 个数属于第 0 个头，接着 d_head 个数属于第 1 个头……所以必须先把 H 和 d_head 拆成相邻两轴，再换位置。
  • contiguous() 的位置：在 transpose 回来之后、reshape 之前。PyTorch 里 transpose 只改步长（stride），不搬数据；直接 reshape 一个非连续张量要么报错，要么触发一次隐式拷贝——显式写出 .contiguous() 既安全又能让面试官看出你知道这件事。
  • 多头的参数量：总维度不变时，多头和单头的参数量是同一量级（ 拆成几份），差别在「并行的多组子空间」而不是参数规模。

面试官会追问：

Q：view 和 reshape 有什么区别？

A：view 要求张量内存连续，否则报错；reshape 会在需要时自动拷贝。白板上写哪个都行，但要说清区别——生产代码里我倾向先 .contiguous() 再 .view()，因为「拷贝发生了没有」这件事在性能敏感的地方必须可控。

Q：为什么不直接用 [B,H,S,S] 的四维 einsum？

A：可以，而且公式更短。但面试里手写维度变换更能体现你懂数据布局。注意 torch.einsum 的具体调用签名请以官方文档核对——我记的是它的语义（按标签收缩），不保证参数顺序全对。

Q：多头之后为什么还要一个输出投影？

A：因为各个头的输出只是简单拼接，拼接之后各子空间之间还没有交互。输出投影负责把这 个子空间的信息混合回 的统一表示里。

常见错误答法：

错误后果
x.reshape(B, H, S, d_head) 直接 reshape形状对、语义错，最难被发现的一种错
合并时忘记 contiguous / 在 transpose 前就 reshapePyTorch 报 stride 错误，或结果错位
说「多头增加了参数量」总维度不变时参数量同量级
把 H 和 d_head 的顺序说反后面所有形状推导全错

三、手写 KV Cache 推理（prefill 与 decode 分开） ​

题目：写出带 KV Cache 的自回归推理，明确区分 prefill 与 decode 两阶段。

python
"""完整可运行：KV Cache 的 prefill / decode 两阶段（纯 numpy 演示形状）。"""
import numpy as np


def softmax(x, axis=-1):
    x = x - np.max(x, axis=axis, keepdims=True)
    e = np.exp(x)
    return e / np.sum(e, axis=axis, keepdims=True)


class KVCache:
    """每层的缓存形状：[B, H, S_seen, d_head]（K 与 V 各一份）。

    显存估算从「每 token 每层」起步：
      2（K 和 V） × n_kv × d_head × bytes  ← 每 token 每层
      再逐级乘：层数 L → 序列长度 S → batch B
    """

    def __init__(self, n_layers: int, B: int, H: int, d_head: int):
        self.n_layers, self.B, self.H, self.d_head = n_layers, B, H, d_head
        self.k: list[np.ndarray | None] = [None] * n_layers
        self.v: list[np.ndarray | None] = [None] * n_layers

    def append(self, layer: int, k_new: np.ndarray, v_new: np.ndarray):
        """k_new/v_new: [B, H, S_new, d_head]"""
        if self.k[layer] is None:
            self.k[layer], self.v[layer] = k_new, v_new
        else:
            self.k[layer] = np.concatenate([self.k[layer], k_new], axis=2)
            self.v[layer] = np.concatenate([self.v[layer], v_new], axis=2)

    @property
    def seen(self) -> int:
        return 0 if self.k[0] is None else self.k[0].shape[2]


def attn(Q, K, V, causal: bool):
    """Q:[B,H,S_q,d] K,V:[B,H,S_k,d] -> [B,H,S_q,d]"""
    scores = Q @ np.swapaxes(K, -1, -2) / np.sqrt(Q.shape[-1])   # [B,H,S_q,S_k]
    if causal:
        S_q, S_k = Q.shape[-2], K.shape[-2]
        mask = np.tril(np.ones((S_q, S_k), dtype=bool), k=S_k - S_q)  # 对齐到缓存末端
        scores = np.where(mask, scores, -np.inf)
    return softmax(scores, -1) @ V


def prefill(tokens: np.ndarray, proj, cache: KVCache, n_layers: int):
    """prefill：一次把整段 prompt 喂进去，每个位置都能并行算。

    attention 是**平方复杂度**在这里：S_q × S_k 的分数矩阵。
    """
    B, S = tokens.shape
    x = tokens
    for layer in range(n_layers):
        q = proj(x, layer, "q")                  # [B,H,S,d_head]
        k = proj(x, layer, "k")
        v = proj(x, layer, "v")
        cache.append(layer, k, v)
        x = attn(q, k, v, causal=True)           # 因果：位置 i 只能看到 <= i
    return x


def decode(tokens: np.ndarray, proj, cache: KVCache, n_layers: int):
    """decode：每次只喂 1 个新 token。

    S_q = 1，所以注意力每步只需读缓存里的 S 个位置：
    **计算量从「重算整个前缀」变成线性，但缓存显存随 S 线性增长。**
    """
    S_new = tokens.shape[1]
    assert S_new >= 1
    x = tokens
    for layer in range(n_layers):
        q = proj(x, layer, "q")                  # [B,H,S_new,d_head]
        k = proj(x, layer, "k")
        v = proj(x, layer, "v")
        cache.append(layer, k, v)
        x = attn(q, cache.k[layer], cache.v[layer], causal=(S_new > 1))
    return x


if __name__ == "__main__":
    rng = np.random.default_rng(0)
    B, H, d_head, n_layers = 2, 4, 8, 3
    d_model = H * d_head

    def proj(x, layer, which):
        """玩具投影：真实实现是每个头一套 W_q/W_k/W_v。"""
        B_, S_ = x.shape
        out = x @ rng.standard_normal((d_model, d_model)) if x.shape[-1] == d_model \
            else x @ rng.standard_normal((1, d_model))      # 单 token 时 d=1
        return out.reshape(B_, S_, H, d_head).transpose(0, 2, 1, 3)

    prompt = rng.standard_normal((B, 6, d_model)).astype(np.float32)
    cache = KVCache(n_layers, B, H, d_head)
    prefill(prompt, proj, cache, n_layers)
    print("prefill 后已缓存 token 数:", cache.seen)          # 6
    print("单层缓存形状:", cache.k[0].shape)                 # (2, 4, 6, 8)

    nxt = rng.standard_normal((B, 1, d_model)).astype(np.float32)
    decode(nxt, proj, cache, n_layers)
    print("decode 后已缓存 token 数:", cache.seen)            # 7

关键点讲解：

  • prefill 与 decode 是两个阶段，瓶颈类型也不同：prefill 算力受限（大矩阵乘， 分数矩阵），decode 显存带宽受限（每步都要把全部权重和 KV Cache 读一遍，但只算 1 个 token）。这句话是很多推理优化题的判分点。
  • 因果 mask 的偏移：decode 时 、，掩码要用 k=S_k - S_q 对齐到缓存末端；写成 np.tril(ones) 会只允许看第 0 个位置。
  • 缓存的 key/val 形状是 [B, H, S_seen, d_head]，只存要参与注意力的那份头数（GQA/MQA 下这个 H 是 而不是 ）。
  • 别把「算力」和「显存」搞混：KV Cache 省的是重复计算，付出的是显存。

面试官会追问：

Q：prefill 和 decode 哪个是瓶颈？

A：看场景，而且要分开说。 prefill 是算力受限：长 prompt 的分数矩阵是平方级的；decode 是显存带宽受限：每生成一个 token 都要把全部权重读一遍，batch 小的时候带宽完全浪费。所以「推理慢就加卡」和「推理慢就调采样参数」都是没判断瓶颈的做法。

Q：GQA 在代码里怎么体现？

A：缓存只存 份，算注意力时把 K/V 沿头维 broadcast 到 。变的是 KV 头数，Q 头数不变——这句话必须说清，因为它是这题最容易被问倒的点。

Q：PagedAttention 解决什么？

A：解决显存碎片与预留浪费。朴素实现要为每条序列预留 max_length 的连续空间，实际只用了其中一段；分页之后按块分配、不要求连续，能塞下的并发数直接上升。

常见错误答法：

错误后果
decode 阶段还用 np.tril 全量 mask只能看到第一个位置，结果错
把缓存写成 [B, S, H, d_head]能跑但和注意力算符对不上；面试官会认为你没想清布局
说「有 KV Cache 后注意力变成 」每步仍要读 个位置，是
说「KV Cache 与参数量成正比」缓存取决于层数、KV 头数、头维度、长度、batch

四、手写 LRU Cache ​

题目：实现一个容量为 capacity 的 LRU 缓存，get 和 put 都是 。

python
"""完整可运行：LRU，两个版本。

版本 A 用 OrderedDict：生产里就该这么写。
版本 B 用哈希表 + 双向链表：面试官说「不许用现成库」时这么写。
"""
from collections import OrderedDict


class LRUCache:
    """版本 A：OrderedDict。get/put 都是 O(1)。"""

    def __init__(self, capacity: int):
        assert capacity > 0, "容量必须为正"
        self.capacity = capacity
        self._data: OrderedDict = OrderedDict()

    def get(self, key):
        if key not in self._data:
            return None
        self._data.move_to_end(key)          # 标记为最近使用
        return self._data[key]

    def put(self, key, value) -> None:
        if key in self._data:
            self._data.move_to_end(key)
        self._data[key] = value
        if len(self._data) > self.capacity:
            self._data.popitem(last=False)   # 弹出最久未使用


class _Node:
    __slots__ = ("key", "value", "prev", "next")

    def __init__(self, key=None, value=None):
        self.key, self.value = key, value
        self.prev = self.next = None


class LRUCacheManual:
    """版本 B：哈希表 + 双向链表（带哨兵头尾，省掉边界判断）。"""

    def __init__(self, capacity: int):
        assert capacity > 0
        self.capacity = capacity
        self.map: dict = {}
        self.head, self.tail = _Node(), _Node()      # 哨兵：head.next 最新，tail.prev 最旧
        self.head.next, self.tail.prev = self.tail, self.head

    def _unlink(self, node: _Node) -> None:
        node.prev.next, node.next.prev = node.next, node.prev

    def _push_front(self, node: _Node) -> None:
        node.next = self.head.next
        node.prev = self.head
        self.head.next.prev = node
        self.head.next = node

    def get(self, key):
        node = self.map.get(key)
        if node is None:
            return None
        self._unlink(node)
        self._push_front(node)
        return node.value

    def put(self, key, value) -> None:
        node = self.map.get(key)
        if node is not None:
            node.value = value
            self._unlink(node)
            self._push_front(node)
            return
        if len(self.map) >= self.capacity:
            victim = self.tail.prev                  # 最久未使用
            self._unlink(victim)
            del self.map[victim.key]                 # 别忘了从 map 里删
        node = _Node(key, value)
        self.map[key] = node
        self._push_front(node)

五、手写 BM25 与中文 bigram 分词 ​

题目：实现 BM25 打分，并实现一个能给中文分词的分词函数。

python
"""完整可运行：BM25 + 中文 bigram 分词。

BM25 = TF 饱和项 × IDF × ...
  score(q, d) = Σ_t IDF(t) · (f(t,d)·(k1+1)) / (f(t,d) + k1·(1 - b + b·|d|/avgdl))
"""
import math
import re
from collections import Counter

_LATIN_NUM = r"[A-Za-z][A-Za-z0-9\-]*|\d+(?:\.\d+)?"
_CJK = r"[\u4e00-\u9fff]"


def tokenize(text: str) -> list[str]:
    """英文按词、数字原样、中文按二元组（不足两字退回单字）。

    ⚠️ 中文为什么不能用 \\b 切词：汉字在 Unicode 里属于「字母」，
    所以字与字之间**没有词边界**，\\b 一个都切不出来。
    例如 re.findall(r"\\w+", "探索") 得到的是整串 "探索"，
    re.findall(r"\\b\\w+\\b", "探索") 同样只有整串 —— 得不到单字。

    中文的常见做法有两类：
      a) 词典/统计分词（jieba 等）：效果更好，但引入依赖与词典；
      b) n-gram（这里用二元组）：零依赖，对 BM25 这类词频模型够用。
    本项目选 (b)：「探索」→「探索」，只有真含该词的块才命中，
    精度远高于把每个汉字当独立 token（单字的文档频率极高，IDF 接近 0）。
    """
    low = text.lower()
    toks: list[str] = re.findall(_LATIN_NUM, low)
    for run in re.findall(rf"{_CJK}+", low):
        if len(run) == 1:
            toks.append(run)
        else:
            toks.extend(run[i:i + 2] for i in range(len(run) - 1))
    return toks


class BM25:
    def __init__(self, docs: list[str], k1: float = 1.5, b: float = 0.75):
        self.k1, self.b = k1, b
        self.doc_tokens = [tokenize(d) for d in docs]
        self.doc_len = [len(t) for t in self.doc_tokens]
        self.avgdl = sum(self.doc_len) / max(1, len(self.doc_len))
        self.tf = [Counter(t) for t in self.doc_tokens]

        # df: 含该词的文档数
        df: Counter = Counter()
        for t in self.doc_tokens:
            df.update(set(t))
        n = len(docs)
        # IDF：加 0.5 平滑，并对负值取一个下限，避免极高频词给出负分
        self.idf = {t: max(0.0, math.log(1 + (n - c + 0.5) / (c + 0.5)))
                    for t, c in df.items()}
        self.n = n

    def score(self, query: str, i: int) -> float:
        s = 0.0
        dl = self.doc_len[i]
        for t in tokenize(query):
            f = self.tf[i].get(t, 0)
            if f == 0:
                continue
            denom = f + self.k1 * (1 - self.b + self.b * dl / self.avgdl)
            s += self.idf.get(t, 0.0) * f * (self.k1 + 1) / denom
        return s

    def search(self, query: str, top_k: int = 3):
        scored = [(self.score(query, i), i) for i in range(self.n)]
        scored.sort(reverse=True)
        return scored[:top_k]

六、手写 RRF 融合 ​

题目：把多路召回结果融合成一个排名。

"""完整可运行：RRF（Reciprocal Rank Fusion）。

score(d) = Σ_r 1 / (k + rank_r(d))，k 常用 60。
"""
from collections import defaultdict


def rrf_fuse(rankings: list[list[str]], k: int = 60, top_k: int = 10) -> list[tuple[str, float]]:
    """rankings: 每一路的 doc_id 列表，**已按相关性从高到低排好**。"""
    scores: dict[str, float] = defaultdict(float)
    for ranking in rankings:
        for rank, doc_id in enumerate(ranking, start=1):     # rank 从 1 开始
            scores[doc_id] += 1.0 / (k + rank)
    ordered = sorted(scores.items(), key=lambda kv: (-kv[1], kv[0]))  # 同分按 id 稳定排序
    return ordered[:top_k]


if __name__ == "__main__":

    for doc, s in rrf_fuse([dense, sparse], k=60, top_k=5):
        print(f"{doc}  {s:.6f}")
    # d1 / d3 两路都靠前 ⇒ 分数最高

面试官会追问：

Q：为什么不用加权分数融合？

A：因为它需要可比的分数，而这不成立。我的两路一个是 BM25 分数、一个是余弦相似度，量纲和分布都不同；硬加权等于引入一个需要按语料调的参数。RRF 把「调权重」换成「不需要调」，代价是丢掉了「分数差距的绝对大小」这个信息。

Q：那 RRF 有什么缺点？ A：它尊重每一路的排名，包括错的那一路。 这就是我实测崩过的原因——如果稀疏路整体跑偏，RRF 依然会给它的结果加分。所以修法不在融合公式里，而在融合之前加一个「这一路可信吗」的判据（我用的是两路 top-k 交集大小）。

Q：如果两路的 top-k 完全一样呢？

A：那融合是恒等变换——两路一致时 RRF 只是把同一份排名算两遍。这恰好是「交集大 ⇒ 可以信」直觉的来源，也说明这个判据是可以被解释的，不只是一个数字。

七、手写 top-k（堆） ​

题目：从 个数里取最大的 个，要求比全排序快。

python
"""完整可运行：三种 top-k 写法与复杂度对比。"""
import heapq
import random
import time


def topk_via_sort(nums: list[int], k: int) -> list[int]:
    """O(n log n)，最简单。CPython 的 sort 是 C 实现，常数极小。"""
    return sorted(nums, reverse=True)[:k]


def topk_via_heap(nums: list[int], k: int) -> list[int]:
    """维护大小为 k 的小顶堆：O(n log k)，额外空间 O(k)。

    为什么是小顶堆：堆顶是当前 k 个里最小的那个，
    新元素只要 > 堆顶就替换它 —— 一次比较就能淘汰大部分元素。
    """
    if k <= 0:
        return []
    if k >= len(nums):
        return sorted(nums, reverse=True)
    heap = nums[:k]
    heapq.heapify(heap)                       # O(k)
    for x in nums[k:]:
        if x > heap[0]:                       # 只有比堆顶大才需要操作
            heapq.heapreplace(heap, x)        # 弹出堆顶 + 压入，O(log k)
    return sorted(heap, reverse=True)


if __name__ == "__main__":
    random.seed(0)
    nums = [random.randint(0, 10**6) for _ in range(200_000)]
    k = 20

    a, b = topk_via_sort(nums, k), topk_via_heap(nums, k)
    assert a == b, "两种写法结果必须一致"

    # 注意：heapq.nlargest 的内部实现：当 k 相对 n 很小时用堆；否则退化为整体排序。
    # 「什么时候退化」的实现细节请以 CPython 官方文档/源码为准。
    c = heapq.nlargest(k, nums)
    assert a == sorted(c, reverse=True) or set(a) == set(c)

    t0 = time.perf_counter(); topk_via_sort(nums, k); t1 = time.perf_counter()
    t2 = time.perf_counter(); topk_via_heap(nums, k); t3 = time.perf_counter()
    print(f"全排序 : {t1 - t0:.4f}s")
    print(f"小顶堆 : {t3 - t2:.4f}s")

八、手写 ReAct 循环 ​

题目：写出一个 ReAct 循环：模型输出思考与动作，执行工具，把结果回填，直到给出最终答案。

python
"""完整可运行（用假模型，不需要 API Key）。

ReAct 循环的骨架：观察历史 → 决定下一步 → 执行工具 → 把结果写回历史 → 再判断。
终止条件必须是**多类**的，不能只靠「模型说它完成了」。
"""
import json
import re
from dataclasses import dataclass, field


@dataclass
class Step:
    thought: str
    action: str | None = None
    action_input: dict = field(default_factory=dict)
    observation: str = ""


ACTION_RE = re.compile(
    r"Thought:\s*(?P<thought>.*?)\s*"
    r"Action:\s*(?P<action>[\w\-]+)\s*"
    r"Action Input:\s*(?P<ainput>\{.*?\})\s*$",
    re.S,
)
FINAL_RE = re.compile(r"Final Answer:\s*(?P<answer>.+)", re.S)


def parse_model_output(text: str) -> dict:
    """解析模型的输出。**永不抛异常**（解析失败是预期内的情况）。"""
    m = FINAL_RE.search(text)
    if m:
        return {"type": "final", "answer": m.group("answer").strip()}
    m = ACTION_RE.search(text)
    if not m:
        return {"type": "unparsable", "raw": text[:200]}
    try:
        args = json.loads(m.group("ainput"))
        if not isinstance(args, dict):
            raise ValueError("Action Input 必须是 JSON 对象")
    except (json.JSONDecodeError, ValueError) as e:
        return {"type": "bad_args", "error": str(e), "action": m.group("action")}
    return {
        "type": "action",
        "thought": m.group("thought").strip(),
        "action": m.group("action"),
        "action_input": args,
    }


def run_react(question: str, model_fn, tools: dict, *, max_steps: int = 6,
              max_parse_failures: int = 3, max_tool_failures: int = 3) -> dict:
    """ReAct 主循环。返回 {answer, steps, stop_reason}。

    三类终止条件：
      1) 成功终止：模型给出 Final Answer
      2) 预算终止：步数上限 / 解析失败上限 / 工具失败上限
      3) 异常终止：解析连续失败或工具连续失败（也算预算，但语义不同）
    """
    history: list[Step] = []
    parse_failures = tool_failures = 0

    for step_no in range(1, max_steps + 1):
        prompt = render(question, history)
        raw = model_fn(prompt)                     # 真实实现：带上工具 schema 调模型
        parsed = parse_model_output(raw)

        if parsed["type"] == "final":
            return {"answer": parsed["answer"], "steps": history, "stop_reason": "final"}

        if parsed["type"] in ("unparsable", "bad_args"):
            parse_failures += 1
            # 不炸：把错误当成一次 observation 回给模型，让它改
            history.append(Step(
                thought="",
                observation=f"输出无法解析（{parsed.get('error', '格式不符')}），"
                            f"请严格按 Thought / Action / Action Input 格式重写。",
            ))
            if parse_failures >= max_parse_failures:
                return {"answer": None, "steps": history, "stop_reason": "parse_budget"}
            continue

        action, args = parsed["action"], parsed["action_input"]
        if action not in tools:
            tool_failures += 1
            history.append(Step(
                thought=parsed["thought"],
                action=action,
                action_input=args,
                observation=f"没有名为 {action} 的工具。可用工具：{sorted(tools)}",
            ))
            if tool_failures >= max_tool_failures:
                return {"answer": None, "steps": history, "stop_reason": "tool_budget"}
            continue

        try:
            obs = str(tools[action](**args))
        except TypeError as e:                     # 参数不合法：预期内，回给模型
            obs = f"参数错误：{e}。请检查参数名与类型。"
            tool_failures += 1
        except Exception as e:                     # 程序错误：也要记录，但语义不同
            obs = f"工具执行失败：{type(e).__name__}: {e}"
            tool_failures += 1

        history.append(Step(thought=parsed["thought"], action=action,
                            action_input=args, observation=obs))
        if tool_failures >= max_tool_failures:
            return {"answer": None, "steps": history, "stop_reason": "tool_budget"}

    return {"answer": None, "steps": history, "stop_reason": "max_steps"}


def render(question: str, history: list[Step]) -> str:
    """把问题与历史渲染成下一轮的 prompt（真实实现里还要拼工具 schema 与 system）。"""
    lines = [f"Question: {question}"]
    for s in history:
        if s.thought:
            lines.append(f"Thought: {s.thought}")
        if s.action:
            lines.append(f"Action: {s.action}")
            lines.append(f"Action Input: {json.dumps(s.action_input, ensure_ascii=False)}")
        lines.append(f"Observation: {s.observation}")
    return "\n".join(lines)

        return ('Thought: 需要查天气。\nAction: get_weather\n'

关键点讲解：

  • 三类终止条件必须都在：成功（final）、预算（步数/解析次数/工具失败次数）、异常（连续解析失败与连续工具失败——它们语义不同，分开计数才能区分「模型不会用工具」和「工具本身坏了」）。

面试官会追问：

Q：你怎么防止它死循环？

A：四类预算而不是一类。 轮次上限、token 上限、时间上限、成本上限——只设轮次不够，因为一轮里可能塞进巨大的上下文或者调很多次工具。而且预算要能被打断：检查点要落在每一轮结束时，这样超预算时能干净地退出并把中间结果交出来。

Q：模型一直给同一个工具调同一个参数怎么办？

A：这是「循环检测」问题，和预算不是一回事。我的做法是对「工具名 + 归一化参数」做重复检测，连续重复就注入一条提示（告诉它「你刚刚已经查过这个了，结果是什么」），再重复就终止。关键是这个「重复」要能在 trace 里看到，不然线上只会看到一个转不完的请求。

Q：你怎么测试这些终止条件？

A：构造必然无法完成的场景，断言它在规定轮次内停下来。 比如一个永远返回「没查到」的工具、一个永远输出非法格式的假模型。这类断言的价值在于「它能失败」——如果我把 max_steps 去掉，它必须变红。我的项目里有一条相关教训：v1 有 11 个自检入口从来没有被测试框架执行过，代码写了但没人跑。「写下」和「执行」是两件事。

常见错误答法：

错误后果
只有 while True + 模型自己判断结束线上一定会出现转不完的请求
只设轮次上限一轮可能烧掉大量 token 或时间
解析失败直接抛异常模型格式抖一下就整条链路失败
把参数错误和工具故障混为一谈分不清该重试还是该熔断
不记录中间步骤出问题无法复盘，也无法评测过程

九、手写工具注册装饰器 + 入参校验 ​

题目：写一个 @tool 装饰器，从函数签名与类型注解生成工具描述，并在调用前做入参校验。

python
"""完整可运行：极简工具注册 + 入参校验（零第三方依赖）。

设计要点：
  1) 从类型注解生成 JSON schema（真实项目里请以 pydantic / 官方 SDK 文档为准）
  2) 校验失败**不抛异常**，而是返回一条可读的错误，让 Agent 有机会改参数
  3) 缺参数、多参数、类型错 —— 三类都要给具体信息
"""
import inspect
from typing import Any, Callable, get_type_hints

_TYPE_MAP = {str: "string", int: "integer", float: "number", bool: "boolean",
             list: "array", dict: "object"}


class ToolRegistry:
    def __init__(self) -> None:
        self.schemas: dict[str, dict] = {}
        self.funcs: dict[str, Callable] = {}

    def tool(self, name: str | None = None, description: str | None = None):
        def deco(fn: Callable) -> Callable:
            fn_name = name or fn.__name__
            hints = get_type_hints(fn)
            sig = inspect.signature(fn)

            props: dict[str, dict] = {}
            required: list[str] = []
            for pname, p in sig.parameters.items():
                ann = hints.get(pname)
                props[pname] = {"type": _TYPE_MAP.get(ann, "string")}
                if p.default is inspect.Parameter.empty:
                    required.append(pname)

            self.schemas[fn_name] = {
                "name": fn_name,
                # description 优先用显式传入的，否则取 docstring 的第一段
                "description": description or (inspect.getdoc(fn) or "").strip().split("\n\n")[0],
                "parameters": {"type": "object", "properties": props, "required": required},
            }
            self.funcs[fn_name] = fn
            return fn
        return deco

    def call(self, name: str, args: dict[str, Any]) -> str:
        """执行工具。**永不抛异常**：错误作为可读文本返回。"""
        if name not in self.funcs:
            return f"错误：没有名为 {name} 的工具。可用工具：{sorted(self.funcs)}"

        schema = self.schemas[name]["parameters"]
        missing = [p for p in schema["required"] if p not in args]
        if missing:
            return f"错误：缺少必需参数 {missing}。参数说明：{schema['properties']}"

        extra = [k for k in args if k not in schema["properties"]]
        if extra:
            # 多传参数要明确拒绝，而不是静默忽略 —— 静默忽略会让模型一直带着无效参数重试
            return (f"错误：不支持的参数 {extra}。"
                    f"只接受 {sorted(schema['properties'])}")

        expected = {k: v["type"] for k, v in schema["properties"].items()}
        py_types = {v: k for k, v in _TYPE_MAP.items()}
        for k, v in args.items():
            want = expected[k]
            # bool 是 int 的子类，所以必须先判 bool，否则 True 会被当成合法整数
            if want == "integer" and (isinstance(v, bool) or not isinstance(v, int)):
                return f"错误：参数 {k} 需要整数，实际是 {type(v).__name__}"
            if want == "string" and not isinstance(v, str):
                return f"错误：参数 {k} 需要字符串，实际是 {type(v).__name__}"
            _ = py_types  # 需要更严格的类型映射时再展开

        try:
            return str(self.funcs[name](**args))
        except TypeError as e:
            return f"错误：调用参数不匹配（{e}）"
        except Exception as e:
            return f"工具执行失败：{type(e).__name__}: {e}"

        """查询订单。"""
        return f"订单 {order_id}：已发货（含物流={with_logistics}）"

    print(reg.call("query_order", {"order_id": "A1", "x": 1}))# 多参数
    print(reg.call("no_such_tool", {}))                       # 工具不存在

面试官会追问：

Q：参数校验失败为什么要回给模型，而不是直接失败？

A：因为这是 Agent 自我纠错的主要方式。校验是确定性的，所以它不是「再试一次碰运气」，而是「带着明确的修正线索重试」。我的项目里就是这么做的：校验失败不炸图，错误被当成工具结果写回状态。

Q：会不会掩盖真正的 bug？

A：会——但可以用「错误的类别」把两者分开。参数不合法走「回给模型」，程序错误（字段名写错、库版本不匹配）一律当异常。这个区分必须显式写出来，否则「不炸图」这个设计就会变成「bug 藏起来」。我踩过一个非常典型的例子：getattr(llm, "model") 这个写法在同一个文件的两处逐字复发了同一个错误——它拿不到真实值就返回默认值，不报错但结果是错的。

Q：工具描述里最重要的是什么？

A：参数名要自解释（date_range_start 优于 d1）、描述要说清「什么时候用」而不只是「它是什么」、返回体要裁剪。第三点尤其容易被应届生忽略：工具一次返回十万行 JSON 会撑爆上下文，还会让模型失焦。工具契约设计是 Agent 应用里最像「接口设计」的部分，值得单独当一题准备。

常见错误答法：

错误后果
校验失败抛异常模型格式抖一下就整条链断掉
错误信息只说「参数错误」模型无法修正，会一直重试同样的错误
静默忽略多余参数模型带着无效参数反复重试
用 bool 通过 int 校验True 被当成合法整数
工具描述写成函数名直译模型不知道该在什么场景调用它

十、手写 SSE 流式端点 ​

题目：用 FastAPI 写一个 SSE 流式端点，并说明需要哪些响应头。

python
"""完整可运行：FastAPI SSE 流式端点（用 TestClient 自测，不需要起服务）。

依赖：fastapi + uvicorn（TestClient 需要 httpx）。具体版本以官方文档为准。
"""
import json
import time
from typing import Iterator

from fastapi import Depends, FastAPI, Header, Request
from fastapi.responses import JSONResponse, StreamingResponse

app = FastAPI()

DEV_API_KEY = "dev-key"          # 真实项目：从环境变量注入，绝不写进代码

# SSE 的三个必需响应头 —— 少一个就会出现「本地好好的、上 Nginx 后不流式」
SSE_HEADERS = {
    "Cache-Control": "no-cache",      # 否则中间层/CDN 缓存住整个流
    "X-Accel-Buffering": "no",        # 否则 Nginx 默认 proxy_buffering 会缓冲，首字从 300ms 变 30s
    "Connection": "keep-alive",       # 否则某些代理按短连接处理，长回答被截断
}


def sse_frame(event: str, data: dict) -> str:
    """SSE 帧格式：`event: X\\n` + `data: JSON\\n` + 空行结尾。"""
    return f"event: {event}\ndata: {json.dumps(data, ensure_ascii=False)}\n\n"


@app.get("/health")
def health() -> dict:
    """liveness：只回答「进程活着」。⚠️ 不要拿它当「可以接流量」。"""
    return {"status": "alive"}


@app.get("/health/ready")
def ready() -> JSONResponse:
    """readiness：回答「能不能接流量」。真实项目里应检查最依赖的那次真实调用。"""
    warm_done = True          # 玩具值；真实实现看预热状态与依赖可用性
    if not warm_done:
        return JSONResponse({"ready": False, "reason": "模型尚未加载完成"}, status_code=503)
    return JSONResponse({"ready": True})


def guard(request: Request, x_api_key: str | None = Header(default=None, alias="X-API-Key")):
    """前置检查。**顺序不能换：鉴权必须在限流之前。**

    未授权的请求不该消耗限流额度 —— 否则攻击者用无权请求就能把合法用户挤出去，
    限流就从保护机制变成了拒绝服务放大器。
    """
    if (x_api_key or "") != DEV_API_KEY:
        raise ValueError("unauthorized")      # 真实实现：返回 401，且不消耗限流额度
    return {"client": getattr(request.client, "host", "unknown")}


@app.post("/ask/stream")
def ask_stream(payload: dict, ctx: dict = Depends(guard)) -> StreamingResponse:
    question = str(payload.get("question", ""))

    def gen() -> Iterator[str]:
        # 首帧就把 trace id 之类可核对的信息回给客户端（真实实现用响应头）
        yield sse_frame("start", {"question": question})
        answer = f"关于「{question}」的回答"
        for i, ch in enumerate(answer):
            if i == 0:
                yield sse_frame("first_token", {"t": round(time.time(), 3)})
            yield sse_frame("delta", {"text": ch})
        yield sse_frame("done", {"reason": "stop"})

    return StreamingResponse(gen(), media_type="text/event-stream", headers=SSE_HEADERS)

A：看用户对首字延迟的敏感度。人在等一个回答时，首字延迟是体验的关键；而批量任务对结构化输出的可靠性更敏感。这是产品取舍，不是技术优劣。

十一、手写滑动窗口限流 ​

题目：实现一个每分钟 N 次的限流器，并说明它放在鉴权的哪一侧。

python
"""完整可运行：滑动窗口限流 + 「鉴权在限流之前」的说明。

为什么不用「计数器 + 取整分钟」：
  取整窗口在边界处会放行 2 倍流量 —— 59 秒发满 60 个、61 秒再发满 60 个，
  两秒内实际过了 120 个。滑动窗口用 20 行就避免了这个问题。
"""
import threading
import time
from collections import deque


class RateLimiter:
    def __init__(self, per_min: int) -> None:
        assert per_min > 0
        self.per_min = per_min
        self._hits: dict[str, deque[float]] = {}
        self._lock = threading.Lock()      # ⚠️ Web 服务里 get 和 put 会被多线程调用

    def allow(self, key: str, now: float | None = None) -> tuple[bool, int]:
        """返回 (是否放行, 剩余额度)。"""
        now = now if now is not None else time.time()
        with self._lock:
            dq = self._hits.setdefault(key, deque())
            while dq and now - dq[0] > 60.0:      # 弹出窗口外的旧时间戳
                dq.popleft()
            if len(dq) >= self.per_min:
                return False, 0
            dq.append(now)
            return True, self.per_min - len(dq)


if __name__ == "__main__":
    rl = RateLimiter(per_min=3)
    t = 1000.0
    for i in range(4):
        print(f"t={t + i * 1.0:.0f}s", rl.allow("ip-a", now=t + i * 1.0))
    # 第 4 次被拒 —— 窗口内已有 3 次

    print("窗口滑出后:", rl.allow("ip-a", now=t + 61.0))   # True
    print("另一个 key 不受影响:", rl.allow("ip-b", now=t)) # True

面试官会追问：

Q：多实例部署怎么办？

A：内存版直接失效。两个方向：用共享存储（Redis 计数 + 过期）或网关层限流。实践上最好是两层——网关挡粗粒度的洪峰，应用做按用户/租户的精细配额。代价要说清：引入 Redis 就是把限流变成一个有外部依赖的功能，Redis 挂了限流要么失效要么变成全拒绝，这个降级策略必须事先定。

Q：限流的 key 用什么？

A：我实际用的是客户端 IP，但要主动说清它的两个边界：NAT 后的多个用户会共享 IP（可能误伤）、IP 可以伪造。更合理的维度是 API Key 或用户 ID，IP 只作为无身份请求的兜底。

Q：限流能防住攻击吗？

A：不能，它防的是误用和失控，不是攻击。 真正的安全边界是鉴权 + 配额（按账号计的累计用量）——配额是累计量，换 IP 也没用。而且要说清两者的区别：限流防「太快」（429，可退避重试），配额防「太多」（402，重试无用）。客户端必须按状态码分流，否则会把不可重试的错误无脑重试。

十二、手写幂等键的生成与去重 ​

题目：为写操作生成幂等键并实现去重，说明为什么不能直接用请求体的 hash。

python
"""完整可运行：幂等键 + 结果回放。"""
import hashlib
import json
from typing import Any, Callable

# 不影响业务语义、必须被剔除的字段（噪声字段）
NOISE_FIELDS = {"timestamp", "ts", "trace_id", "request_id", "nonce", "client_time"}


def idem_key(tool: str, args: dict[str, Any], *, user: str = "", scope: str = "") -> str:
    """幂等键 = f(业务语义字段, 作用域)。

    ⚠️ 为什么不能直接 hash(请求体)：
       请求体里含 timestamp / trace_id / nonce 这类**不影响业务语义**的字段。
       body 变一个字节键就变 ⇒ 重试会被当成新请求 ⇒ 幂等静默失效。
       而且它**不会报错**，只会静默地重复执行副作用。
    """
    clean = {k: v for k, v in args.items() if k not in NOISE_FIELDS}
    payload = json.dumps(
        {"tool": tool, "args": clean, "user": user, "scope": scope},
        sort_keys=True,                # 键序稳定：否则同样内容算出不同键
        ensure_ascii=False,
        default=str,                   # 非 JSON 原生类型降级成字符串，避免抛异常
        separators=(",", ":"),         # 去掉空格，保证相同内容字节一致
    )
    return hashlib.sha256(payload.encode("utf-8")).hexdigest()[:32]


class IdempotencyStore:
    """进程内幂等存储。⚠️ 有效范围仅「同进程同参数」；跨进程需外部存储。"""

    def __init__(self) -> None:
        self._done: dict[str, Any] = {}

    def run_once(self, key: str, fn: Callable[[], Any]) -> tuple[Any, bool]:
        """返回 (结果, 是否命中已有结果)。**只在成功后登记**。"""
        if key in self._done:
            return self._done[key], True          # 回放，不重新执行
        result = fn()                             # 失败会抛异常 ⇒ 不会登记 ⇒ 可安全重试
        self._done[key] = result
        return result, False


if __name__ == "__main__":
    store = IdempotencyStore()
    calls = {"n": 0}

    def create_ticket(order_id: str, reason: str) -> dict:
        calls["n"] += 1
        return {"ticket_id": f"T{calls['n']:03d}", "order_id": order_id, "reason": reason}

    a1 = {"order_id": "A1001", "reason": "未收到货", "timestamp": 1730000000, "trace_id": "t1"}
    a2 = {"order_id": "A1001", "reason": "未收到货", "timestamp": 1730009999, "trace_id": "t2"}

    k1 = idem_key("create_ticket", a1, user="u1")
    k2 = idem_key("create_ticket", a2, user="u1")
    print("噪声字段变化后键是否相同:", k1 == k2)          # True

    r1, dup1 = store.run_once(k1, lambda: create_ticket(**{k: v for k, v in a1.items()
                                                           if k not in NOISE_FIELDS}))

关键点讲解：

  • 为什么不能 hash(请求体)：timestamp、trace_id、nonce 这类字段一变，键就变了，重试被当成新请求。这个错误最阴的地方是它不报错——只在事后统计里表现为「同一个订单建了三张工单」。
  • 三步设计：① 选业务语义字段（用户、动作、业务主键）；② 归一化（剔噪声、sort_keys、统一分隔符、非原生类型降级）；③ 定作用域（键在哪个范围内唯一）。
  • sort_keys=True + 固定 separators：保证同一份内容算出同一个键。字典顺序在 Python 里是插入序，不排序的话两次构造顺序不同就会算出不同键。
  • 只在成功后登记：失败也登记的话，用户重试会拿到一个「看起来成功但实际没做」的结果——比重复执行更糟。
  • 有效期与清理：进程内字典会无限增长。真实实现要带 TTL，并且要说清 TTL 与业务重试窗口的关系——TTL 比用户的重试窗口短，幂等就漏了。

面试官会追问：

Q：幂等和人工确认解决的是同一个问题吗？

A：不是，而且必须一起讲。 幂等解决「重复」——重试导致的重复副作用；人工确认解决「误操作」——包括被注入诱导的操作。攻击者想达到的是误操作，所以真正兜住它的是人工确认；幂等只是防止确认后的重试把一次操作变成两次。

Q：你的幂等实现有效范围是什么？

A：「同进程同参数」范围内被验证过——实测同一参数二次调用返回同一个 ticket、审计记录 1→1。跨进程和跨 thread_id 的碰撞没有验证，它在我的未实测清单上，有明确的验收条件。这一条必须主动说：把作用域说成全局的，是这题最容易犯的过度承诺。

我也能推进方向：换成外部存储（数据库唯一索引或 Redis）并做并发压测，断言「N 个并发同键请求只产生 1 次副作用」。

Q：为什么不用数据库的自增或唯一索引直接做？

A：可以，而且那是更可靠的做法——用唯一索引让数据库保证唯一性，比在应用层做去重更稳（应用层多实例时会失效）。代价是它把「幂等」变成了「一次数据库写入」，需要处理唯一键冲突的错误路径。我现在的实现是应用层版本，因为它在进程内零依赖，但它不是终点。

常见错误答法：

hash(请求体) 当键噪声字段导致幂等静默失效

十三、手写结构感知切块 ​

题目：按 Markdown 标题层级切块，并保证表格不被拆散。

python
"""完整可运行：结构感知切块。

两条硬约束：
  1) 按标题层级切 —— 保持语义单元完整
  2) **绝不拆散表格** —— 表头与所有数据行必须在同一个切片里
"""
import re

HEADING_RE = re.compile(r"^(#{1,6})\s+(.*)$")


def _is_table_row(line: str) -> bool:
    return line.strip().startswith("|")


def _is_table_sep(line: str) -> bool:
    s = line.strip()
    return bool(s) and set(s) <= set("|-: ") and "-" in s


def split_blocks(text: str) -> list[dict]:
    """把正文切成块。表格是**不可分割的原子块**。"""
    lines = text.splitlines()
    blocks: list[dict] = []
    heading_path: list[str] = []
    buf: list[str] = []
    i = 0

    def flush() -> None:
        if buf:
            body = "\n".join(buf).strip()
            if body:
                blocks.append({"heading_path": list(heading_path), "type": "text", "text": body})
            buf.clear()

    while i < len(lines):
        line = lines[i]
        m = HEADING_RE.match(line)
        if m:
            flush()
            level, title = len(m.group(1)), m.group(2).strip()
            heading_path = heading_path[: level - 1] + [title]
            blocks.append({"heading_path": list(heading_path), "type": "heading", "text": title})
            i += 1
            continue

        # 表格：从表头行开始，一直吃到不再是表格行
        if _is_table_row(line) and i + 1 < len(lines) and _is_table_sep(lines[i + 1]):
            flush()
            table_rows = [line, lines[i + 1]]
            i += 2
            while i < len(lines) and _is_table_row(lines[i]):
                table_rows.append(lines[i])
                i += 1
            blocks.append({"heading_path": list(heading_path), "type": "table",
                           "text": "\n".join(table_rows)})
            continue

        buf.append(line)
        i += 1

    flush()
    return blocks


def chunk(text: str, max_chars: int = 400, overlap_blocks: int = 0) -> list[dict]:
    """把块打包成切片。

    ⚠️ 表格块**永远独占切片**（或与同一标题下的文本合并时整体考虑，
    但绝不切开）—— 表头和数据行分开，读者和模型都读不出含义。
    """
    blocks = split_blocks(text)
    chunks: list[dict] = []
    cur: list[dict] = []
    cur_len = 0

    def close() -> None:
        nonlocal cur, cur_len
        if not cur:
            return
        chunks.append({
            "heading_path": cur[0]["heading_path"],
            "text": "\n\n".join(b["text"] for b in cur),
            "has_table": any(b["type"] == "table" for b in cur),
        })
        # 需要重叠时，保留最后 N 个块（注意：绝不把表格切一半留在重叠区）
        keep = [b for b in cur[-overlap_blocks:] if b["type"] != "table"] if overlap_blocks else []
        cur, cur_len = list(keep), sum(len(b["text"]) for b in keep)

    for b in blocks:
        if b["type"] == "heading":
            continue
        blen = len(b["text"])
        if b["type"] == "table":
            # 表格先收尾独立成片，再单独成片
            close()
            cur, cur_len = [b], blen
            close()
            continue
        if cur_len + blen > max_chars and cur:
            close()
        cur.append(b)
        cur_len += blen
    close()
    return chunks


if __name__ == "__main__":
    md = """# 3 方法

## 3.1 总体流程
我们采用两阶段方法，先检索再生成。

| 模型 | 参数量 | R@5 |
|---|---|---|
| A | 7B | 0.72 |
| B | 13B | 0.81 |

## 3.2 实现细节
精排使用交叉编码器，候选数为 20。
"""
    out = chunk(md, max_chars=120)
    for i, c in enumerate(out):
        rows = c["text"].count("\n|") + c["text"].count("|") // 100
        print(f"--- 切片 {i} | 标题: {' > '.join(c['heading_path'])} | 含表: {c['has_table']}")
        print(c["text"])
        if c["has_table"]:
            assert "参数量" in c["text"] and "0.81" in c["text"], "表头与数据行必须同片"
    print("表格完整性断言通过")

  • 这不是理论问题，我的项目在这上面翻过车：PDF 抽取会把分情形公式线性化（一个分段函数被抽成一行乱序文本，符号还被识别错）；更严重的是清洗规则曾经把表格里的整数单元格当成页码删掉，导致表格类问题永久答不对——因为文档里那个数字已经不存在了。所以现在的做法是：表格类事实优先引用正文，抽取阶段就标记表格块。
  • 元数据要一起切进去：页码、章节标题、文档标识。这些字段是后续引用溯源和排障的依据——没有它们，用户报「答案错了」时你无法定位到是哪一块。

面试官会追问：

Q：你怎么知道切块策略变好了？

A：要有一个与切片无关的评测口径，否则你是在「换尺子比数字」。我踩过的坑是：把 512 换成 1024 之后，粗切会把相邻的两个 ground truth 块合并成一块，于是 gt 从 36 块降到 30 块——分母变小，Recall 自然变高。这属于典型的「换尺子后比数字」。

Q：那正确的做法是什么？

A：用一个不依赖切片边界的证据口径——我的做法是统计「top-k 块里能完整包含这个事实探针的比例」（覆盖率）加上探针级的 MRR。关键是探针是独立于切片方式定义的，这样不同配置之间才可比。

Q：如果表格被拆散了，你怎么发现？

A：写一条能失败的断言：切片里如果出现表格分隔行，那么片段内必须同时包含表头；出现数据行则必须能追溯到同片的表头。我在上面的代码里就写了这条断言（assert "参数量" in c["text"] and "0.81" in c["text"]）。

这类断言的通用价值是：它会在你改切块逻辑的那一刻失败，而不是等到用户投诉答案不对。「只验没报错」等于没验——我的中文 BM25 静默返回空、清洗规则删掉表格数字，都是「不报错但结果错」的活例子。

常见错误答法：

错误后果
只按固定长度切标题与正文分离、表格被切断
表格和数据行分开单看一行数据无法理解
不带元数据引用无法定位，排障无依据
用「感觉更好了」判断切块没有可比口径，可能在换尺子比数字
不做「表格完整性」断言抽取/清洗阶段的静默损坏不会被发现

十四、并发：asyncio.gather vs ThreadPoolExecutor vs 多进程 ​

判据表（背这张，比背结论有用） ​

任务类型首选理由
大量 IO 等待（网络、磁盘、DB）asyncio.gather / 异步单线程事件循环，开销最小，不占线程
阻塞式 IO（只有同步库可用）ThreadPoolExecutor阻塞调用会释放 GIL，线程能真正并行等待
CPU 密集（纯 Python 计算）多进程GIL 让线程无法并行纯 Python 字节码
CPU 密集（numpy / 科学计算 / 已释放 GIL 的 C 扩展）线程池也够这类库内部释放 GIL，线程可并行

关键点讲解：GIL 到底限制了谁 ​

GIL 保证同一时刻只有一个线程执行 Python 字节码。 它限制的是「纯 Python 计算」，不限制两件事：

  1. IO 等待：time.sleep、网络读写这些阻塞调用会主动释放 GIL，所以线程在等 IO 时是并行的。
  2. 已经释放 GIL 的 C 扩展：numpy 的大矩阵运算、zlib 的压缩解压等，在 C 层循环里会放开 GIL。

所以「Python 多线程没用」这句话是错的，但「Python 多线程对纯计算没用」是对的。 判据是：这段代码在 CPU 上跑的时候，GIL 是握着还是放开的。

一个必须讲的真实例子（我自己的基准测试）：

我写过一个并发瓶颈探测脚本，测「多线程对一个 CPU 密集任务有没有加速」。第一版结论是加速比只有 1.02 倍——看起来完美验证了「GIL 让并行毫无收益」。

但那个结论是错的。 真实原因是：我的被测函数在每一次调用内部重建了一个 52 MB 的大 bytes 对象（块 * 大整数），这段构造本身持有 GIL，把并行收益掩盖掉了。把块移到模块级预建之后，同一测量的加速比变成 6.41 倍（并发 8、3 次取中位数）。

教训有两条，都要能说出来：

  1. 基准测试的脚手架本身会污染结论 —— 你要测的是「函数体的并行收益」，不是「对象构造的串行开销」。
  2. 「快」和「慢」的结论不能只看一个数 —— 同一份代码，改一个变量（块在哪构造）就从「无收益」变成「接近线性」。所以性能实验必须先验证「被测函数真的在跑、且测的就是你想测的那部分」。我另外还有一个同类失误：某个函数定义了但从没被调用，于是那行 0.047 秒测的是空函数。

同一条纪律的推论：如果一段 CPU 密集逻辑无法避免地包含大量 Python 层循环，那线程池不会给你加速——这时候要么改写成能释放 GIL 的形式（用 numpy 之类），要么上多进程。

追问链：并发模型的选择 ​

Q：你的 RAG 服务里哪些地方用了并发？

A：检索侧：双路召回（向量 + 稀疏）是并行的，因为它们互不依赖；精排是串行的，因为它依赖两路的融合结果；多个候选块的精排打分理论上可以并行，但它整体在 CPU 上，属于要判断的那类——这正是我用基准测试去确认的对象。

Q：那你怎么判断某一段该不该并行？

A：三步。① 先确认它是不是瓶颈（用延迟分解，我的是精排，不是 LLM）；② 再确认它并发时会不会真的变快（写一个能失败的基准断言，并且保证脚手架不污染结论）；③ 最后才动手。这三步的顺序不能反——先测再改，有可能改完就不需要改了。

我还会补一句边界：并发不是越多越好。我的压测显示并发从 1 涨到 8 时，P50 从 7.5 秒涨到 45.8 秒，而 RPS 只从 0.15 涨到 0.40——延迟涨 6 倍只换 2.7 倍吞吐，说明资源已经饱和，再加并发只是让所有人一起变慢。所以我把并发上限设在第二档（2）而不是往上堆。

Q：这是 asyncio 会更好吗？

A：不会。 我的基准实验里有一条对照断言：asyncio 卸载到线程池的那一档和直接用线程池的那一档表现基本相同（差 < 40%）——因为它们的机制是一样的（都是把阻塞调用丢给线程）。「为了简历写 asyncio 而改并发」是明确被我的实测否掉的一个动机。

常见错误答法 ​

错误后果
「Python 多线程完全没用」忽略了阻塞调用与 C 扩展会释放 GIL
「CPU 密集就直接上多进程」没先确认它是不是瓶颈；多进程有序列化与启动开销
用 asyncio.gather 包阻塞调用事件循环被卡住，所有请求一起变慢
基准测试不含「被测函数真的在跑」的断言测到空函数或掺入了构造开销
只看加速比不看资源饱和并发往上堆，延迟线性涨、吞吐饱和

十五、经典算法题清单（只给思路，不写题解） ​

这一页的重点在 AI 相关手撕，所以下面只列题目和一句话思路，用来在面试前快速过一遍题型。 完整题解请到 L0 算法与复杂度——那里有判定路径和复杂度分析。

链表（考「指针操作 + 边界」，最容易在空链表/单节点上翻车） ​

题目一句话思路
反转链表三指针迭代：prev / cur / nxt，先存 nxt 再改 cur.next
合并两个有序链表哑节点 + 尾指针，收尾时直接接上剩余链
环形链表检测快慢指针；追上了有环。找入环点：相遇后一个指针回头，同步走
K 个一组反转先数够不够 k 个，不够就原样返回——「不够就不动」是这题的关键分支
复制带随机指针的链表哈希表映射旧节点→新节点，两遍扫描

二叉树（考「递归状态设计」，重点是「要向上返回什么」） ​

题目一句话思路
层序遍历队列；每轮先记下当前层的节点数，才能分层
最大深度 / 平衡判断递归返回深度；平衡要在「发现不平衡」时用哨兵值短路
最近公共祖先后序遍历：左右子树各自找到目标就说明当前是 LCA
二叉树的最近路径和 / 直径返回给父节点的值 ≠ 全局答案，这两个要分开维护
验证 BST递归传上下界，比「只比父子」正确

动态规划（考「状态定义」，状态定义对了就成功一半） ​

题目一句话思路
爬楼梯 / 斐波那契一维 DP，滚动变量省空间
最长递增子序列 是 DP； 用「维护每种长度下的最小结尾」+ 二分
编辑距离二维 DP，三种操作对应三个转移方向
背包0-1 背包倒序枚举容量（避免同一物品用两次）
最长公共子序列二维 DP，相同时取对角 +1，否则取上/左的最大

栈与队列（考「单调性」这个技巧） ​

题目一句话思路
有效括号栈；左括号入栈，右括号必须匹配栈顶
每日温度 / 下一个更大元素单调栈：让栈里保持单调递减，遇到更大的就弹栈并结算
滑动窗口最大值单调队列：队头是当前窗口最大值；出窗口时从队头弹出
用栈实现队列两个栈，一个管入一个管出，出栈空了再把入栈倒过去

二分（考「边界」，这是最容易写出死循环的一类） ​

题目一句话思路
标准二分查找明确区间是闭还是半开，然后全程不变
搜索旋转排序数组每次判断哪一半是有序的，再决定往哪边找
寻找峰值比较 nums[mid] 与 nums[mid+1] 决定往哪边收缩（不需要有序）
二分答案（如最小化最大值）把「求最优值」转成「判断可行性」，这是二分答案的通用套路

字符串（考「滑动窗口 + 哈希」） ​

题目一句话思路
无重复字符的最长子串滑动窗口 + 哈希记录上次出现位置
最小覆盖子串滑动窗口 + 需要计数器，用「还需要多少个字符」判断是否满足
字符串相加 / 大数乘法从低位往上逐位算，进位单独处理
最长回文子串中心扩展（、好写）或 Manacher（面试一般不用）
