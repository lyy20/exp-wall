如何使用这个站 ​

一、启动与访问 ​

在 D:\AI-Learning 目录下双击 start.cmd，或者手动跑：

bash
cd D:\AI-Learning
npm run docs:build     # 构建静态站（约 4 秒）
npm run serve          # 起本地服务，默认 http://localhost:3000

想边写边看效果，用热更新模式：

bash
npm run docs:dev       # http://localhost:5173

为什么不是纯静态

普通的 VitePress 静态站不能调用 DeepSeek（API Key 会暴露在浏览器里）。这个站在静态站外面套了一层本地 Node 服务：

浏览器 ──► Express:3000 ──► DeepSeek API
             │
             ├─ 静态托管 docs/.vitepress/dist
             ├─ BM25 站内检索（我的笔记全文）
             └─ 笔记落盘 docs/inbox/*.md

API Key 只存在服务端的 .env 里，永远不进浏览器。

二、右侧助教怎么用 ​

页面右下角的悬浮按钮打开对话助手。它不是一个通用聊天机器人，它是一个读过这个站所有笔记的资深 AI 开发工程师 + 校招技术面试官。

它能做四件事：

用法怎么问它会怎么答
讲原理「LangGraph 的 checkpointer 到底存了什么？」先给结论，再讲机制，能画的直接给 Mermaid 图
对项目「我 YYHelp 里那个中文 BM25 失效，面试官会怎么追问？」挂靠站内对应页面，给追问链与答法
出题考我「考我三题 RAG 检索，从易到难」按面试官视角出题，我答完它点评
存笔记答得好的内容点「存为笔记」写进 docs/inbox/，自动重建站点并进侧栏

它不干什么

  • 不编造 API 名、参数默认值、版本号 —— 拿不准它会直接说拿不准
  • 不替我美化经历或编数字 —— 面试被追问三层会崩
  • 不设置对话条数上限，本地用的东西不需要防

三、检索习惯 ​

站内搜索（左上角或 Ctrl+K）用的是中文友好的 BM25，不是简单字符串匹配：

  • 中文按 bigram 切，所以「混合检索」和「检索混合」都能命中
  • 标题命中加权，所以标题里带这个词的页面排前面
  • 同一个文件最多出两个片段，避免一个长页面刷屏

搜不到想要的，换英文术语再搜一次 —— 页面里所有技术名词都保留英文原词（RAG、RRF、Rerank、checkpointer、interrupt），用这些词命中率最高。

三条主线的关系：

  • 项目拆解回答「我做过什么」，是简历的弹药库
  • 知识体系回答「我懂什么原理」，是面试的底层
  • 架构图库回答「能不能画给我看」，是表达工具

同一个主题通常三处都有：项目页讲我的实现，知识页讲通用原理，图库给视觉骨架。建议的阅读顺序是 图 → 知识页 → 项目页：先用图建立空间感，再看原理，最后落到自己的代码上。

五、学习方法（这个站的用法约定） ​

不要「看完再做」 ​

707 小时的量，看完再做就已经错过窗口了。改成 边看边交付：每学一个知识点，立刻问自己「我能在哪个项目里用上 / 我项目里哪个地方印证了它」，然后写一句话记下来。

每页的「和你自己的项目对上号」是重点 ​

这一节把通用原理拉回到我自己的代码上。跳过它，这一页就只是别人的博客；读了它，这一页才是我的面试素材。

「面试怎么问」要出声念一遍 ​

默读会骗人。念出来才知道自己哪一句是卡壳的。卡壳的地方就是没真懂的地方。

学完一个知识点，去助教那里考一次 ​

让它按面试官视角出题。答不上来的直接进 进度看板 的错题本。

每场面试后必须回填错题本 ​

被问到但答不好的问题，是最真实的缺口清单。投递期最值钱的就是这张表。
